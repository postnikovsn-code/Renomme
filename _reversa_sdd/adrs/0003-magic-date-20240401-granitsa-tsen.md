# ADR 0003 — Magic-date '20240401' как граница смены логики ценообразования

- **Статус:** Принято (исторически) · 🟡 ВЫВЕДЕНО
- **Дата:** граница активации — 2024-04-01
- **Модуль:** Ценообразование / Бронирование

## Контекст

Логика расчёта цены проживания была переработана (переход на новый «Календарь цен» с каскадом База→Долгосрочная→Текущая). Уже существовали проведённые брони, рассчитанные по старой модели; их пересчёт по новой исказил бы исторические суммы.

Свидетельства:
- Константа `ДокументыСервер.ДатаПереходаНаНовыйКалендарьЦен = '20240401'` — хардкод-флаг ветвления (PR-03). 🟢
- Параллельные кодовые базы: `ДокументыСервер` vs `ДокументыСервер_Старый`, `КалендарьЦен` vs `КалендарьЦен_Старый`, `Тариф_НеИспользуется` (двойная реализация цены). 🟢
- `ЗаполнитьТаблицуПроживания_Таблица` переключается на `ДокументыСервер_Старый` для дат до границы. 🟢

## Решение

Ввести жёсткую дату-границу `'20240401'`: брони/расчёты до неё используют старый модуль расчёта, после — новый календарь цен. Старый код сохранить рядом (с суффиксами `_Старый`/`_НеИспользуется`).

## Рассмотренные альтернативы

- **Версионирование цены в данных** (хранить версию алгоритма в самой броне). Отклонено: проще сравнить дату документа с константой, чем добавлять реквизит версии во все брони.
- **Единовременный пересчёт всех исторических броней по новой модели.** Отклонено: исказил бы закрытые финансовые периоды и сверки.
- **Удаление старого кода сразу.** Отклонено: исторические документы должны открываться/пересчитываться по своей логике.

## Последствия

- ➕ Исторические брони сохраняют корректные суммы; новые получают новый календарь цен.
- ➖ Двойная кодовая база ценообразования (`*_Старый`) — высокий техдолг и риск расхождения поведения версий.
- ➖ `MagicDate` `'20240401'` зашита в код, не вынесена в настройку; смена даты требует правки исходников.
- ➖ Любая правка логики цен должна вноситься в ОБЕ ветви или сознательно только в новую.
- ⚠ При миграции граница и обе ветви должны быть учтены: исторические суммы нельзя пересчитывать новой моделью.
