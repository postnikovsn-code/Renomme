## Основной поток — расчёт стоимости проживания

См. `flowcharts/Ценообразование-РасчетПроживания.md`. Порядок (`ЗаполнитьТаблицуПроживания_Таблица:428-513`):

1. **Граница legacy:** если `РезервПо < '20240401'` → делегирование `ДокументыСервер_Старый.ЗаполнитьТаблицуПроживания_Таблица`, возврат (`BR-17`). 🟢
2. **Скидка:** `ПроцентСкидки = ИтогоСкидкаКлиент(Объект, Истина)` (MAX категорийной/накопительной). 🟢
3. **Однодневная бронь** (`РезервС = РезервПо`): отдельная ветка. Если БонШанс — `Цена = ПолучитьБонШансЦена`, `Количество = 1`, БЕЗ скидки. Иначе `Количество = 1` + `ЗаполнитьЦенаСуммыСтрокаПроживание`. 🟢
4. **Многодневная бронь:** цикл `ДТН` от `НачалоДня(РезервС)` пока `ДТН ≤ НачалоДня(РезервПо) − 86400`. На каждый день — строка ТЗ:
   - День заезда: `Вр0→2`, `Вр6→1.5`, иначе `1` (`BR-07`). 🟢
   - День выезда: `Вр18→1.5`, `Вр0→2`, иначе `1`. 🟢
   - Промежуточный: `1`. 🟢
   - Вызов `ЗаполнитьЦенаСуммыСтрокаПроживание(Строка, Объект, Двухместный, ПроцентСкидки)`. 🟢
5. **Возврат ТЗ** в вызывающий код (ТЧ `ЗаявкаНаБронирование.Проживание`). 🟢

## Поток — цена и скидка строки (`ЗаполнитьЦенаСуммыСтрокаПроживание:515-539`)

1. Если `ТарифныйПлан` заполнен → `Цена = ЦенаНаДеньТарифныйПлан`. Если цена ≠ 0: `СуммаБезСкидки = Цена×Количество`, `Сумма = СуммаБезСкидки` (СКИДКА НЕ ПРИМЕНЯЕТСЯ), возврат. 🟢
2. Иначе (тариф пуст или цена = 0) — ценовая политика: `Цена = ЦенаНаДень`, `СуммаБезСкидки = Цена×Количество`, `Сумма = Окр(СуммаБезСкидки × (1 − Скидка/100), 2)` (скидка применяется). 🟢

## Поток — каскад цены дня

См. `flowcharts/Ценообразование-ЦенаДняКалендарь.md`. Три уровня (`ПолучитьТекущаяЦенаДня:161-224`):

1. **Уровень 1 — Базовая** (`ПолучитьБазоваяЦенаДня:57-99`): `ПолучитьТЗБазовыеЦены` (ПЕРВЫЕ 1, `ДатаУстановкиЦены ≤ ДатаЦены`, УБЫВ). Состав цены — `BR-02`. При отсутствии — все цены = 0. 🟢
2. **Уровень 2 — Долгосрочная** (`ПолучитьДолгосрочнаяЦенаДня:101-159`): чтение `КалендарьЦенБазовый`/`КалендарьЦенКатегории` с `ВидЦены=Долгосрочная`; перезапись по `ТипЦены`; при отсутствии — наследует базовую. 🟢
3. **Уровень 3 — Текущая**: чтение тех же регистров с `ВидЦены=Текущая`; перезапись; при отсутствии — текущая = долгосрочная. 🟢

> **Перф-риск (🔴):** уровни 2 и 3 выполняют отдельные запросы (база + категория) на каждый день → 5 запросов/день. В цикле расчёта проживания это `CreateQueryInCycle`. Реконструкция ДОЛЖНА предзагружать срез календаря на весь период брони одним запросом (см. `tasks.md` T-15).

## Поток — цена по тарифному плану

См. `flowcharts/Ценообразование-ЦенаТарифныйПлан.md`. `ЦенаНаДеньТарифныйПлан:553-628`:

1. Guard: `ТарифныйПлан` не заполнен или `Двухместный = Неопределено` → возврат 0. 🟢
2. `ВыходнойДень = ДеньНедели(ДТН) > 4`. 🟢
3. Выгрузить `ТарифныйПланСтроки`, сортировка `(ДатаТарифаС, ДатаТарифаПо)`; первая строка с `ДатаС ≤ ДТН ≤ ДатаПо` и категорией совпадающей/пустой (`BR-05`). 🟢
4. Выбор ячейки из 8 (будни/вых × 1/2 × завтрак); fallback «без завтрака»=0 → «с завтраком» (`BR-04`). 🟢
5. Нет строки → возврат 0 (переключение на политику). 🟢

## Поток — запись изменения цен

См. `flowcharts/Ценообразование-ИзменениеЦен.md`. `ИзменитьВыбранныеНаСервере:1565-1661`:

1. `Автор = ПараметрыСеанса.ТекущийПользователь`. 🟢
2. Цикл по `ДатаЦены` из `СписВыбранных`:
   - `КалендарьЦенБазовый` (ВидЦены=Текущая): создать набор, отбор `(ДатаЦены, ВидЦены)`, прочитать, `Очистить()`; добавить строки только для изменённых типов (БазоваяЦена / ДоплДвух / ДоплЗавтрак); записать. 🟢
   - `КалендарьЦенКатегории` (ВидЦены=Текущая): аналогично по строкам категорий; для изменённых — `ЗаписатьКалендарьЦенКатегорииИстория` + строка. 🟢
   - `ЗаписатьКалендарьЦенБазовыйИстория` ×3 (только если значение изменилось). 🟢
3. Очистить `СписВыбранных`, `ОбновитьГод(Объект.Год)` (перерисовка матрицы). 🟢

> **Риск (🔴):** весь цикл идёт БЕЗ `НачатьТранзакцию/Попытка` — при сбое часть дат останется записанной. Реконструкция должна обернуть цикл в транзакцию (`tasks.md` T-13).

## Зависимости

- **Бронирование** — потребитель: `ЗаполнитьТаблицуПроживания_Таблица` заполняет ТЧ `ЗаявкаНаБронирование.Проживание`; `РассчитатьСуммуЗаПроживание:883-885`/`РасчитатьДолг:890-937` агрегируют итог.
- **Размещение и номерной фонд** — `Catalog.КатегорииНомеров` (разрез всех цен; legacy-реквизиты `БазовыйТарифБудни/Выходные/БудниДвух`).
- **Гости и регистрация** — `Catalog.Клиенты` (`Категория.Скидка`, ТЧ `ПроцентыКомиссии`/`ПроцентыВ2В`, `ТипОплатыСчета`, `Турагентство`), `Catalog.КатегорииКлиентов.Скидка`.
- **Финансы и касса** — приёмник рассчитанных сумм (счета, долги, взаиморасчёты); `ПроцентыЭквайринга`.
- **Интеграции и обмен** — TravelLine как источник цен конкурентов/загрузки (`ЦеныКонкурентов_С_ТревелЛайн`, fallback средней цены конкурентов). Протокол загрузки — в модуле «Интеграции»; здесь — лишь потребление результата.

## Внутреннее состояние

Модуль не хранит сессионного состояния. «Состояние» — это данные регистров календаря цен (точечные отклонения по датам в разрезе `ВидЦены`) и справочников `БазовыеЦены`/`ТарифныеПланы`. Форма `КалендарьЦен` держит транзиентную матрицу года (`Объект.Год`) и список выбранных ячеек `СписВыбранных`, материализуемый в регистры только командами «Изменить выбранные»/«Изменить долгосрочные».

## Наблюдаемость

- Аудит изменений цен: регистры `КалендарьЦенБазовыйИстория`/`КалендарьЦенКатегорииИстория` с `Автор` + `ДатаВремяИзменения` (запись при каждом фактическом изменении). 🟢
- Каждая запись цены несёт реквизиты `Автор`/`ДатаИзменения`. 🟢
- Отдельного логирования (ЖР) расчёта цены/проживания в коде не обнаружено. 🟡

## Риски и пробелы

- 🔴 `CreateQueryInCycle`: 5 запросов на каждый день в `ПолучитьТекущаяЦенаДня`, вызывается в цикле по дням → N×5 запросов на расчёт проживания (перф-риск; см. `questions.md` Q-01).
- 🔴 Запись изменения цен без транзакции — несогласованность при сбое (Q-02).
- 🔴 Двойная кодовая база `*_Старый`/`_НеИспользуется` с magic-date — не разобрана построчно (ADR-0003; Q-04).
