> Сквозной поток: ночной аудит, ежедневный отчёт-факт, сводные отчёты, обмен данными по сети отелей.

## US-AU-01 — Ночной аудит (ЕжедневныйАудит)

**Как** Администратор стойки (ночной аудитор), **я хочу** провести ночной аудит проданных номеров за день, **чтобы** зафиксировать факт продаж, незаезды и аннуляции.

Источник: `Documents/ЕжедневныйАудит/ObjectModule.bsl`, `Forms/ФормаДокумента/Module.bsl`. 🟢

### Критерии приёмки
```gherkin
Дано наступила дата аудита
Когда аудитор открывает ЕжедневныйАудит
Тогда заполняются ТЧ ПроданныеНомера, Незаезды, Аннуляции (ЗаполнитьТаб)
  И при проведении формируются движения регистров (registerRecords)

Дано фактическая сумма проживания отличается от плановой
Когда выполняется аудит
Тогда рассчитывается отклонение (СуммаЗаПроживаниеОтклонение / ПроживаниеОтклонение)
```
🟢 `ЕжедневныйАудит/Forms/ФормаДокумента/Module.bsl:422-799,807-1006`.

## US-AU-02 — Ежедневный отчёт-факт

**Как** Менеджер/Руководитель, **я хочу** видеть ежедневный отчёт-факт с метриками (загрузка, ADR, эквайринг, В2В), **чтобы** контролировать показатели отеля.

Источник: `DataProcessors/ЕжедневныйОтчетФакт`, `CommonModules/ЕжедневныйОтчетФакт`, РС `ЕжедневныйОтчетФакт`. 🟢

### Критерии приёмки
```gherkin
Дано выбран период
Когда формируется ежедневный отчёт-факт
Тогда собирается ТЗ_ОтчетДанные, заполняется РС ЕжедневныйОтчетФакт
  И выводятся метрики (общее число номеров, загрузка, проценты эквайринга)
```
🟢 `ЕжедневныйОтчетФакт/Module.bsl:2-407`. 🔴 формулы СуммаАгентскогоВознаграждения/СуммаВ2В/ADR_НА построчно не разобраны.

## US-AU-03 — Сводный отчёт по сети отелей

**Как** Руководитель, **я хочу** получить сводный отчёт-факт по нескольким отелям сети, **чтобы** сравнивать их показатели.

Источник: `CommonModules/ЕжедневныйОтчетФакт.СформироватьСводный`, `DataProcessors/ЕжедневныйОтчетФактСводный`, `HTTP_Модуль` (подтягивание данных соседних баз). 🟢

### Критерии приёмки
```gherkin
Дано настроены HTTP-серверы соседних отелей (константы Сервер*HTTP)
Когда формируется сводный отчёт
Тогда данные подтягиваются по HTTP (hs/products/get_Report_1) от каждого отеля
  И сводятся в единую витрину
```
🟢 `ЕжедневныйОтчетФакт/Module.bsl:436-762,817-840`. См. `openapi/peer-installations-http.yaml`.
🟡 хардкод имён отелей сети и HTTP-параметров в модуле.

## US-AU-04 — Календарь активностей города

**Как** Менеджер/Руководитель, **я хочу** видеть календарь городских мероприятий, **чтобы** учитывать фактор спроса в планировании.

Источник: `DataProcessors/АктивностиКалендарь`, РС `АктивностиКалендарь`, `Catalog.Мероприятия`. 🟢/🟡

### Критерии приёмки
```gherkin
Дано заданы мероприятия города
Когда формируется календарь активностей
Тогда они отображаются по датам (ЗаполнитьАктивностиКалендарь)
```
🟢 `АктивностиКалендарь/Forms/Форма/Module.bsl:1-40`.

## US-AU-05 — Подсистема отчётов

**Как** Менеджер/Руководитель, **я хочу** запускать аналитические отчёты (финансы, статистика бронирования/оплат, неоплаты, источники бронирования, минибар, горничные), **чтобы** анализировать работу отеля.

Источник: подсистема `Reports/` (39 объектов: 14 DCS + ~25 на запросах). 🟢 (6 разобраны вглубь) / 🟡 (33 по имени) / 🔴 (СКД построчно).

### Критерии приёмки
```gherkin
Дано выбран отчёт и период
Когда отчёт формируется
Тогда выводятся данные согласно его схеме (DCS или запрос на форме)
```
🟢 разобраны: ФинансовыйОтчет, ОтчетПоПоказателям, СтатистикаБронирования, СтатистикаОплаты, НеОплаты, ОтчетПоИсточникамБронирования.
🔴 14 DCS-отчётов построчно не разобраны (кандидат на доп. анализ — см. code-spec-matrix).

## US-AU-06 — Расчёт зарплаты администраторов

**Как** Менеджер/Руководитель, **я хочу** рассчитать зарплату администраторов стойки по сменам с надбавками, **чтобы** начислить оплату.

Источник: `Documents/АдминистраторыЗарплата` (модуль «Персонал»). 🟢

### Критерии приёмки
```gherkin
Дано расчётный месяц и администраторы
Когда выполняется расчёт зарплаты
Тогда по дням месяца (динамические реквизиты *_DDMMYY) считаются оклад/надбавки/переработка
  И добавляются доплаты за проживающих/завтраки/стаж по шкалам РС
  И результат разворачивается в ТЧ Зарплата при записи
```
🟢 `АдминистраторыЗарплата/Forms/ФормаДокумента/Module.bsl`. 🟡 денормализация *_DDMMYY (ADR-0011).
