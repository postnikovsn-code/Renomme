# Аудит и отчётность — Крайние случаи

> `edge-cases.md` для unit «Аудит и отчётность» (`doc_level=detalhado`). Метки: 🟢 подтверждено кодом, 🟡 выведено, 🔴 пробел.

## EC-01 — Аудит при пустой занятости за день 🟢

**Сценарий.** За `ДатаОтбора` нет ни одной брони со статусом `Проживает`/`Выехал` (закрытый отель, переучёт, выходной день).

**Поведение легаси.** `ЗаполнитьТаб()` очищает ТЧ (`:424-426`), запрос проживающих возвращает пустой результат, цикл по строкам не выполняется → ТЧ `ПроданныеНомера/Незаезды/Аннуляции` остаются пустыми. Документ корректно проводится; при `Проверка=Истина` цикл `Для Каждого … Из ПроданныеНомера` не делает итераций → 0 движений РС. 🟢 (`ObjectModule.bsl:6-22`)

**Ожидание реализации.** Пустой день не ошибка: документ сохраняется/проводится, движений нет. Тест: TT-01 с нулевой занятостью → 0 строк, 0 движений.

## EC-02 — Деление на ноль в загрузке / ADR 🟢

**Сценарий.** `КоличествоНомеров = 0` (все номера помечены на удаление / справочник пуст) или `ИтогоЗанятыеНомера = 0` / `КолОдном = 0` / `КолДвухм = 0` (нет продаж типа).

**Поведение легаси.** Все деления в расчёте метрик обёрнуты `Если знаменатель = 0 Тогда 0` → загрузка, ADR (одно-/двухм.), средняя стоимость = 0; макет строится без аварии. 🟢 (`flowcharts/Аудит-ЕжедневныйОтчетФакт.md` «Защита»; `Forms/Форма/Module.bsl:203-239`)

**Ожидание реализации.** Воспроизвести защиту на КАЖДОМ делении (загрузка, оба ADR, средняя стоимость, проценты структуры). Тест: TT-05 — период без продаж → все метрики 0, исключения нет.

## EC-03 — Сводный отчёт: отель сети недоступен по HTTP 🟢

**Сценарий.** При формировании свода по 5 отелям один сервер недоступен (сеть/таймаут) или ответил, но не подготовил данные (`Результат.Данные = Неопределено`).

**Поведение легаси.** `ЗагрузитьHTTP_ЕжедневныйОтчетФакт` возвращает `Ошибка=Истина` с текстом, включающим имя сервера: «Ошибка соединения с HTTP сервисом <ИмяСервера>. ОБРАТИТЕСЬ К АДМИНИСТРАТОРУ ПРОГРАММЫ.» либо «Ошибка подготовки данных в HTTP сервисе <ИмяСервера>…». 🟢 (`CommonModules/ЕжедневныйОтчетФакт/Module.bsl:821-834`)

**Ожидание реализации.** Ошибка одного отеля не должна аварийно прерывать свод по остальным; текст ошибки доводится до оператора с именем сервера. 🟡 (точная стратегия — пропустить отель и продолжить vs. прервать свод — построчно не подтверждена; требует валидации, см. `questions.md` Q-04). Тест: TT-06.

## EC-04 — Расчётный час: полусутки и граничные часы 🟢/🟡

**Сценарий.** Фактическое время заезда/выезда попадает на границы политики расчётного дня: ранний заезд `Час < 6`; поздний выезд в диапазонах 14–18 / 18–23 / ровно 23; тарифы `Вр6`/`Вр14`/`Вр12`/`Вр18` и количество суток 0.5/1/1.5/2.

**Поведение легаси.** `ПроживаниеОтклонение` ветвится по магическим часам 6/13/14/17/18/23 и долям 0.5/1/1.5, начисляя доплату `ЦенаНаДень` или `ЦенаНаДень*0.5` и отклонение по часам `6−ЧасЗаезд` / `14−ЧасЗаезд` / `ЧасВыезд−13` / `ЧасВыезд−17`. 🟢 (значения), захардкоженность политики 🟡 (`Forms/ФормаДокумента/Module.bsl:873-1006`)

**Ожидание реализации.** Покрыть тестами каждую ветвь границ (ровно 6, ровно 14, ровно 18, ровно 23). Магические часы вынести в конфигурируемую политику расчётного дня (см. `questions.md` Q-04). Тест: TT-03 + дополнительные граничные кейсы.

## EC-05 — Строка с нулевым отклонением и без строки проживания 🟢

**Сценарий.** Для брони `СтрокаПроживание = Неопределено` И все отклонения = 0 (бронь дня без значимых расхождений).

**Поведение легаси.** Такая строка пропускается и не добавляется в ТЧ `ПроданныеНомера` (`Skip{СтрокаПроживание=Неопр. И отклонения=0}` в `flowcharts/Аудит-ЕжедневныйАудит.md`). 🟢

**Ожидание реализации.** Не засорять витрину дня «пустыми» строками; в «Отклонения» строка попадает только по AU-03.

## EC-06 — Факт-отчёт перезаписывает витрину, читаемую параллельно 🟡

**Сценарий.** Факт-отчёт формируется одновременно с другим отчётом, читающим РС `ЕжедневныйОтчетФакт` за тот же период (AU-05: отчёт сначала ПИШЕТ витрину, затем читает).

**Поведение легаси.** Витрина пересчитывается и перезаписывается при каждом формировании; конкурентное чтение может увидеть промежуточное состояние. 🔴 Транзакционность/блокировки записи витрины в разобранном коде не подтверждены.

**Ожидание реализации.** Уточнить требования к конкурентному доступу к витрине (см. `questions.md` Q-05). При переподнятии — оборачивать запись витрины в управляемую транзакцию.
