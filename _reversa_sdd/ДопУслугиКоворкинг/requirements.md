## Визия Обзор

Модуль покрывает два связанных контура конфигурации «ОТЕЛЬ». **(1) Доп. услуги гостю** — прайс-справочник `Catalog.ДопУслуги` (транспорт, проживание-услуги, завтраки, минибар, прачечная, штраф, коворкинг — по `Enum.ПрограммныйКодУслуги`); долг за допуслуги копится в ТЧ `ЗаявкаНаБронирование.ДопУслуги` (контур долгов брони) и массово закрывается документом-реестром `СписаниеДопУслуг`. **(2) Коворкинг** — аренда рабочих мест: заявка (`КоворкингЗаявка`), цепочка счетов (`КоворкингСчета`) с собственным мини-контуром взаиморасчётов, проверка/резервирование занятости в `InformationRegister.ЗанятостьНомеровКоворкинг`, рабочее место оператора (`КоворкингЗаявкаОбработка`) и визуальная шахматка (`КоворкингШахматка`). 🟢

## Ответственности

- Вести прайс платных услуг гостю (`Catalog.ДопУслуги`), зеркаля в него номенклатуру минибара. 🟢
- Вести справочники коворкинга: рабочие места (`КоворкингНомера`) и прайс услуг счёта (`КоворкингУслуги`). 🟢
- Принимать заявки на аренду коворкинга и резервировать занятость рабочего места по часам/дням. 🟢
- Формировать из заявки непрерывную цепочку счетов (`КоворкингСчета`) по периоду аренды. 🟢
- Проверять занятость рабочего места двухпроходно (приоритет конфликта со счётом над конфликтом с заявкой). 🟢
- Распределять оплаты (касса/выписка банка) по телу счёта и строкам допуслуг коворкинга; обрабатывать частичный возврат и пересчёт. 🟢
- Массово закрывать долг за допуслуги (`СписаниеДопУслуг`) с предохранителем `СуммаДолг = СуммаСчетДолг`. 🟢
- Визуализировать занятость коворкинга (шахматка дни/часы) и предоставлять рабочее место оператора. 🟢
- Печатать счета/акты/счёт-фактуры коворкинга и акт списания допуслуг с выбором макета по организации. 🟢

## Бизнес-правила

- **DK-01** Резерв коворкинга раскрывается в дискретные записи РС: по одной записи `ЗанятостьНомеровКоворкинг` на каждый час (почасовая) или день (посуточная) периода; агрегации нет. 🟢
- **DK-02** Двухпроходная проверка занятости: 1-й проход ищет конфликт со *счетами* других заявок (пропуская записи-заявки), 2-й — среди заявок. Конфликт со счётом приоритетнее конфликта с заявкой. Заявка исключает счета своей заявки; счёт исключает сам себя и родительскую заявку. 🟢
- **DK-03** Счета заявки идут непрерывной цепочкой без разрывов: `ДатаС` нового счёта = `МАКСИМУМ(ДатаПо непомеченных счетов заявки) + 1 день`; если счетов нет — `Заявка.ДатаС`. Для посуточного — стоп, если `СледующийСчетДатаС > Заявка.ДатаПо`. 🟢
- **DK-04** `СчетДатаПо` по периоду аренды: `МЕСЯЦ` (1-е число → конец месяца; иначе → та же дата след. месяца −1 день, с переносом года), `НЕДЕЛЯ` (`ДатаС + 6 дней`), `ДЕНЬ`/`ЧАС` (`НачалоДня(ДатаС)`), иначе `Неопределено`. Для `МЕСЯЦ`/`НЕДЕЛЯ`/`ДЕНЬ` `Количество` жёстко = 1; пропорциональный расчёт (длина месяца/недели, выходные) **закомментирован**. 🟢
- **DK-05** Оплата счёта коворкинга распределяется СНАЧАЛА на тело счёта (`ЭтоУслуга=Ложь`), затем по строкам допуслуг (`ЭтоУслуга=Истина`, `ГУИДДолги=ГУИД` строки) до исчерпания остатка. Сумма к оплате = долг тела (`Сумма−СуммаОплачено`) + долг строк допуслуг. 🟢
- **DK-06** Списание долга за допуслуги создаётся ТОЛЬКО если `СуммаДолг = СуммаСчетДолг` (долг по `ЗаявкаНаБронирование.ДопУслуги` совпадает с долгом в `СчетаДетальноДолги`); иначе строка попадает в ТЧ `Ошибки`, документ оплаты-списания не создаётся. 🟢
- **MB-05** Номенклатура минибара зеркалируется в `Catalog.ДопУслуги` (группа с программным кодом МИНИБАР) — минибар продаётся гостю как доп. услуга. Точка истины — модуль «Минибар». 🟢
- Частичный возврат (`УменьшитьОплатыКоворкингСчетаСуммаВозврата`): уменьшает строки распределения по очереди (последнюю частично) или удаляет целиком + синхронизирует финансовый низ. 🟢
- `СуммаОплачено` шапки счёта — производная: пересчитывается в `КоворкингСчета.ПередЗаписью` как `Итог("СуммаОплаты")` по ТЧ `РаспределениеОплатКоворкинг` (единственный источник истины суммы оплат). 🟢
- Запрет пометки удаления заявки при наличии счетов даёт `КоворкингКлиент.ПроверкаУдаленияЗаявки` (на форме); обработчик `КоворкингЗаявка.ПередЗаписью_Вариант` назван `_Вариант` и, судя по имени, не подключён. 🟡
- Списание долга допуслуг также фигурирует в закрытии финансового периода (FN-08, модуль «Финансы»). 🟢
- 🔴 `СписаниеДопУслуг` — документ БЕЗ `ObjectModule` и без движений регистров; вся бизнес-логика и транзакции вынесены на форму (нетипичная архитектура — требует валидации, что это намеренное решение).

## Критерии приёмки

```gherkin
# RF-05 / DK-01 — резервирование при проведении заявки (happy)
Дано свободное рабочее место и заявка на посуточную аренду с 01.06 по 03.06
Когда оператор проводит КоворкингЗаявку
Тогда в ЗанятостьНомеровКоворкинг создаётся по одной записи на каждый день (01.06, 02.06, 03.06)
И каждая запись имеет Зарезервирован=Истина, ДокументРегистратор=ссылка на заявку, Клиент заявки

# RF-06 / DK-02 — конфликт занятости (failure)
Дано рабочее место, занятое СЧЁТОМ другой заявки в периоде 02.06
Когда оператор проводит новую заявку, пересекающуюся по 02.06
Тогда проверка занятости возвращает Результат=Истина с Регистратором-счётом
И проведение отклоняется (Отказ=Истина) с сообщением «номер занят»

# RF-07 / DK-03 / DK-04 — цепочка счетов (happy)
Дано заявка МЕСЯЦ с ДатаС=15.06 без существующих счетов
Когда оператор формирует счёт
Тогда ДатаС счёта = 15.06, ДатаПо = 14.07 (та же дата след. месяца −1 день), Количество=1
И при формировании следующего счёта его ДатаС = ДатаПо предыдущего + 1 день

# RF-07 / DK-03 — стоп цепочки посуточного счёта (failure)
Дано заявка ДЕНЬ с ДатаПо=20.06 и существующим счётом до 20.06
Когда оператор формирует следующий счёт
Тогда СледующийСчетДатаС (21.06) > Заявка.ДатаПо (20.06)
И система показывает предупреждение и не создаёт счёт

# RF-09 / DK-05 — распределение оплаты (happy)
Дано счёт коворкинга с долгом тела 1000 и долгом строк допуслуг 300, оплата 1200
Когда выполняется распределение оплаты
Тогда сначала закрывается тело (1000, ЭтоУслуга=Ложь)
И остаток 200 распределяется по строкам допуслуг (ЭтоУслуга=Истина, ГУИДДолги=ГУИД строки)
И финансовый низ синхронизируется через ОплатыОбщееСервер

# RF-11 / DK-06 — списание долга допуслуг (happy)
Дано долг гостя за допуслуги по ЗаявкаНаБронирование.ДопУслуги, где СуммаДолг = СуммаСчетДолг
Когда оператор выполняет СоздатьДокументыСписания по отмеченной строке
Тогда создаётся ПрочиеОплаты с ВидОперации=СписаниеДопУслуг
И сумма распределяется по СчетаДетальноДолги (Услуга=Истина)

# RF-11 / DK-06 — предохранитель списания (failure)
Дано долг за допуслуги, где СуммаДолг ≠ СуммаСчетДолг
Когда оператор выполняет СоздатьДокументыСписания
Тогда строка попадает в ТЧ Ошибки с текстом «долг доп.услуг <> долг в счетах»
И документ оплаты-списания не создаётся
```
