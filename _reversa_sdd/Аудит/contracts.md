# Аудит и отчётность — Внешние контракты

> `contracts.md` для unit «Аудит и отчётность». Описывает внешний контракт сводного отчёта по сети отелей: HTTP-сбор ежедневного факт-отчёта с удалённых баз 1С. Метки: 🟢 подтверждено кодом, 🟡 выведено, 🔴 пробел. Источник: `CommonModules/HTTP_Модуль/Module.bsl`, `CommonModules/ЕжедневныйОтчетФакт/Module.bsl`, ADR-0008/0009.

## Контракт C-01 — HTTP: ежедневный факт-отчёт отеля сети (GET) 🟢

Каждый отель сети («Реноме» — локальная база; «Лайв», «Чехов», «ДомСоветов», «СтритАрт» — удалённые) публикует HTTP-сервис 1С, отдающий данные витрины `ЕжедневныйОтчетФакт` за период. Сводный отчёт-потребитель собирает их и объединяет (`СформироватьЕжедневныйОтчетСводный`).

### Роли
- **Потребитель (клиент):** локальная база «ОТЕЛЬ» → `ЕжедневныйОтчетФакт.ЗагрузитьHTTP_ЕжедневныйОтчетФакт(ДатаС, ДатаПо, ИмяСервера)` → `HTTP_Модуль.ПолучитьЕжедневныйОтчетФакт(ДатаС, ДатаПо, ИмяСервера)`. 🟢
- **Поставщик (сервер):** HTTP-сервис на стороне каждого удалённого отеля, публикующий ресурс `get_Report_1`. 🔴 Серверная реализация в этом проекте отсутствует — описание поставщика выведено из формы запроса.

### Транспорт и эндпоинт 🟢
- Метод: **GET** (`Соединение.Получить(...)`, `HTTP_Модуль/Module.bsl:120`).
- Базовый адрес сервера: значение константы по имени `ИмяСервера` (`ОбщийФункционалСервер.ПолучитьЗначениеКонстанты(ИмяСервера)`, `:156`). Таймаут соединения **120 сек** (`:114`). 🟢
- Путь (`ТекстДляЗапроса`, `:169-188`) собирается по имени сервера:

| `ИмяСервера` (константа) | Префикс пути | Полный путь |
|--------------------------|--------------|-------------|
| `СерверЛайвHTTP` | `/LIVE_HTTP/` | `/LIVE_HTTP/hs/products/get_Report_1/date_from/{dd.MM.yyyy}/date_to/{dd.MM.yyyy}` |
| `СерверЧеховHTTP` | `/Chehov_HTTP/` | `/Chehov_HTTP/hs/products/get_Report_1/date_from/{ДатаС}/date_to/{ДатаПо}` |
| `СерверДомСоветовHTTP` | `/DomSovetov_HTTP/` | `/DomSovetov_HTTP/hs/products/get_Report_1/date_from/{ДатаС}/date_to/{ДатаПо}` |
| `СерверСтритАртHTTP` | `/StreetArt_HTTP/` | `/StreetArt_HTTP/hs/products/get_Report_1/date_from/{ДатаС}/date_to/{ДатаПо}` |

🟡 Имена серверов и префиксы путей захардкожены в `ПолучитьНастройкиЕжедневныйОтчетФакт` (ветвление `Если ИмяСервера = …`), сами адреса вынесены в константы (ADR-0008/0009).

### Параметры запроса 🟢
| Параметр | Где | Формат | Источник |
|----------|-----|--------|----------|
| `date_from` | сегмент пути | `dd.MM.yyyy` (`Формат(ДатаС, "ДФ=dd.MM.yyyy")`) | `:183-184` |
| `date_to` | сегмент пути | `dd.MM.yyyy` | `:185-186` |

### Ответ 🟢
- Тело — **JSON**, сохраняется во временный файл `КаталогБД() + "HTTPЕжедневныйОтчетФакт" + ИмяСервера + ".txt"` (`:116`), затем читается `ПрочитатьJSON(Чтение, Ложь, ["Дата"], ФорматДатыJSON.ISO)` (`:136-145`). 🟢
- Поле `Дата` парсится как дата ISO; остальные поля соответствуют ресурсам витрины РС `ЕжедневныйОтчетФакт` (количества/суммы размещений, ADR_НА, %_НА, B2B, комиссия, агентское). 🟡 (точная схема JSON-полей не извлечена — определяется серверной реализацией поставщика, 🔴).
- Успех: `HTTPОтвет.КодСостояния < 300`; данные → `Результат.Данные` (структура/массив из JSON). 🟢

### Ошибки 🟢
| Условие | `Ошибка` | `ТекстОшибки` | Строка |
|---------|----------|---------------|--------|
| Константа сервера не заполнена | Истина | `"Ошибочная настройка константы " + ИмяСервера` | `:100-104` |
| Пустой текст запроса | Истина | `"Ошибочные настройки HTTP"` | `:107-112` |
| Исключение соединения/получения | Истина | `"Ошибка соединения с HTTP: " + ОписаниеОшибки()` | `:119-126` |
| Код состояния ≥ 300 | Истина | `"Ошибка HTTP Соединение.Получить. Код состояния: " + Код` | `:128-133` |
| Обёртка верхнего уровня (вызов из CM `ЕжедневныйОтчетФакт`) | Истина | `"Ошибка соединения с HTTP сервисом <ИмяСервера>. ОБРАТИТЕСЬ К АДМИНИСТРАТОРУ ПРОГРАММЫ."` / `"Ошибка подготовки данных в HTTP сервисе <ИмяСервера>…"` | `ЕжедневныйОтчетФакт/Module.bsl:821-834` |

### Контракт-кейсы (Gherkin)
```gherkin
# Успешный сбор отеля сети
Дано константа СерверЛайвHTTP заполнена адресом доступного сервиса
Когда вызывается ПолучитьЕжедневныйОтчетФакт(ДатаС, ДатаПо, "СерверЛайвHTTP")
Тогда выполняется GET /LIVE_HTTP/hs/products/get_Report_1/date_from/.../date_to/...
И при КодСостояния < 300 Результат.Ошибка = Ложь и Результат.Данные содержит строки витрины

# Недоступный сервис
Дано сервис отеля недоступен (исключение соединения или код >= 300)
Когда вызывается ПолучитьЕжедневныйОтчетФакт(...)
Тогда Результат.Ошибка = Истина и ТекстОшибки содержит имя сервера/код состояния
И сводный отчёт доводит ошибку до оператора, не падая аварийно

# Незаполненная константа
Дано константа ИмяСервера пуста
Когда вызывается ПолучитьЕжедневныйОтчетФакт(...)
Тогда Результат.Ошибка = Истина и ТекстОшибки = "Ошибочная настройка константы <ИмяСервера>"
```

## Пробелы контракта (🔴/🟡)
- 🔴 Серверная сторона (`get_Report_1`) в этом проекте не реализована/не найдена — схема JSON-полей ответа определяется внешними базами отелей; для паритета нужно зафиксировать её отдельно.
- 🔴 Аутентификация/авторизация HTTP-вызова не обнаружена в разобранном коде (логин/пароль `HTTPСоединение` не передаются) — уточнить, как защищён сервис (см. `questions.md` Q-04).
- 🟡 Локальный отель «Реноме» данные читает не по HTTP, а напрямую (`МассивРеноме` → `РегистрЕжедневныйОтчетФактВыгрузить`); HTTP-контракт применяется только к 4 удалённым отелям.
- 🟡 Стратегия при сбое одного отеля (пропустить и продолжить свод vs. прервать) построчно не подтверждена (EC-03).
