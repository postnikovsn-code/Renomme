## Основной поток

### A. Проведение заявки/счёта коворкинга (DK-01, DK-02)
1. `ОбработкаПроведения` → `ПроверкаЗаполнения` через `КоворкингСервер.ПроверкаЗаполнения...ТекстСообщения`; при ошибке `Сообщить` + `Отказ=Истина`, выход. (`КоворкингЗаявка/ObjectModule.bsl:3-45`, `КоворкингСчета/ObjectModule.bsl:3-44`) 🟢
2. `КоворкингСервер.ПроверкаЗанятостиКоворкинг(ЭтотОбъект)` → `ЗанятостьНомераКоворкингПроверить` (двухпроходно, `:111-178`); при конфликте `Отказ=Истина`. 🟢
3. Определение шага: почасовая → `ТемпС=НачалоЧаса(ДатаС)+ЧасС*3600`, `ТемпПо=НачалоЧаса(ДатаПо)+ЧасПо*3600−1`, шаг 3600; посуточная → `НачалоДня(ДатаС)…НачалоДня(ДатаПо)`, шаг 86400. 🟢
4. Цикл `Пока ТемпС<=ТемпПо`: движение `ЗанятостьНомеровКоворкинг` (`КоворкингНомер`, `ПериодРезерва=ТемпС`, `Клиент`, `ДокументРегистратор=Ссылка`, `Зарезервирован=Истина`); `ТемпС += шаг`. 🟢
5. (Только счёт) `ПередЗаписью`: пересчёт `СуммаОплачено` шапки/строк по ТЧ `РаспределениеОплатКоворкинг`, простановка `СчетГУИД`/`ГУИД` строк допуслуг. 🟢

### B. Формирование счёта из заявки (DK-03, DK-04)
1. Команда формы `КоворкингЗаявкаОбработка/Forms/Форма/Module.bsl:321-365` → `ДобавитьСчетНаСервере`. 🟢
2. Для посуточного: предварительно `СледующийСчетДатаС > Заявка.ДатаПо?` → предупреждение + выход (DK-03). 🟢
3. Ветвление по почасовости → `ДобавитьСчетЧасы` / `ДобавитьСчетДни` (`КоворкингСервер:349-505`). 🟢
4. `ДатаС = СледующийСчетДатаС` (цепочка без разрывов); `ДатаПо = СчетДатаПо(ДатаС, ПериодАренды)` (DK-04; `Неопределено` → выход). 🟢
5. Для МЕСЯЦ/НЕДЕЛЯ/ДЕНЬ `Количество=1`, `КоличествоЕдиниц`=дни, `Сумма=Цена*Количество`; почасовой — `КоличествоЕдиниц=ЧасПо−ЧасС`, `Количество=КоличествоЕдиниц`. 🟢
6. `Счёт.Записать(Проведение)` → возврат ссылки. 🟢

### C. Распределение оплаты по счёту (DK-05)
1. `ДобавитьДокументОплатаКоворкингСчет`: `НачатьТранзакцию`; `ДокументДолгОбъект = Счет.ПолучитьОбъект`. 🟢
2. `РаспределитьДокументОплатаКоворкингСчетОбъект` (по ссылке `СуммаРаспределено`). Если оплата не `КассовыйДокумент`/`ВыпискаБанка` — выход. 🟢
3. `СуммаКоплате = СуммаКОплатеКоворкинг` (тело + допуслуги); если 0 — выход. 🟢
4. Запрос суммы возврата (по `ВозвратДокумент`); `ОстатокОплаты = Оплата.Сумма − СуммаВозврата`; `СуммаКРаспределению = МИН(СуммаКоплате, ОстатокОплаты)`. 🟢
5. Закрытие тела (`ЭтоУслуга=Ложь`) на мин(остаток, долг тела); затем цикл по строкам `ДопУслугиКоворкинг` (`Сумма<>СуммаОплачено`): строки `РаспределениеОплатКоворкинг` (`ЭтоУслуга=Истина`, `ГУИДДолги=ГУИД`), `Прервать` при остатке 0. 🟢
6. Новая строка `ДокументыОплаты` (`СуммаРаспределено`); `ДокументДолгОбъект.Записать(Проведение)`. 🟢
7. `ОплатыОбщееСервер.ЗаполнитьДокументОплатыДолгОплатаДляКоворкинг` → финансовый низ; `ЗафиксироватьТранзакцию`. 🟢

### D. Списание долга за допуслуги (DK-06)
1. `ПриСозданииНаСервере` → `ДобавитьУслугиРодитель` (`ManagerModule.ЗаполнитьУслугиРодительСправочник`) формирует динамические колонки «Услуга_N» по группам `ДопУслуги` (`ЗаголовокОтчеты`, `НомерПП`). 🟢
2. `ОтборДокументовСписания` → форма `ОтборДокументыКСписанию` (период `РезервС/По`) → `ManagerModule.ПолучитьДокументыКСписанию` (запрос по `ЗаявкаНаБронирование`: `СуммаДолг` допуслуг = Σ `Цена*Количество` где `ВСчет=Истина`, минус оплаты `РаспределениеОплатДолги`, сверка со `СчетаДетальноДолги` `Услуга=Истина`, минус уже `Списано`). 🟢
3. Заполнение ТЧ `ДокументыКСписанию` + флаг `ДолгРавенСчетДолг = (СуммаДолг=СуммаСчетДолг)`. 🟢
4. `СоздатьДокументыСписания`: `Записать(Проведение)`; цикл по отмеченным строкам:
   - `СуммаДолг=СуммаОплатыДолг?` → `Продолжить` (нечего списывать);
   - `СуммаДолг<>СуммаСчетДолг?` → строка в ТЧ `Ошибки` (DK-06);
   - иначе `ДобавитьОплатаСписание` → `СуммаКСписанию` (по `СчетаДетальноДолги` `Услуга=Истина`, `ГрупповойСчет=Ложь`); если 0 — пропуск;
   - `ДобавитьОплатаСписаниеНаСервере`: `НачатьТранзакцию` → `ОплатыОбщееСервер.СоздатьПрочиеОплатыСписание` (вид операции `СписаниеДопУслуг`) → `ЗаявкаСервер.ДобавитьОплатаСчетаДетальноОплаты` + `РаспределитьСтрокаОплатыСчетаДетальноДолги` → `Бронь.Записать(Проведение)` + `Форма.Записать` → `ЗафиксироватьТранзакцию`. 🟢
5. Удаление списания (`УдалитьДокументСписанияНаСервере`): находит `СчетаДетальноОплаты` с `ДокументОплаты.ВидОперации=СписаниеДопУслуг` и откатывает через `ЗаявкаСервер.УдалитьСтрокаОплатыНаСервере`. 🟢

### E. Шахматка (контракт)
`ПриОткрытии` → режим Дни/Часы → `ВывестиШахматкуДни`/`ВывестиШахматкуЧасы`: строки = `КоворкингНомера` (иерархия, `Номер_пп`), столбцы = дни/часы; запрос `ЗанятостьНомеровКоворкинг` за период; ячейка красится цветом клиента/номера/`СлучайныйЦвет`; вывод в `ПолеОтчета`. Клик `ПолеОтчетаВыбор` → `ОпределитьПоКоординатам(x,y)` → открыть заявку/счёт/номер. 🟢 (контракт) / 🔴 (внутренние циклы отрисовки `:122-1145` построчно не разобраны).

## Альтернативные потоки

- **Конфликт занятости (DK-02):** проведение отклоняется (`Отказ=Истина`), резерв не пишется. 🟢
- **Посуточный счёт за пределами заявки:** `СледующийСчетДатаС > Заявка.ДатаПо` → предупреждение, счёт не создаётся. 🟢
- **Период аренды не МЕСЯЦ/НЕДЕЛЯ/ДЕНЬ/ЧАС:** `СчетДатаПо` возвращает `Неопределено` → `ДобавитьСчетДни` возвращает `Неопределено`, счёт не создаётся. 🟢
- **Расхождение долга (DK-06):** строка → ТЧ `Ошибки`, оплата-списание не создаётся. 🟢
- **Частичный возврат:** `УменьшитьОплатыКоворкингСчетаСуммаВозврата` — если распределённое ≤ возврата → удаление строк + `ОплатыОбщееСервер.УдалитьДокументОплатыДокументДолгДолгОплата`; иначе уменьшение строк (последняя частично) + `ДобавитьЗаменитьДокументОплатыДолгОплата`. 🟢

## Внутреннее состояние

- **Занятость** хранится в `ЗанятостьНомеровКоворкинг`: дискретные слоты (`ПериодРезерва`) на номер, привязанные к регистратору (заявка — черновой резерв, счёт — фактический). Записи живут только при проведённом документе (`RecorderSubordinate` + `AutoDelete`). 🟢
- **Взаиморасчёты счёта** хранятся в 4 ТЧ `КоворкингСчета`: `ДопУслугиКоворкинг` (строки допуслуг, ключ `ГУИД`), `ДокументыОплаты` (входящие оплаты), `РаспределениеОплатКоворкинг` (распределение, ключ `ГУИДДолги`), `СрокиАренды`. `СуммаОплачено` тела/строк — производные. 🟢
- **Жизненный цикл (state-machines §5):** счёт коворкинга `НеОплачен → ЧастичноОплачен → Оплачен` (`СуммаКОплатеКоворкинг=0`); возврат возвращает в `ЧастичноОплачен`. Заявка: `Бронь` (черновой резерв) → `ВРаботе` (сформированы счета). 🟢

## Наблюдаемость

- Пользовательские сообщения `Сообщить` при отказе проведения («номер занят», «ЗАПИСЬ ОТМЕНЯЕТСЯ»). 🟢
- ТЧ `Ошибки` документа `СписаниеДопУслуг` как канал диагностики расхождений долга (DK-06). 🟢

## Риски и пробелы

- 🔴 Транзакции без `Попытка/Исключение` в `ДобавитьДокументОплатаКоворкингСчет`, `УменьшитьОплатыКоворкингСчетаСуммаВозврата`, `ОбновитьОплатыКоворкинг`, `ДобавитьОплатаСписаниеНаСервере`, `УдалитьДокументСписанияНаСервере` — при ошибке `Записать` транзакция повисает (`BeginTransactionBeforeTryCatch`).
- 🔴 Запись РС в цикле без агрегации — десятки записей на месячную посуточную аренду.
- 🔴 `СписаниеДопУслуг` без `ObjectModule`/движений — нетипичная архитектура; нужно подтвердить намеренность.
- 🔴 Массивное дублирование `КоворкингСервер↔КоворкингКлиент`; параллельные реализации отрисовки шахматки + мёртвый код (`ТЕСТ`, `ИмяОбработки_ПеренесеноВОбщийМодуль`, блок «ВключатьВыходные»).

- 🔴 Внутренние циклы отрисовки `КоворкингШахматка` (`:122-1145`) построчно не разобраны.
- 🟡 Несогласованность инверсии возврата `ПроверкаЗаполнения` (заявка — `Истина` при ошибке, счёт — `Ложь`).
- 🟡 ТЧ `ДокументыКСписанию.ДокументДолг` типизирована только `DocumentRef.ЗаявкаНаБронирование` — иные регистраторы долга не охвачены.
