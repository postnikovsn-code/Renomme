# User Stories — Жизненный цикл брони

> Сквозной поток: заявка → подтверждение → заселение → выезд. Глобальный артефакт Reversa.
> Роли: Администратор стойки, Менеджер/Руководитель, Гость (через сайт/мессенджеры).
> Связанные unit: [`Бронирование/`](../Бронирование/), [`Размещение/`](../Размещение/), [`Ценообразование/`](../Ценообразование/), [`Финансы/`](../Финансы/), [`Гости/`](../Гости/), [`Интеграции/`](../Интеграции/).
> Доверие: 🟢 подтверждено · 🟡 выведено · 🔴 пробел.

## US-BR-01 — Приём заявки на бронирование

**Как** Администратор стойки, **я хочу** создать заявку на бронирование с выбором номера, дат и времени заезда/выезда, **чтобы** зарезервировать номер за гостем без двойного бронирования.

Источник: `Documents/ЗаявкаНаБронирование/ObjectModule.bsl`, `CommonModules/ДокументыСервер.ЗанятостьНомераПроверить`. 🟢

### Критерии приёмки
```gherkin
Дано выбран номер, период РезервС..РезервПо и времена заезда/выезда
Когда администратор записывает и проводит заявку
Тогда система проверяет занятость номера по РС ЗанятостьНомеров на пересекающиеся часы
  И при свободном номере создаёт почасовые записи занятости (Номер_пп по часам)
  И статус брони = Бронь

Дано номер уже занят другой бронью на пересекающиеся часы (не БонШанс)
Когда администратор пытается провести заявку
Тогда проведение отклоняется с сообщением о занятости
```
Время заезда Вр0/6/14/18 → 0/6/14/18 ч; выезд Вр0/6/12/18 → 24/6/12/18 ч (`ДокументыСервер:231-262`). 🟢
Брони с флагом БонШанс между собой не конфликтуют. 🟢

## US-BR-02 — Заявка с сайта и из мессенджеров

**Как** Гость, **я хочу** оставить бронь на сайте/в WhatsApp, **чтобы** забронировать номер без звонка на стойку.

Источник: `CommonModules/ОбменСайт`, `Document.ЗаявкаСайт`, `Documents/ЗаявкаСайт/Forms/ФормаДокумента/Module.bsl`. 🟢

### Критерии приёмки
```gherkin
Дано на сайте оформлена бронь
Когда выполняется обмен с сайтом (HTTPS GET, окно 90 дней)
Тогда создаётся Document.ЗаявкаСайт с ФИО/телефоном/датами/категорией

Дано есть необработанная ЗаявкаСайт
Когда администратор конвертирует её в ЗаявкаНаБронирование
Тогда клиент сопоставляется по ФИО/телефону (или создаётся новый)
  И повторная конвертация блокируется проверкой ЕстьЗаявкаНаБронирование
```
🟢 `Документы/ЗаявкаСайт/Forms/ФормаДокумента/Module.bsl:26-64`.

## US-BR-04 — Подтверждение бронирования гостю

**Как** Менеджер, **я хочу** отправить гостю подтверждение/аннуляцию брони, **чтобы** зафиксировать договорённость.

Источник: `Document.ПодтверждениеБронирования` (~35 макетов писем по организациям), `Интеграции` (WhatsApp/Email). 🟡 (логика формы вглубь не разобрана 🔴)

### Критерии приёмки
```gherkin
Дано подтверждённая бронь
Когда формируется ПодтверждениеБронирования и отправляется гостю
Тогда выставляется признак Отправлено
Дано бронь отменена
Когда отправляется аннуляция
Тогда выставляется признак Аннулированно
```
🟡

## US-BR-05 — Расчёт проживания и разделение счёта

**Как** Администратор стойки, **я хочу** рассчитать стоимость проживания и при необходимости разделить счёт между двумя гостями, **чтобы** корректно выставить суммы.

Источник: `CommonModules/ЗаявкаСервер.УстановитьЦенаСуммаДляРазделитьСчет`, `ДокументыСервер.ЗаполнитьТаблицуПроживания_Таблица`. 🟢

### Критерии приёмки
```gherkin
Дано бронь с флагом РазделитьСчет и двумя гостями (Клиент, Клиент2)
Когда рассчитывается сумма проживания
Тогда первый получает Сумма/2 + 0.001, второй — Сумма − Сумма/2 − 0.001 (компенсация копейки)
```
🟢 `ЗаявкаСервер:432-446`. Подробный расчёт сумм — поток `Ценообразование-РасчетПроживания`.

## US-BR-06 — Заселение, выезд и неустойка

**Как** Администратор стойки, **я хочу** переводить бронь по статусам (Бронь→Проживает→Выехал), **чтобы** отражать фактический жизненный цикл и фиксировать отказы/неустойки.

Источник: `Enum.СтатусБрони` (Бронь/Проживает/Выехал/ОтменаБронирования/ОтказОтБронирования/Неустойка), `state-machines.md`. 🟢

### Критерии приёмки
```gherkin
Дано бронь со статусом Бронь и наступила дата заезда
Когда гость заселяется
Тогда статус = Проживает (ячейка шахматки белая)
Дано статус Проживает и наступил выезд
Когда гость выезжает
Тогда статус = Выехал (ячейка серо-бежевая)
Дано отказ от брони
Когда фиксируется отказ
Тогда статус = ОтказОтБронирования (ячейка тёмный лосось) либо Неустойка
```
🟢 Раскраска: `Размещение/DataProcessors/Интерфейс/Forms/Форма/Module.bsl:1124-1140`.

## US-BR-07 — Аналитика глубины бронирования

**Как** Менеджер/Руководитель, **я хочу** видеть глубину бронирования по корзинам дней до заезда, **чтобы** прогнозировать загрузку.

Источник: `DataProcessors/ГлубинаБронирования`. 🟢

### Критерии приёмки
```gherkin
Дано множество активных броней
Когда формируется отчёт глубины
Тогда брони раскладываются по корзинам (0-1,2-3,4-7,8-14,15-30,31-60,>60 дней)
  И прогноз загрузки = ИтогоНомеров / КоличествоНомеров * 100
```
🟢 `ГлубинаБронирования/Forms/Форма/Module.bsl:96-138`.
