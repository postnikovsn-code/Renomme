## Обзор

Модуль управляет полным жизненным циклом брони номера отеля: приём заявок из всех каналов (стойка, сайт/Travelline, мессенджеры, лист ожидания), проверка занятости номерного фонда по почасовой модели, резервирование номера во времени, расчёт проживания и допуслуг, формирование счетов/долгов, отправка подтверждений и аннуляций гостю, аналитика глубины бронирования. Центральный объект — документ `ЗаявкаНаБронирование` (≈80 реквизитов шапки, 8 табличных частей), проводимый по регистру `ЗанятостьНомеров` и регистру накопления `Взаиморасчеты`. 🟢

## Ответственности

- Приём и регистрация заявок на бронь из разных каналов (`КаналыБронирования`). 🟢
- Конвертация сырой внешней заявки `ЗаявкаСайт` → документ `ЗаявкаНаБронирование` с защитой от дублей и сопоставлением клиента. 🟢
- Проверка занятости конкретного номера на запрашиваемый период по почасовой сетке. 🟢
- Резервирование номера: запись почасовых движений в `РегистрСведений.ЗанятостьНомеров`. 🟢
- Управление статусами брони (`Enum.СтатусБрони`): создание, заезд, выезд, отмена, отказ, неустойка. 🟢
- Формирование счетов и долгов брони, в т.ч. разделение счёта между двумя гостями. 🟢
- Парковка спроса при отсутствии свободного номера через `ЛистОжидания`. 🟢
- Поддержка спец-тарифа «БонШанс» с особым правилом непересечения резервов. 🟡
- Формирование подтверждений/аннуляций гостю (`ПодтверждениеБронирования`). 🟢
- Денормализация истории клиента (`ИсторияКлиента`) для CRM/отчётов. 🟢
- Аналитика глубины бронирования и прогноза загрузки (`ГлубинаБронирования`). 🟢

## Бизнес-правила

- **BR-01.** Бронь с признаком `ЛистОжидания = Истина` при проведении НЕ формирует движений (парковка спроса). 🟢 (`ObjectModule.bsl:8-11`)
- **BR-02.** Бронь со статусом `ОтменаБронирования` или `ОтказОтБронирования` при проведении НЕ формирует движений. 🟢 (`ObjectModule.bsl:8-11`)
- **BR-03.** Номер занят, если на пересекающийся почасовой интервал существует запись `ЗанятостьНомеров` от другого регистратора (`Регистратор <> ТекущийРегистратор`). При конфликте запись брони отменяется с сообщением «Номер занят… ЗАПИСЬ ОТМЕНЯЕТСЯ». 🟢 (`ObjectModule.bsl:13-18`, `ДокументыСервер.ЗанятостьНомераПроверить:264-311`)
- **BR-04.** Доступность номерного фонда хранится с гранулярностью **1 час**: одна запись `ЗанятостьНомеров` на каждый час интервала резерва. 🟢 (ADR-0002; `ObjectModule.bsl:61-76`)
- **BR-05.** Маппинг времён: заезд `Вр0/Вр6/Вр14/Вр18 → 0/6/14/18`; выезд `Вр0/Вр6/Вр12/Вр18 → 24/6/12/18`. Период резерва = `[НачалоЧаса(НачалоДня(РезервС)+Заезд·3600); НачалоЧаса(НачалоДня(РезервПо)+Выезд·3600)]`, последний час исключается (выезд). 🟢 (`ДокументыСервер.ЗанятостьНомераПериодРезерва:231-262`)
- **BR-06.** Суточная бронь (`РезервС = РезервПо`): окно расширяется до +24ч; при вырожденном интервале принудительно ставится окно 13:00–18:00. 🟡 (`ObjectModule.bsl:23-40`; магические часы)
- **BR-07.** Бронь по тарифу «БонШанс» (`БонШанс = Истина`) не конфликтует с другими «БонШанс»-резервами (в запросе занятости добавляется условие `БонШанс = ЛОЖЬ`). 🟡 (`ДокументыСервер.ЗанятостьНомераПроверить`)
- **BR-08.** При наложении нескольких резервов в одном часе измерение `Номер_пп` инкрементируется (механизм мульти-резерва/переселения). 🟡 (`ObjectModule.bsl:70-73`)
- **BR-09.** Разделение счёта (`РазделитьСчет И ЕстьКлиент2`): первому гостю `Цена/Сумма = X/2 + 0.001`, второму `= X − X/2 − 0.001`. Корректирующие ±0.001 гарантируют, что сумма двух половин равна исходной (без потери копейки на нечётных суммах). 🟢 (`ЗаявкаСервер.УстановитьЦенаСуммаДляРазделитьСчет:432-446`)
- **BR-10.** Удаление документа `ЗаявкаНаБронирование` разрешено только пользователю с признаком `Админ` (`ПараметрыСеанса.ТекущийПользователь.Админ`); иначе «Удаление документов запрещено», `Отказ = Истина`. 🟢 (`ObjectModule.bsl:206-215`; ADR-0010)
- **BR-11.** Конвертация `ЗаявкаСайт → ЗаявкаНаБронирование` запрещена при наличии уже созданной проведённой брони с `ЗаявкаСайт = ТекущаяСсылка` (защита от дублей). 🟢 (`ЗаявкаСайт/Forms/ФормаДокумента/Module.bsl:50-64`)
- **BR-12.** При сопоставлении клиента из заявки сайта по ФИО/телефону: `ТипСовпадения=1` — не найдено, `=2` — найдено несколько (требуется ручной выбор/создание), иначе — однозначное совпадение. 🟡 (`Forms/ФормаДокумента/Module.bsl:459`)
- **BR-13.** При копировании брони (`ПриКопировании`) сбрасываются оперативные реквизиты (времена, номер, оплата), статус выставляется `Бронь`, очищаются движения и табличные части. 🟢 (`ObjectModule.bsl:265-310`)
- **BR-14.** Комиссия турагентству начисляется, если `Бронирует.Турагентство` = Истина: % от суммы проживания без скидки + % от услуг с кодом `ПРОЖИВАНИЕ_УСЛУГИ`. 🟢 (`ДокументыСервер.СуммаКомиссии:314-353`)
- **BR-15.** Пустые счета (без детальных долгов) удаляются при записи отложенно (через массив к удалению, не в цикле обхода). 🟢 (`ObjectModule.bsl:160-181`)
- **BR-16.** Дата перехода на новый календарь цен захардкожена `'20240401'` — флаг ветвления старой/новой логики цен. 🟢 (`ДокументыСервер:369-371`; ADR-0003)
- **BR-17 (🔴 GAP).** Где формируются движения регистров `Долги`/`ОстаткиПродукции`/`ПродажиТоваров` — не обнаружено: они заявлены в регистраторах `.mdo`, но в `ОбработкаПроведения` не заполняются (мёртвый/перенесённый блок `:96-138`). 🔴

## Критерии приёмки

```gherkin
# RF-04 / BR-03 / BR-04 — резервирование и проверка занятости (основной поток)
Дано документ ЗаявкаНаБронирование со статусом "Бронь", заполненными РезервС/РезервПо/ВремяЗаезда/ВремяВыезда/НомерВРезерв
И номер свободен на запрашиваемый почасовой период
Когда документ проводится (ОбработкаПроведения)
Тогда в РегистрСведений.ЗанятостьНомеров создаётся по одной записи на каждый час интервала резерва
И в РегистрНакопления.Взаиморасчеты создаётся движение-расход на сумму долга по каждому счёту

# RF-03 / BR-03 — конфликт занятости (failure path)
Дано документ ЗаявкаНаБронирование на номер, уже зарезервированный другим документом на пересекающийся час
Когда документ проводится
Тогда выводится сообщение "Номер занят… ЗАПИСЬ ОТМЕНЯЕТСЯ"
И Отказ = Истина, движения не формируются

# RF-02 — валидация заполнения (failure path)
Дано документ ЗаявкаНаБронирование с незаполненными обязательными реквизитами
Когда документ проводится
Тогда ПроверкаЗаполнения возвращает Ложь
И Отказ = Истина, проведение отменяется

# RF-05 / BR-01, BR-02 — статусы без движений
Дано документ ЗаявкаНаБронирование со статусом "ОтменаБронирования" (или ЛистОжидания = Истина)
Когда документ проводится
Тогда движения не формируются (ранний Возврат)

# RF-06 / BR-11 — конвертация заявки сайта (happy path)
Дано документ ЗаявкаСайт без связанной проведённой брони
Когда пользователь выполняет команду "СоздатьЗаявкуНаБронирование"
Тогда открывается форма ЗаявкаНаБронирование с параметром ЗаявкаСайт = ссылка исходной заявки
И поля брони заполняются из заявки сайта

# RF-06 / BR-11 — дубль конвертации (failure path)
Дано документ ЗаявкаСайт, для которого уже существует проведённая ЗаявкаНаБронирование
Когда пользователь выполняет команду "СоздатьЗаявкуНаБронирование"
Тогда выводится предупреждение и новая бронь не создаётся

# RF-11 / BR-09 — разделение счёта (happy path)
Дано бронь с РазделитьСчет = Истина и заполненным Клиент2, сумма строки = 1001
Когда вызывается УстановитьЦенаСуммаДляРазделитьСчет для первого и второго гостя
Тогда первому начисляется 500.501, второму 500.499
И сумма двух половин равна исходным 1001 (копейка не теряется)

# RF-16 / BR-10 — право удаления (failure path)
Дано пользователь без признака Админ
Когда он пытается удалить документ ЗаявкаНаБронирование
Тогда выводится "Удаление документов запрещено" и Отказ = Истина

# RF-12 / BR-07 — БонШанс непересечение (happy path)
Дано бронь с БонШанс = Истина на номер, где уже есть другая бронь БонШанс на тот же час
Когда проверяется занятость
Тогда конфликт НЕ фиксируется (фильтр БонШанс = ЛОЖЬ), номер считается доступным
```

## Приоритизация (MoSCoW)

| Требование | MoSCoW | Обоснование |
|-----------|--------|---------------|
| Проверка занятости + почасовое резервирование (RF-03, RF-04) | Must | Критический путь; ядро модели доступности (ADR-0002) |
| Валидация + проведение брони (RF-01, RF-02, RF-08) | Must | Без них бронь не существует как сущность |
| Ранний выход для отмен/листа ожидания (RF-05) | Must | Бизнес-правило без fallback (BR-01/BR-02) |
| Конвертация заявки сайта (RF-06) | Must | Основной канал поступления броней; защита от дублей критична |
| Формирование счетов (RF-10) | Must | Финансовый контур брони |
| Право удаления — только админ (RF-16) | Must | Защита данных; правило без альтернативы (ADR-0010) |
| Сопоставление клиента (RF-07), подтверждения (RF-13), история (RF-14), split-bill (RF-11) | Should | Важно, но есть ручные альтернативы |
| БонШанс (RF-12), комиссии/B2B (RF-17), мульти-резерв (RF-18), глубина (RF-15) | Could | Срабатывают в частных случаях/аналитике |
| Мёртвые версии (`СформироватьНаСервере_1/2/3`, `ВыполнитьЗапросСайт`, пустая `ОбновитьИсториюКлиента`) | Won't | Закомментированный/отключённый код, не воспроизводить |
