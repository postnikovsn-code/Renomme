## Обзор

Модуль отвечает за всё ценообразование номеро-ночи: базовый прайс категории, плановые (сезонные) и оперативные правки цены по датам через динамический «Календарь цен», тарифные планы (матрица будни/выходные × одно/двухместный × с/без завтрака), горящий тариф «БонШанс», расчёт полной стоимости проживания за период брони (раскладка по дням, коэффициент частичных суток), систему скидок (категорийная, накопительная клиентская, комиссия турагентства, B2B-наценка), аналитику конкурентов и динамическое задание цены по корзинам загрузки. Ядро расчёта проживания физически лежит в `ОбщийМодуль.ДокументыСервер`, но принадлежит ценообразованию (вызывается из модуля «Бронирование» для заполнения ТЧ `ЗаявкаНаБронирование.Проживание`). 🟢

## Ответственности

- Хранение базового прайса (`Catalog.БазовыеЦены`, «с даты установки») и тарифных планов (`Catalog.ТарифныеПланы`). 🟢
- Динамическое ценообразование по датам через регистры `КалендарьЦенБазовый`/`КалендарьЦенКатегории` с разрезом `ВидЦены` (Долгосрочная/Текущая). 🟢
- Расчёт цены дня каскадом: Базовая → Долгосрочная → Текущая (`КалендарьЦен.ПолучитьТекущаяЦенаДня`). 🟢
- Расчёт цены дня по тарифному плану (матрица 2×2×2 с fallback). 🟢
- Расчёт полной стоимости проживания за период брони (`ДокументыСервер.ЗаполнитьТаблицуПроживания_Таблица`). 🟢
- Применение коэффициента частичных суток по времени заезда/выезда. 🟢
- Расчёт скидки = MAX(категорийная, накопительная клиентская) + комиссия турагентства + B2B-наценка по историзированным процентам. 🟢
- Запись/изменение цен наборами записей из формы `КалендарьЦен` (текущие и долгосрочные) с логированием в `*История`. 🟢
- Расчёт горящей цены «БонШанс» (`InformationRegister.ЦеныБонШанс`). 🟢
- Аналитика цен конкурентов и средней цены (`ЦеныКонкурентовАналитика`, загрузка из TravelLine). 🟢
- Динамическое задание рекомендуемой цены по корзинам загрузки 30/45/60/75/90% (`КалендарьЦенЗаданиеНаЦены`). 🟢
- Автономный калькулятор стоимости проживания (`РасчетПроживания`). 🟢
- Ветвление расчёта по magic-date `'20240401'` (старый/новый календарь цен). 🟢

## Бизнес-правила

- **BR-01.** Цена дня по ценовой политике = каскад трёх уровней: базовая цена (последняя запись `БазовыеЦены` с `ДатаУстановкиЦены ≤ ДатаЦены`) → перезапись долгосрочными записями календаря (`ВидЦены=Долгосрочная`) → перезапись текущими записями (`ВидЦены=Текущая`). При отсутствии текущих записей текущая цена = долгосрочная; при отсутствии долгосрочных = базовая. 🟢 (`КалендарьЦен.ПолучитьТекущаяЦенаДня:161-224`; ADR-0004)
- **BR-02.** Состав цены дня: `Одноместный = База + ДоплатаЗаКатегорию (+ ДоплатаЗаЗавтрак×1, если с завтраком)`; `Двухместный = База + ДоплатаЗаДвухместный + ДоплатаЗаКатегорию (+ ДоплатаЗаЗавтрак×2)`. Завтрак двухместного считается двойным (допущение «2 гостя = 2 завтрака»). 🟢 (`flowcharts/Ценообразование-ЦенаДняКалендарь.md`)
- **BR-03.** Приоритет источника цены строки проживания: тарифный план (`ЦенаНаДеньТарифныйПлан`) → если цена = 0, ценовая политика календаря (`ЦенаНаДень`). У цены тарифа скидка клиента НЕ применяется (`Сумма = СуммаБезСкидки`); у цены ценовой политики — применяется. 🟢 (`ДокументыСервер.ЗаполнитьЦенаСуммыСтрокаПроживание:515-539`)
- **BR-04.** Тарифная матрица — 8 цен в ТЧ `ТарифныйПланСтроки`: будни/выходные × одно/двухместный × с/без завтрака. Выходной день = `ДеньНедели(ДТН) > 4` (пт/сб/вс). Цены «без завтрака» имеют fallback на цену «с завтраком», если поле = 0. 🟢 (`flowcharts/Ценообразование-ЦенаТарифныйПлан.md`)
- **BR-05.** Выбор строки тарифа: первая по сортировке `(ДатаТарифаС, ДатаТарифаПо)`, у которой `ДатаС ≤ ДТН ≤ ДатаПо` (пустые границы = без ограничения) и категория совпадает либо не задана (пустая категория = «для всех»). Возврат 0 при отсутствии подходящей строки/тарифа → переключение на ценовую политику. 🟢 (`ЦенаНаДеньТарифныйПлан:553-628`)
- **BR-06.** Период проживания раскладывается по дням на интервале `[РезервС; РезервПо−86400]` (последняя ночь — день перед выездом). 🟢 (`ЗаполнитьТаблицуПроживания_Таблица:428-513`)
- **BR-07.** Коэффициент частичных суток (`Количество` строки): день заезда — `Вр0→2`, `Вр6→1.5`, иначе `1`; день выезда — `Вр18→1.5`, `Вр0→2`, иначе `1`; промежуточный день — `1`. 🟢 (`flowcharts/Ценообразование-РасчетПроживания.md`)
- **BR-08.** Однодневная бронь (`РезервС = РезервПо`) — отдельная ветка, `Количество = 1`; коэффициенты заезда/выезда не применяются (закомментированы). 🟢
- **BR-09.** Бронь по тарифу «БонШанс» (однодневная + признак) — цена из `InformationRegister.ЦеныБонШанс` (последняя запись ≤ даты) с fallback на `Константы.БонШансЦена`; скидка клиента НЕ применяется. 🟢 (`ПолучитьБонШансЦена:405-425`)
- **BR-10.** Итоговая скидка строки проживания = `MAX(ИтогоСкидка, СкидкаКлиент)`. `ИтогоСкидка` — категорийная/комиссионная скидка по приоритету Бронирует(турагентство)→Оплачивает→Клиент из реквизита `Категория.Скидка`. `СкидкаКлиент` — накопительная скидка по истории оплаченных ночей (только для физлиц «Реноме»). 🟢 (`ИтогоСкидкаКлиент:657-673`, `ИтогоСкидка:773-808`, `СкидкаКлиента:676-768`)
- **BR-11.** Для турагентств с типом оплаты Взаимозачет / ОплатаТурагентствомСоСкидкой скидкой выступает процент комиссии. Комиссия = `Окр(СуммаПроживанияБезСкидки × %/100, 2)` + комиссия по услугам с программным кодом `ПРОЖИВАНИЕ_УСЛУГИ`. 🟢 (`СуммаКомиссии:314-353`)
- **BR-12.** B2B-наценка для строк с флагом В2В = `(Цена/((100−%)/100) − Цена) × Количество`. Процент комиссии/B2B берётся из ТЧ `Клиенты.ПроцентыКомиссии`/`ПроцентыВ2В` (последняя запись ≤ даты) с fallback на реквизит клиента. 🟢 (`СуммаВ2В:356-365`, `ПроцентКомиссии:816-838`, `ПроцентВ2В:840-862`)
- **BR-13.** Округление: `ОкруглитьЦену = Цел(Цена)`; `ОкруглитьЦену_25` — округление до 0/50/100 руб (порог 25/75); `ОкруглитьСумма = Окр(Сумма, 2)`. 🟢 (`ОкруглитьЦену*:374-394`)
- **BR-14.** Изменение цен записывается наборами записей регистров `КалендарьЦенБазовый`/`КалендарьЦенКатегории` из формы `КалендарьЦен`: набор по `(ДатаЦены, ВидЦены)` читается, `Очистить()`, заполняется заново ТОЛЬКО изменёнными типами цен (точечное хранение отклонений). Документы `ИзменениеЦены`/`ИзменениеБазовойЦены` движений НЕ делают. 🟢 (`ИзменитьВыбранныеНаСервере:1565-1661`)
- **BR-15.** Каждое изменение цены логируется в `*История` (измерение `ДатаВремяИзменения`, ресурс — новое значение, реквизит `Автор`); запись истории пропускается, если значение не изменилось. 🟢 (`ЗаписатьКалендарьЦенБазовыйИстория:1664`, `ЗаписатьКалендарьЦенКатегорииИстория:1681`)
- **BR-16.** Интерактивное изменение цен пишет `ВидЦены = Текущая`; долгосрочные цены меняются отдельной процедурой `ИзменитьДолгосрочныеЦеныНаСервере` (`ВидЦены = Долгосрочная`). 🟢
- **BR-17.** Расчёт цены ветвится по magic-date `ДатаПереходаНаНовыйКалендарьЦен = '20240401'`: бронь/день ДО границы считается старым модулем `ДокументыСервер_Старый`/`КалендарьЦен_Старый`, после — новым календарём цен. 🟢 (`ДатаПереходаНаНовыйКалендарьЦен:369-371`; ADR-0003)
- **BR-18.** Средняя цена конкурентов = среднее по отелям с непустой ценой и `НЕ ПродажиЗакрыты`; при отсутствии данных — fallback на цену TravelLine. 🟢 (`СредняяЦенаКонкурентовАналитика:577-595`)
- **BR-19.** Динамическое задание цены: фактический % загрузки маппится в нижнюю границу корзины 30/45/60/75/90% (`ГраницаЗначение`), что служит основой рекомендации цены, записываемой в `InformationRegister.ЦеныКонкурентовАналитика`. 🟢 (`КалендарьЦенЗаданиеНаЦены:390-422`)
- **BR-20 (🔴 GAP).** Назначение документов `ИзменениеЦены`/`ИзменениеБазовойЦены` (ТЧ `ДатаЦены`: Процент/Категория/Двухместный/БезЗавтрака) не подтверждено: метаданные есть, `ObjectModule` и движений нет, реальная запись идёт мимо них из формы обработки. 🔴 (см. `questions.md` Q-03)

## Критерии приёмки

```gherkin
# RF-03 / BR-01 — каскад цены дня (happy path)
Дано дата ДатаЦены, категория номера и флаг с завтраком
И есть базовая цена, нет долгосрочных и текущих правок календаря на эту дату
Когда вызывается ПолучитьТекущаяЦенаДня(ДатаЦены, Категория, БезЗавтрака)
Тогда текущая цена дня равна базовой цене (Одноместный = База + ДоплКатегория + ДоплЗавтрак×1)

# RF-03 / BR-01 — перезапись текущей ценой (happy path)
Дано на дату есть текущая запись календаря с новой базовой ценой
Когда вызывается ПолучитьТекущаяЦенаДня
Тогда текущая цена дня берётся из текущей записи (перекрывает базовую и долгосрочную)

# RF-03 / BR-01 — fallback при отсутствии данных (failure path)
Дано на дату НЕТ записи базовой цены (БазовыеЦены пуст)
Когда вызывается ПолучитьТекущаяЦенаДня
Тогда все цены = 0 (контракт не падает, отдаёт нулевую структуру)

# RF-04 / BR-04 — тариф без завтрака с fallback (happy path)
Дано выбран тарифный план, день будний, двухместный, без завтрака, поле ЦенаБудниДвухБезЗавтрака = 0
Когда вызывается ЦенаНаДеньТарифныйПлан
Тогда возвращается ЦенаБудниДвух (fallback «без завтрака»=0 → обычная цена)

# RF-04 / BR-05 — нет подходящей строки тарифа (failure path)
Дано тариф задан, но нет строки с ДатаС ≤ ДТН ≤ ДатаПо и подходящей категорией
Когда вызывается ЦенаНаДеньТарифныйПлан
Тогда возвращается 0 (вызывающий код переключается на ценовую политику)

# RF-05, RF-06 / BR-06, BR-07 — расчёт проживания с частичными сутками (happy path)
Дано бронь с РезервС < РезервПо, ВремяЗаезда = Вр6, ВремяВыезда = Вр18
Когда вызывается ЗаполнитьТаблицуПроживания_Таблица(Объект, Двухместный)
Тогда создаётся строка на каждый день [РезервС; РезервПо−86400]
И день заезда имеет Количество = 1.5, день выезда — Количество = 1.5, промежуточные — 1

# RF-07 / BR-03 — несимметрия скидок (happy path)
Дано строка проживания с заполненным тарифным планом, цена тарифа > 0
Когда вызывается ЗаполнитьЦенаСуммыСтрокаПроживание
Тогда Сумма = СуммаБезСкидки (скидка клиента НЕ применяется)

Дано строка проживания без тарифа (цена из ценовой политики)
Когда вызывается ЗаполнитьЦенаСуммыСтрокаПроживание
Тогда Сумма = Окр(СуммаБезСкидки × (1 − Скидка/100), 2) (скидка применяется)

# RF-08 / BR-10 — итоговая скидка = MAX (happy path)
Дано категорийная скидка = 5%, накопительная клиентская = 8%
Когда вызывается ИтогоСкидкаКлиент
Тогда итоговая скидка строки = 8% (MAX из двух)

# RF-10 / BR-09 — БонШанс без скидки (happy path)
Дано однодневная бронь с признаком БонШанс
Когда вызывается ЗаполнитьТаблицуПроживания_Таблица
Тогда Цена = ПолучитьБонШансЦена (последняя ЦеныБонШанс ≤ даты или Константы.БонШансЦена)
И Сумма = Цена × 1 без применения скидки

# RF-11 / BR-14, BR-15 — запись изменения цен (happy path)
Дано на форме КалендарьЦен изменены цены для набора выбранных дат
Когда вызывается ИзменитьВыбранныеНаСервере
Тогда наборы записей КалендарьЦенБазовый/КалендарьЦенКатегории по (ДатаЦены, Текущая) перезаписываются только изменёнными типами
И в *История пишется запись с Автором по каждому изменённому значению

# RF-12 / BR-17 — граница magic-date (failure/branch path)
Дано бронь с РезервПо до '20240401'
Когда вызывается ЗаполнитьТаблицуПроживания_Таблица
Тогда расчёт делегируется ДокументыСервер_Старый (старая модель цен)
```

## Приоритизация (MoSCoW)

| Требование | MoSCoW | Обоснование |
|-----------|--------|---------------|
| Каскад цены дня (RF-03), цена тарифа (RF-04), расчёт проживания (RF-05, RF-06, RF-07) | Must | Критический путь; ядро ценообразования, вызывается из каждой брони |
| Базовый прайс и тарифные планы (RF-01, RF-02) | Must | Источники цены, без них расчёт невозможен |
| Запись изменения цен + история (RF-11) | Must | Единственный фактический механизм управления ценами |
| Ветвление по magic-date (RF-12) | Must | Без него исторические суммы искажаются (ADR-0003) |
| Итоговая скидка MAX (RF-08), округление (RF-17) | Must | Прямо влияют на сумму счёта |
| Комиссия/B2B (RF-09), калькулятор (RF-13), % эквайринга (RF-16) | Should | Важны, но есть ручные/смежные альтернативы |
| БонШанс (RF-10), задание цены по загрузке (RF-14), средняя цена конкурентов (RF-15) | Could | Срабатывают в частных случаях / аналитике |
| Старые ветви `ДокументыСервер_Старый`/`КалендарьЦен_Старый`, `Тариф_НеИспользуется`, `КодыТарифов_КУдалению` | Won't | Legacy для исторических дат / помечены к удалению; новую логику не воспроизводить |
| Методы формы `КалендарьЦен` `*_OLD`/`Тест`/`_1`/`_2` | Won't | Отключённые/тестовые версии |

> Приоритет выведен по частоте вызова и позиции в цепочке зависимостей.
