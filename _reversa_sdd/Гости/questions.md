# Гости и регистрация, Вопросы для человеческой валидации

> Файл `questions.md`. Пробелы (🔴) и сомнения (🟡), требующие подтверждения владельцем системы/командой эксплуатации перед реализацией/миграцией. Каждый вопрос ссылается на легаси.

## 🔴 Критические (блокируют корректную реконструкцию)

### Q-01 — Магическое число типа документа `103008` (паспорт РФ)
В выгрузке ФМС для граждан РФ тип документа жёстко зашит как `103008` в двух местах: `ВыгрузкаДляФМС/Forms/Форма/Module.bsl:181` и `Клиенты/Forms/ФормаЭлемента/Module.bsl:2019`.
- Откуда это значение (классификатор ФМС `ТипДокументаФМС_NEW.ID`)? Является ли оно стабильным?
- Можно ли заменить на ссылку на предопределённый элемент классификатора, чтобы убрать рассинхрон двух копий?
**Влияние:** некорректный тип документа → отбраковка файла миграционной службой.

### Q-02 — Незавершённая миграция реквизитов `_NEW` / `_OLD`
В `Catalog.Клиенты` сосуществуют старая и новая модели ФМС-данных: `ГражданствоФМС_NEW`, `ТипДокументаФМС_NEW`, `ПунктыВыдачиФМС_NEW`, … и `_OLD`/`_НеИспользуется` (`ПроцентАгент_OLD`, `Тариф_НеИспользуется`); в коде выгрузки — десятки закомментированных `_OLD`-полей (`code-analysis.md` §3.4; ADR-0007).
- Какая модель актуальна на сегодня (`_NEW`)? Можно ли удалить `_OLD`?
- Какие `_OLD`-поля ещё содержат живые данные, требующие миграции?
**Влияние:** перенос неверной модели → потеря/искажение миграционных данных.

### Q-03 — Объединение клиентов: `Записать(Проведение)` в цикле без `Попытка`
`ОбъединитьКлиентовНаСервере` (`КлиентыОбъединиение/.../Module.bsl:206-221`) выполняет каскадную замену в транзакции, но `Записать(Проведение)` внутри цикла не обёрнут в `Попытка/Исключение`; при сбое `ОтменитьТранзакцию` не вызывается (нарушение `BeginTransactionBeforeTryCatch`).
- Подтвердить, что это дефект, и согласовать исправление (обернуть тело в `Попытка/Исключение` + `ОтменитьТранзакцию`).
- Были ли случаи частичного объединения в продакшене?
**Влияние:** несогласованные ссылочные данные при сбое слияния.

### Q-04 — Внешние классификаторы ФМС (`*ФМС_NEW`)
Справочники `СтраныФМС_NEW`, `ТипДокументаФМС_NEW`, `ПунктыВыдачиФМС_NEW`, `КратностьВизыФМС_NEW`, `ТипВизыФМС_NEW`, `ЦельВъездаФМС_NEW`, `ЦельПоездкиФМС_NEW`, `ПунктПересеченияГраницыФМС_NEW`, `СтепеньРодства` (реквизиты `ID`, `CODE_ALPHA3`, `CODE_0`, `END_DATE`) — структура не разбиралась (вне домена) (`legacy-mapping.md` §Внешние справочники ФМС).
- Источник классификаторов (официальные справочники ФМС/МВД)? Как обновляются?
- Семантика `CODE_ALPHA3`, `CODE_0`, `ID`, `END_DATE` для каждого справочника?
**Влияние:** без точной структуры классификаторов выгрузка ФМС невоспроизводима.

### Q-05 — `Document.АнкетаНовая`: 5 ТЧ ответов не разобраны
Самоописываемая анкета с ТЧ `Заголовки`, `Вопросы` и 5 ТЧ ответов (`Ответы_ПХУП`, `Ответы_Текст`, `Ответы_ДаНет`, `Ответы_ТаблицаДаНет`) (`data-dictionary.md` §Document.АнкетаНовая).
- Как связаны метаданные вопросов и ТЧ ответов? Логика построения формы по типу ответа (ПХУП/Текст/ДаНет/ТаблицаДаНет)?
- Используется ли `АнкетаНовая` вместо `Анкета`, или обе параллельно?
**Влияние:** нельзя реконструировать функциональность анкетирования.

## 🟡 Важные (влияют на полноту, не блокируют ядро)

### Q-06 — Детекция дублей только для юрлиц
`КлиентыДвойныеИНН` выявляет дубли только `ТипКлиента=ЮрЛицо` (`Module.bsl:22-143`). Намеренно ли физлица исключены? Нужна ли детекция дублей физлиц (ФИО+ДатаРождения+паспорт)?

### Q-07 — Версионные дубли кода (мёртвый код)
`ВыгрузкаДляФМС` vs `ВыгрузкаДляФМС_Исходная`; `ПечатьУведомления` vs `ПечатьУведомления_Старое`; `ИсторияКлиентаНаСервере_Старое`; `ПрикрепитьФотоДействие_1`/`ПереместитьФайлВПутьДоФото_1`. Подтвердить, что `_Исходная`/`_Старое`/`_1` — мёртвые копии, исключаемые из реконструкции (MoSCoW = Won't).

### Q-08 — Семантика «Исключить из отчётов» (GR-02)
Вид клиента «Исключить из отчётов» отключает антидубль по наименованию (🟡, выведено). Подтвердить точное условие и какие именно виды клиентов под него попадают.

### Q-09 — Политика хранения ПДн и сканов
Сканы паспортов хранятся в файловой папке `Папка_СКАНЫ` и в ТЧ `СканыДокументов`; карточка содержит полные паспортные/миграционные данные. Каковы требования к шифрованию/сроку хранения/удалению (152-ФЗ)?

### Q-10 — `АдресРегистрацииОтсутствует` для ИГ всегда True
В выгрузке ФМС для иностранного гражданина признак трактуется как True (🟡). Подтвердить, что это корректное допущение формата, а не дефект.
