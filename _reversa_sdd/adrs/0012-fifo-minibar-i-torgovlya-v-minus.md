# ADR 0012 — FIFO-партионный учёт минибара с допущением «торговля в минус»

- **Статус:** Принято (исторически) · 🟢 ПОДТВЕРЖДЕНО кодом
- **Дата:** неизвестна
- **Модуль:** Минибар

## Контекст

Минибар потребляется гостями и фиксируется горничными постфактум (при уборке). Себестоимость нужна для отчёта прибыли. Фактический расход часто регистрируется позже прихода и может превышать учётный остаток (товар физически был, но приход не оформлен вовремя).

Свидетельства:
- `МинибарПриход` создаёт отдельную FIFO-партию на каждый приход; `МинибарРасход` списывает от старейшей партии по дате прихода (MB-01). 🟢
- При нехватке партий добавляется движение расхода БЕЗ `ДокументПрихода` (пустая партия), уводящее остаток в минус; себестоимость такого расхода = 0 (MB-02). 🟢
- Расход собирается из уборок (`ГорничныеОбслуживаниеНомера.Минибар`) идемпотентно за месяц (MB-04). 🟢
- Параллельно существует ОТДЕЛЬНЫЙ контур «Бар» (`Товары`/`ОстаткиПродукции`) с инвентаризацией (MB-06). 🟢

## Решение

Вести минибар партионным методом FIFO (партия = документ прихода), а средневзвешенную себестоимость считать помесячно. При нехватке партий не блокировать расход, а допускать отрицательный остаток («торговля в минус») с нулевой себестоимостью недостающего количества.

## Рассмотренные альтернативы

- **Запрет расхода при нехватке остатка.** Отклонено: горничные регистрируют фактическое потребление постфактум — запрет потерял бы реальные продажи; учёт должен следовать за фактом.
- **Только средневзвешенный учёт без партий.** Частично применено для отчёта прибыли/себестоимости (помесячный средневзвешенный срез), но партии нужны для FIFO-списания.
- **Объединение минибара и бара в один контур.** Не сделано: «Бар» (`Товары`/`ОстаткиПродукции`) ведётся независимо; синхронизация остатков между контурами в коде не обнаружена (🔴).

## Последствия

- ➕ Учёт следует за фактом потребления; не теряет продажи при запоздалом приходе.
- ➕ Помесячная средневзвешенная себестоимость для отчёта прибыли.
- ➖ 🔴 «Торговля в минус» с нулевой себестоимостью занижает себестоимость и завышает прибыль — учётная корректность не гарантирована.
- ➖ 🔴 Два независимых товарных контура (минибар vs «Бар») без обнаруженной синхронизации остатков.
- ➖ Магическая строка `НайтиПоНаименованию("Бар")` ломается при переименовании группы; опечатка в FQN `ИнвентарицацияБара`.
- ⚠ При миграции: согласовать контуры минибар/бар и пересмотреть политику отрицательных остатков/себестоимости.
