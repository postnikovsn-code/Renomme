# Интеграции и обмен — Крайние случаи

> Файл `edge-cases.md`. Граничные и отказные сценарии транспортного слоя. Шкала доверия: 🟢/🟡/🔴.
> Корень легаси: `ПСН_РЕНОМЕ__АУДИТ/src`.

## EC-01 — Внешний сервис недоступен / таймаут 🟢

- **Сценарий:** сайт, HTTP-сервис заселений или Green API не отвечает / превышен таймаут.
- **Текущее поведение:**
  - `ОбменСайт.ПолучитьДанныеБронирования`: исключение оборачивается в `{ДанныеJSON=Массив(), Ошибка=Истина, Описание=ОписаниеОшибки()}` — вызывающий получает пустой результат, а не падение.
  - `HTTP_Модуль`: таймаут соединения 120 c; код состояния ≥ 300 → ошибка.
  - `GREEN_WhatsApp`: код ≠ 200 → `ВызватьИсключение` (статус+тело), адаптер `WhatsAppСервер` ловит и возвращает `{Ошибка=Истина, ...}`.
- **Источник:** `ОбменСайт/Module.bsl`, `HTTP_Модуль/Module.bsl`, `GREEN_WhatsApp/Module.bsl`, `WhatsAppСервер/Module.bsl`.
- **Ожидаемое (контракт):** ошибка не должна прерывать вызывающий бизнес-поток; результат — структура-ответ с `Ошибка=Истина`.
- **Доверие:** 🟢

## EC-02 — Истёкший token PayKeeper 🟢

- **Сценарий:** `Токен.ВремяИстечения < ТекущаяДата()` (TTL 1200 c вышел) на момент запроса.
- **Текущее поведение:** `ОбновитьТокен` лениво делает GET `/info/settings/token/`, перезаписывает `Идентификатор` и `ВремяИстечения`. Если токен получить не удалось — `ВызватьИсключение`.
- **Источник:** `PayKeeper.ОбновитьТокен` (`PayKeeper/Module.bsl`).
- **Ожидаемое:** прозрачное переполучение токена перед любым запросом; единичная неудача обновления — фатальна (исключение), повторных попыток нет.
- **Доверие:** 🟢

## EC-03 — Дубль платежа при upsert 🟢

- **Сценарий:** один и тот же платёж PayKeeper (`ИД_Платежа`) приходит повторно в списке (повторный опрос).
- **Текущее поведение:** `ОбновитьPayKeeperПлатежи` делает upsert по `ИД_Платежа`, **сохраняя** существующие `ГУИД` и `ДатаСоздания` (не перезаписывает их), обновляя статус/сумму/дату оплаты. Привязка к долгу выполняется только при `Статус='success'`.
- **Источник:** `PayKeeperСервер.ПолучитьИОбработатьСписокПлатежей` / `ОбновитьPayKeeperПлатежи` (`PayKeeperСервер/Module.bsl`).
- **Ожидаемое:** идемпотентность — повторный приём не создаёт дубль и не теряет историю; защита от двойной привязки к долгу требует проверки (🟡 — не подтверждено, что повторная `СвязатьPayKeeperПлатежи` идемпотентна).
- **Доверие:** 🟢 (upsert) / 🟡 (повторная привязка)

## EC-04 — FTP недоступен при обмене 🟢

- **Сценарий:** FTP-сервер узла недоступен при записи/чтении сообщения плана обмена.
- **Текущее поведение:**
  - При записи: `ФТПСервер.ЗаписатьФТПФайл` возвращает структуру с `Ошибка=Истина`; в потоке `Сообщить(...)` об ошибке FTP; **временный XML-файл всё равно удаляется** (метка `~ВЫХОД`).
  - При чтении отсутствие/недоступность файла соотносится с кодами 1/30 → «нет сообщения» (не фатально).
- **Источник:** `ОбменГостиницы/Module.bsl` (WRITE/READ), `ФТПСервер/Module.bsl`.
- **Ожидаемое:** сбой FTP по одному узлу не должен прерывать обмен по остальным узлам; ресурсы (temp-файл) освобождаются.
- **Доверие:** 🟢

## EC-05 — Нормализация телефона: невалидный номер 🟢

- **Сценарий:** номер с буквами/спецсимволами, неполный или иностранный формат.
- **Текущее поведение (`ТелефонGREEN`):** отбрасываются все не-цифры; `8…`→`7…`; ровно 10 цифр → `7`+номер; иначе результат `0` (невалидно). chatId = `<номер>@c.us`.
- **Граничные значения:** `89991234567`→`79991234567`; `9991234567`→`79991234567`; `+7 (999) 123-45-67`→`79991234567`; `abc`/короткий → `0`.
- **Источник:** `GREEN_WhatsApp.ТелефонGREEN`.
- **Ожидаемое:** при результате `0` сообщение не отправляется (или отдаётся ошибка); диспетчер не должен формировать невалидный chatId.
- **Доверие:** 🟢 (нормализация) / 🟡 (обработка результата `0` вызывающим кодом — уточнить)

## EC-06 — Нет нового сообщения в плане обмена (коды 1/30) 🟢

- **Сценарий:** входящего сообщения с изменениями для узла нет.
- **Текущее поведение:** коды ошибок чтения `1` и `30` трактуются как «нет нового сообщения» и НЕ являются фатальными; цикл продолжается по следующим узлам.
- **Источник:** `ОбменГостиницы.ВыполнитьОбменДанными`.
- **Ожидаемое:** обмен устойчив к пустым итерациям; в результат добавляется неблокирующая запись.
- **Доверие:** 🟢

## EC-07 — COM-соединение с планшетом недоступно 🟡

- **Сценарий:** база планшета горничных недоступна (файл занят/недоступен COM).
- **Текущее поведение:** до 3 попыток через `Перейти ~Соединение`; ошибки гасятся пустыми `Попытка` без логирования — сбой может остаться незамеченным.
- **Источник:** `ОбменКартинкаСервер/Module.bsl:8,16`.
- **Ожидаемое:** после исчерпания попыток — явная ошибка/лог; молчаливое проглатывание недопустимо при переподнятии.
- **Доверие:** 🟡

## EC-08 — Канал мессенджера выключен 🟢

- **Сценарий:** все каналы выключены (`СообщенияЧерез*` = Ложь).
- **Текущее поведение:** `МесенджерВключен()` = Ложь; рассылка сообщает «выключено» и завершается без отправки.
- **Источник:** `МесенджерСервер.МесенджерВключен`, `РассылкаWhatsApp`.
- **Ожидаемое:** отсутствие включённых каналов — нормальный неотправляющий путь, не ошибка.
- **Доверие:** 🟢

## EC-09 — HTML-страница блокировки хостинга PayKeeper 🟢

- **Сценарий:** PayKeeper/хостинг возвращает HTML («Система заблокирована. Требуется продление хостинга», `<!DOCTYPE html>`) вместо JSON.
- **Текущее поведение:** транспорт детектирует HTML и извлекает текст ошибки, не пытаясь разобрать JSON.
- **Источник:** `PayKeeper.ВыполнитьЗапрос`.
- **Ожидаемое:** понятная ошибка вместо падения парсера JSON.
- **Доверие:** 🟢

## EC-10 — Пустой состав плана `ВГ_ВыпискаГостиницы` 🟡

- **Сценарий:** обмен выписками с Бухгалтерией при пустом составе плана обмена.
- **Текущее поведение:** штатная регистрация изменений не используется; обмен ведётся вручную через сериализацию `DocumentObject.Выписка` (`ОбменВыписка`), узел ищется `НайтиПоКоду("БУХ")`.
- **Источник:** `ExchangePlans/ВГ_ВыпискаГостиницы/`, `ОбменВыписка/Module.bsl`.
- **Ожидаемое:** при переподнятии — не полагаться на `ВыбратьИзменения`; явный ручной сценарий сериализации.
- **Доверие:** 🟡
