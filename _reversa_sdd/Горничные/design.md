## Архитектурная особенность

Сосуществуют **две базы 1С**: основная «ОТЕЛЬ» и отдельная база «Горничные» (планшеты). Уборки/смены регистрируются в БД горничных, в «ОТЕЛЬ» **загружаются** по синхронному COM (`V83.COMConnector`). В обеих базах есть одноимённый общий модуль `ОбменГорничныеСервер` — RPC-фасад; вызовы идут как `Соединение.ОбменГорничныеСервер.<Метод>(…)` 🟢. Подробности контракта обмена — в `contracts.md`.

## Основной поток — расчёт зарплаты (`РасчитатьЗарплатуНаСервере`)

1. `ЗаполнитьСправочныеДанные`: цены уборок, помещения, горничные, шкала стажа 🟢.
2. Если `ОбменСГорничными` и установлен флаг дозагрузки — `ЗагрузитьОбслуживаниеНомеров/Помещений/Смены` за `ДН..ДК` 🟢.
3. `ЗаполнитьЦеныУборки`: срез `ГорничныеСтоимостьУборок` на первую запись с `ДатаНазначенияЦены <= ДН` 🟢.
4. Запросы агрегатов: РС `УборкиНомеров` (Г/Т/ТС/РК/МК/МДМ по `ТипУборкиПризнак`, `ВремяУброки` в ДН..ДК), прачечная (Σ `СуммаПрачечная`), смены (`КОЛИЧЕСТВО РАЗЛИЧНЫЕ ДатаСмены`), помещения (`КОЛИЧЕСТВО РАЗЛИЧНЫЕ Ссылка` где `Обслужено`) 🟢.
5. Цикл по справочнику горничных: оклад → отпуск → надбавка за стаж → надбавка за стандарты → прачечная → (если `УчетУборок`) сдельные уборки → перенос ручных `_Р/_Есть` → часы 🟢.
6. Помещения: количества + ручные корректировки 🟢.
7. `ОбновитьСтрокаСуммы`: `Поле_Э = ?(Поле_Есть, Поле_Р, Поле_И)`; для количеств `Кол_Э = Кол_И + Кол_Р`, `Сумма = Кол_Э × Цена` 🟢.
8. `ОбновитьЗарплатаИтого`: итог по всем составляющим + прачечная; остаток к выдаче = итого − выплаты 🟢.
9. Запись + проведение документа 🟢.

## Основной поток — загрузка уборок (`ЗагрузитьОбслуживаниеНомеров`)

1. Проверка `ОбменСГорничными`; выход при `Ложь` 🟢 (120-121).
2. `Соединение()`; при `Неопределено` — сообщение и выход 🟢 (123-128).
3. COM: `ВыгрузитьОбслуживаниеНомеров(С, По, НомерГорничные)` → ТЗ (в `Попытка` с подавлением) 🟢 (130-136).
4. Кэш-запросы: существующие документы за период, `НомернойФонд`, `ГорничныеНомера` (по одному разу) 🟢 (138-164).
5. Для каждой строки ТЗ: поиск документа по ключу (ДатаОбслуживания + НомерОбслуживания_пп + НомерГорничные); сопоставление номера и горничной 🟢 (166-187).
6. Если документ найден и `РучноеИзменение` — `Продолжить` (пропуск) 🟢 (214).
7. Если нет — создание документа; при незаполненных `НомерВРезерв`/`ГорничныеНомер` — сообщение и `Продолжить` 🟢 (189-209).
8. Заполнение реквизитов + ТЧ Минибар (поиск номенклатуры по коду, цена из карточки)/ТехНеисправности/ДопОборудование 🟢 (278-329).
9. Запись: при `ПометкаУдаления` — `РежимЗаписиДокумента.Запись` + пометка; иначе — `Проведение` 🟢 (217-335).
10. В конце — `ЗагрузитьСостояниеНомеров()` 🟢 (338).

## Основной поток — проведение уборки (`ГорничныеОбслуживаниеНомера.ОбработкаПроведения`)

1. Одна запись в РС `УборкиНомеров`, измерение `Документ` = ссылка документа 🟢.
2. Денормализация: Комната, Горничная, ВремяУброки, ТипУборкиПризнак, ТипУборки/Комплектации, и склейки строк (`ПолучитьМинибар`/`ПолучитьОборудование`/`ПолучитьТехническиеНеисправности`) 🟢.

## Основной поток — деление прачечной (`ОбновитьСуммаПрачечная`)

1. `СуммаНДС = Окр(СуммаОплаты × СтавкаНДС/(100+СтавкаНДС))` 🟢.
2. `СуммаБезНДС = СуммаОплаты − СуммаНДС` 🟢.
3. `СуммаОтелю = Окр(СуммаБезНДС × ПроцентОтеля/100)` (`ПроцентОтеля=10` по умолчанию) 🟢.
4. `СуммаПрачечная` (к выдаче) `= Окр(СуммаБезНДС × (1 − ПроцентОтеля/100))` 🟢.
5. Σ `СуммаПрачечная` попадает в зарплату (поле `СуммаПрачечная_И`) 🟢.

## Основной поток — обмен справочниками `Горничные` (`Catalog.Горничные.ObjectModule`)

1. `ПередЗаписью`: если `ОбменДанными.Загрузка` или новый объект — выход (флаг `ПроверкаОбмена=Ложь`) 🟢.
2. Если `ГорничнаяГУИДСтрока` пуст — присвоить `Строка(Ссылка.УникальныйИдентификатор())`, `ПроверкаОбмена=Истина` 🟢.
3. Иначе `ПроверкаОбмена()`: только при `УчетУборок=Истина` и изменении одного из {Наименование, Сортировка, НеРаботает, ПометкаУдаления, УчетУборок} 🟢.
4. `ПриЗаписи`: если `ПроверкаОбмена` — `ОбновитьГорничнаяГорничные(ЭтотОбъект)`; при ошибке (возврат Истина) — сообщение «НЕ выгружена» 🟢.

## Альтернативные потоки

- **Обмен выключен (`ОбменСГорничными=Ложь`):** все процедуры обмена сразу возвращают управление; данные не трогаются 🟢.
- **COM недоступна:** `Соединение()` возвращает `Неопределено` → сообщение «Нет связи…» и выход; ошибки COM в `Попытка` часто подавляются 🟢.
- **Документ помечен `РучноеИзменение`:** загрузка пропускает его 🟢.
- **Запись из обмена (`ОбменДанными.Загрузка=Истина`):** обратная выгрузка не выполняется (разрыв эха) 🟢.
- **Горничная не найдена при загрузке:** авто-создаётся по наименованию 🟢.
- **Номер/номенклатура не найдены:** сообщение оператору; строка пропускается / цена = 0 🟢.
- **Отпуск пересекает границы периода:** 4 ветви расчёта расчётных дней 🟢 (см. `edge-cases.md`).

## Зависимости

- `Константа.ОбменСГорничными` — тумблер всего обмена 🟢.
- `Константа.Папка_Горничные` — путь к файловой БД горничных 🟢.
- `SessionParameter.СоединениеГорничнныеАдресВХранилище` — кэш COM-соединения 🟢.
- Модуль «Бронирование» — вызывает `СоздатьЗаявку` при проведении/изменении брони 🟢.
- Модуль «Размещение» — `Catalog.НомернойФонд.НомерГорничные` (связка номеров); зеркалирование карточки номера описано там 🟢.
- Модуль «Минибар» — `Catalog.НоменклатураМиниБара` в ТЧ уборки 🟢.
- Модуль «Финансы» — `СтавкаНДС` (источник числа НДС не разобран 🔴), учёт выплат.
- `НастройкиСервер.Это*()` — профиль отеля, управляет UI зарплаты 🟡.

## Внутреннее состояние

- COM-соединение: структура `{Соединение}` во временном хранилище, адрес — в `ПараметрыСеанса.СоединениеГорничнныеАдресВХранилище`; при разрыве адрес сбрасывается и переподключается 🟢.
- Документы уборки идемпотентны по бизнес-ключу (Дата + пп + НомерГорничные / Горничная) — повторная загрузка обновляет существующие 🟢.
- РС `УборкиНомеров` подчинён регистратору (`ГорничныеОбслуживаниеНомера`); запись управляется проведением документа 🟢.

## Наблюдаемость

- Ошибки обмена сообщаются оператору через `Сообщить(...)` (нет структурированного журнала) 🟢.
- Закомментированные вызовы `ОбщийМодульСлужебныеСервер.ВЛог(...)` — журналирование заданий было отключено 🟢 (`СоздатьЗаявку` 109-115).

## Риски и пробелы

- 🔴 Хардкод COM-учётки `Pwd="123"`, `Usr="Соединение"` в `Соединение()` (22) — утечка секрета.
- 🔴 Баг: клиентский `КоличествоЧасовНаКлиенте` использует `* 8` вместо `Горничная.ДлинаСмены` (847-853) — расхождение клиент/сервер.
- 🔴 Источник `СтавкаНДСЧисло` для прачечной не разобран (вероятно настройка финмодуля).
- 🔴 Печатные формы `ГорничныеОбщийКвиток` и 4 отчёта не разобраны.
- 🔴 Опечатка в имени реквизита `ВремяУброки` (РС УборкиНомеров) — несогласована с `ВремяУборки` документа.
- 🔴 Дубли в `CommonModule.ГорничныеЗарплата` (`..._1/_2`) и устаревший `ГорничныеОбслуживаниеПомещения_Старый` — мёртвый/дублирующий код.
- 🟡 Подавление ошибок пустыми `Попытка` (загрузка ТЗ 130-136) маскирует сбои обмена.
- 🟡 Параметры `ЗагрузитьОбслуживаниеПомещений`/`ЗагрузитьСмены` выведены по аналогии, не прочитаны построчно.
