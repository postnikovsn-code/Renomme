## CRITICAL

### C1. МинибарРасход: двойное списание партий при каждом перепроведении
`Documents\МинибарРасход\ObjectModule.bsl:19, 79–94`
`ПартииОстатки()` читает `РегистрНакопления.МинибарПартии.Остатки(Граница(ДатаРасхода, Включая))` внутри `ОбработкаПроведения` — старые движения этого же документа ещё в регистре. Компенсация вычитает только текущий набор `Движения.МинибарПартии`, не старые записи БД. Каждое перепроведение списывает те же количества из следующих партий: партионные остатки дрейфуют в минус, себестоимость обнуляется. Блокировок нет, `Регистратор <> Ссылка` не исключается.

### C2. КоворкингСчета: оплата услуг вычитается из долга дважды
`Documents\КоворкингСчета\ObjectModule.bsl:76-78`
`ПередЗаписью` пересчитывает шапочную `СуммаОплачено` итогом **всех** строк `РаспределениеОплатКоворкинг` без отбора `ЭтоУслуга = Ложь`, тогда как вся остальная логика (`КоворкингСервер:711-789`) трактует её как оплату только тела счёта (услуги — отдельно в `ДопУслугиКоворкинг.СуммаОплачено`). После записи счёта с оплаченными услугами `СуммаКОплате` занижена — частично оплаченный счёт выглядит закрытым. Противоречит DK-05 документации.

### C3. КоворкингСервер: возврат оплаты — удаление строк не из той ТЧ + неверный остаток
`CommonModules\КоворкингСервер\Module.bsl:23, 33`
`ОбщийФункционалСервер.УдалитьСтроки(ДокументыОплаты, НайденныеСтрокРаспределениеОплатКоворкинг)` — передана не та таблица (copy-paste со стр. 21) → ошибка времени выполнения **внутри транзакции без Попытка/ОтменитьТранзакцию**. Там же: `ОстатокСуммаВозврата = СуммаВозврата − Строка.СуммаОплаты` каждый раз от исходной суммы, а не от остатка — при 2+ строках остаток неверен.

### C4. ФинРезультат коворкинга: оплаты задваиваются при разнесении по дням
`DataProcessors\ФинансовыйРезультатКоворкинг_Расширенный\ManagerModule.bsl:481-503`
`ОстатокСуммаОплаты` сбрасывается на полную сумму оплаты на **каждый день** аренды и уменьшение не сохраняется в `СтрокаОплата`. Счёт 10 дней × 10₽ с оплатой 50₽ разносит 100₽ оплат. Итоги дня/периода завышены всегда, когда оплата ≠ сумме счёта.

### C5. ЛистОжидания: «Перевести в бронь» падает, заявка уже помечена на удаление
`Documents\ЛистОжидания\Forms\ФормаДокумента\Module.bsl:114-117, 145`
Клиент обращается к `Объект.НомерВРезерв` — такого реквизита у документа нет (по .mdo) → «Поле объекта не обнаружено». Найденный сервером номер игнорируется. Хуже: `УстановитьПометкуУдаления(Истина)` выполняется **до** создания брони — при сбое запись листа ожидания теряется.

### C6. ОбменБухгалтерияНДС: ставка НДС в выгрузке = 0 почти для всех типов счетов
`CommonModules\ОбменБухгалтерияНДС\Module.bsl:335` (и 395, 507, 565, 623, 687, 752, 819)
`СтавкаНДСЧислоТекущий = ДокументыСервер.СтавкаНДСЧисло(СтавкаНДСЧислоТекущий)` — функция вызвана от собственного (числового) результата, а она сравнивает аргумент только с `Перечисления.СтавкиНДС.*` → возвращает 0. Корректен только первый блок «ФС» (:256). Типы ЮС, ЮГ, ТСГ, ТСП, ТСФ, «???», ФКС, ЮКС уходят в бухгалтерию со `СтавкаНДС = 0` при ненулевой `СуммаНДС`. Ошибка тихая.

### Ценообразование и турналог

**H12. Две версии расчёта турналога расходятся: 1% vs 2%** — `DataProcessors\РасчетТурНалога1\Forms\Форма\Module.bsl:747+` vs `РасчетТурНалога\...:243, 398-406`
`РасчетТурНалога` параметризует ставку (`Год < 2026 → 1%, иначе 2%`), `РасчетТурНалога1` жёстко делит на 101 → для 2026 года занижение налога вдвое. В интерфейс подключена только первая, но вторая доступна через «Все функции» и не помечена устаревшей. «Детальные» процедуры в **обеих** тоже жёстко /101. Дополнительно ставка «заморожена» на 2% для 2027+ (по НК РФ растёт ежегодно).

**H13. Турагентские брони через границу месяца выпадают из налога совсем** — `РасчетТурНалога\...:378-387` (идентично в `...1:882-891`)
Для турагентств нижняя граница проверяется по `ДатаСМинимум`, верхняя — по `ДатаПоМаксимум`: бронь 28.01–03.02 отсекается и в январе, и в феврале. Начисление теряется навсегда.

**H14. Итоги формы турналога всегда 0** — обе обработки, `:13-18`
Итоги считаются по `ТурНалогДетально`, а активный расчёт заполняет `ТурНалогЗаявки`; процедура, заполняющая `ТурНалогДетально`, не привязана ни к одной команде формы.

**H15. Каскад цен «База → Долгосрочная → Текущая» нарушен** — `CommonModules\КалендарьЦен\Module.bsl:161-201`
При наличии «Текущей» записи компоненты, не затронутые ею, берутся из **базовых** значений, минуя долгосрочные правки. Долгосрочное повышение цены исчезает при любой текущей корректировке другого компонента. Противоречит PR-01.

**H16. Однонощная бронь теряет надбавку за поздний выезд** — `CommonModules\ДокументыСервер\Module.bsl:481-504`
Первый и последний день — взаимоисключающие ветки `Если/ИначеЕсли`; для одной ночи применяется только коэффициент заезда, доплата за поздний выезд (+0.5/+1.0 суток) не начисляется. Компенсация в форме заявки (`:1984-2011`) срабатывает не во всех путях. Найдено независимо двумя аудитами.

### Бронирование

- **M5.** `ДатаСДатаПо`: решение о `+86400` по старым датам счёта — день выезда теряется при превращении суточного счёта в многодневный. `ЗаявкаСервер:891-893, 921-923`.

- **M7.** Удаление связи «оплата-счёт» чистит распределение по всем счетам заявки, а `ДолгиОплата` — только по одному счёту → рассинхрон. `БезналРаспределение:2273-2286` + `ЗаявкаСервер:1192-1202` + `ОплатыОбщееСервер:271-287`.

- **M10.** ФинансовыйРезультат vs ФинансовыйРезультатОтель: разные фильтры дат услуг, учёт `СуммаАннулировано`, отборы статусов/ремонтов — один показатель считается по-разному (Q-06 доков).

## Сквозные паттерны (источники будущих багов)

1. **Чтение остатков/срезов до записи движений** при перепроведении без исключения собственного регистратора и без блокировок — минибар (C1, H10), инвентаризации (M20). Проверить тот же паттерн в `DataProcessor.Минибар` и контуре себестоимости.
2. **Транзакции без Попытка/ОтменитьТранзакцию** — 85 vs 30 по src (H6).
3. **Copy-paste-вилки версий** (`РасчетТурНалога/1`, `ФинансовыйРезультат/Отель/_Расширенный`, `АдминистраторыЗарплата/_Версия`, `ЗаявкаСервер/_1`, `БезналРаспределение/_Старое`) с расходящимися формулами; живая версия не всегда очевидна.

6. **Конструктор `Новый Структура` с несогласованными ключами/значениями** — H1, M35.
