## Основной поток (расчёт)

1. Ввод периода `ДН`/`ДК` в шапке документа. 🟢
2. `ЗаполнитьСправочныеДанные` — выгрузка администраторов (без пометки удаления и без `НеРаботает`), для каждого выбор актуальной строки ТЧ `Начисления` (`ДатаУстановки ≤ ДК`, последняя). `:280-337` 🟢
3. `ЗаполнитьСправочныеДанныеПоДНиДКНаСервере` — загрузка шкал стажа и проживающих на последнюю `ДатаНазначения ≤ ДК`. `:382-445` 🟢
4. `ЗаполнитьПроживающие` — запрос броней (Проживает/Выехал), агрегирование `КоличествоНомеров` по каждому дню периода. `:1187-1303` 🟢
5. Ветвление по имени отеля → загрузка заселений/завтраков из внешних баз: «Реноме»→`ЗагрузитьЗаселенияЛайв_HTTP`; «Чехов»→`ЗагрузитьЗаселенияДомСоветов_HTTP` + `ЗагрузитьЗаселенияСтритАрт_HTTP`. `:347-376` 🟢
6. `ЗаполнитьЗарплатаСмены` — построение посуточной матрицы; каждый день кодируется строкой `Часы_ddMMyy = "ДлинаСмены-НомерСмены/Переработка"`. `:2769-2791` 🟢
7. `РасчитатьЗарплатуНаСервере` — внешний цикл по строкам `ЗарплатаСмены` (= администратор), внутренний по дням `[ДН;ДК]`:
   - `РасчитатьСтрокаЗарплатаСменыСмена` для каждого дня (оклад за смену, переработка, проживающие, заселения, завтраки);
   - агрегация по дням (`ОбновитьСтрокаЗарплатыСменаИзДат`);
   - `РасчитатьНадбавки` (стаж/стандарты/инязыки);
   - если `Администратор.Постоянный` → `РасчитатьПостоянный`;
   - `РасчитатьПрочее`;
   - `ОбновитьСтрокаЗарплатаСменыОсновные_Э` (эффективные значения И/_Р/_Есть);
   - `ОбновитьЗарплатаСменыИтоги` (ИтогоСмены/Итого/КВыплате). `:2449-2480` 🟢
8. Запись: `ПередЗаписью` отклоняет пустые ДН/ДК, ставит режим «Проведение», вызывает `ЗаполнитьПередЗаписью`, который разворачивает `*_ddMMyy` в ТЧ. Движений регистров нет. `:2123-2353` 🟢

## Альтернативные потоки

- **Постоянный администратор:** оклад/проживающие считаются не по сменам, а пропорционально `КоличествоРасчетныхДней / ДнейМесяца` (BR-05/06/07); смены ограничены `{0,3,4}`. 🟢
- **Смена 4 без длины:** `ДлинаСмены` принудительно = 8. 🟢 (`:2600`)
- **Пустая ДатаПриема или `НеНачислятьЗаСтаж`:** надбавка за стаж = 0, остальной расчёт продолжается. 🟢 (`:2560`)
- **Длина смены > 24:** оклад за смену = полная `СтавкаЗаСмену24` без пропорции. 🟢 (`:2866`)
- **Пустая шкала проживающих / номер вне бэндов:** доплата за проживающих = 0. 🟢 (`ManagerModule.bsl:54`)
- **Имя отеля не «Реноме»/«Чехов»:** внешние заселения не загружаются; матрица строится только из ручных/расчётных данных. 🟢 (`:347-376`)
- **Заселения/завтраки (количества):** эффективное значение `_Э = И + _Р` (ручное — дельта). 🟢 (`:2055-2071`)

## Зависимости

- **Бронирование / Ценообразование** — источник «проживающих» и числа номеров по дням (`ОтчетыСервер.ТЗ_Проживание*`, статусы Проживает/Выехал). 🟢
- **Интеграции и обмен** — `ЗагрузитьЗаселения{Лайв,ДомСоветов,СтритАрт}_HTTP` из внешних баз сети. 🟢
- **Общий слой** — `ОбщийФункционалСервер.ЗначениеРеквизитаНаСервере`, `СтруктураИзТаблицы`. 🟢
- **Справочник `Должности`/`ТипыДолжностей`** — атрибут карточки администратора. 🟢
- **Горничные** (только концептуально) — общий паттерн «сдельная ЗП + надбавка за стаж + тройка И/_Р/_Есть»; код независим. 🟡

## Внутреннее состояние

Состояние расчёта живёт в реквизитах формы документа:
- **Динамические `<Показатель>_ddMMyy`** — по каждому дню периода (`НомерСмены_ddMMyy`, `Оклад_ddMMyy`, `Часы_ddMMyy`, `СуммаЗавтракиЛайв_ddMMyy`, …, ~30+ имён). Генерируются по дате формата `ДФ=dd.MM.yy` без точек; в `.mdo` не объявлены. 🔴 (не каталогизированы поимённо)
- **ТЧ-формы `ЗарплатаСмены`** (по администратору, в памяти формы) и итоговая `Зарплата`. 🟢
- При записи состояние материализуется в ТЧ объекта `Зарплата` (итог по администратору) и `ЗарплатаСмены` (по дням, пустые дни пропускаются через `Перейти ~ПРОДОЛЖИТЬ_ДАТА`). 🟢
- История ставок — в ТЧ `Начисления` справочника `Администраторы` по `ДатаУстановки` (выбор актуальной на ≤ДК). 🟢

## Наблюдаемость

Специальной телеметрии/логирования в модуле не обнаружено; пользовательская обратная связь — через `Предупреждение` при невалидном `НомерСмены` (`:2600`). 🟡

## Риски и пробелы

- 🔴 Динамические реквизиты `*_ddMMyy` (~30+) не перечислены в `.mdo` — генерируются по дате; затрудняют типизацию и рефакторинг (ADR-0011).
- 🔴 Расчёт отпускных (`Отпуск`/`Отпуск_Р`, `СтавкаЗаОтпуск`) построчно не локализован — место начисления в `РасчитатьЗарплату*` не определено однозначно.
- 🔴 Деление суммы за проживающих между администраторами смены закомментировано (`:2966-2973`) — текущее поведение отдаёт всю сумму одной строке.
- 🟡 РС `АдминистраторыТабель` объявлен, но в расчёте не используется (мёртвая/будущая интеграция).
- 🟡 Дубли-версии (`Администраторы_Версия`, `АдминистраторыЗарплата_Версия` 4012 строк, `…СуммаЗаПроживающих_Версия`, `…СуммаЗаЗавтраки_Версия`) и `DataProcessor.АдминистраторыТабель_НеИспользуется` — техдолг, не переносить.
- 🟡 Расхождения клиент/сервер в смежных формулах (напр. `КоличествоЧасовНаКлиенте` использует `*8` вместо `ДлинаСмены`) — известный паттерн-баг.
- 🟡 Семантика `НомерСмены` 1=день/2=ночь выведена из валидаций и `ДатаВремяСмена`, не из явной документации.
