# Персонал и зарплата (администраторы), Крайние случаи

> Файл `edge-cases.md` (doc_level=detalhado). Краевые ситуации расчёта ЗП администраторов, извлечённые из легаси. Уверенность: 🟢/🟡/🔴.

## EC-01. Отпуск пересекает расчётный период

- **Условие:** в дни периода есть смены с `НомерСмены=3` (отпускной день).
- **Поведение легаси:** `КоличествоРасчетныхДней = (ДК−ДН+1) − ДниОтпуска`, где `ДниОтпуска` — количество дней со сменой 3. Эти дни исключаются из пропорции оклада и надбавок постоянного. Сам отпускной начисляется отдельно (`СтавкаЗаОтпуск`), но место начисления не локализовано (🔴).
- **Источник:** `Forms/ФормаДокумента/Module.bsl:2506` (`КоличествоРасчетныхДней`), `:2491` (`РасчитатьПостоянный`).
- **Ожидаемый результат:** период 01.06–30.06, 3 дня отпуска → расчётных дней 27; оклад = `Окр(СуммаОклад × 27/30)`. 🟢
- **Граница:** весь период — отпуск → расчётных дней 0 → оклад/надбавки постоянного = 0; отпускные считаются отдельно. 🟡

## EC-02. Ручная корректировка через флаг _Есть (замена vs дельта)

- **Условие:** оператор заполняет `<Показатель>_Р` и ставит `<Показатель>_Есть = Истина`.
- **Поведение легаси:** для большинства показателей `_Э = _Р` (ручное **заменяет** расчётное И). Для **количеств заселений/завтраков** правило иное: `_Э = И + _Р` (ручное — **дельта** к расчётному).
- **Источник:** `Module.bsl:2011` (замена) и `:2055-2071` (дельта).
- **Ожидаемый результат (замена):** И=0, _Р=5000, _Есть=Истина → _Э=5000. 🟢
- **Ожидаемый результат (дельта):** заселений И=10, _Р=2, _Есть=Истина → _Э=12. 🟢
- **Ловушка:** ожидать «замену» там, где действует «дельта» — частая ошибка при рефакторинге. 🟢

## EC-03. Пустая ДатаПриема → надбавка за стаж = 0

- **Условие:** у карточки администратора `ДатаПриема` пуста ИЛИ `НеНачислятьЗаСтаж = Истина`.
- **Поведение легаси:** функция надбавки за стаж сразу возвращает 0, не обращаясь к шкале РС.
- **Источник:** `Module.bsl:2560`.
- **Ожидаемый результат:** надбавка за стаж = 0, остальной расчёт (оклад, прочие надбавки) выполняется нормально. 🟢
- **Граница:** `РазницаВДнях` вне всех бэндов шкалы → также 0 (бэнд не найден). 🟢

## EC-04. Смена 12 часов vs 24 часа (и длина вне ступеней)

- **Условие:** длина смены попадает на границы ступеней оклада.
- **Поведение легаси (`ОкладЗаСмену:2866`):**
  - `ДлС=0` → 0;
  - `ДлС≤12` → `Окр(Ст12 × ДлС/12)` (12 ч → полная Ст12);
  - `12<ДлС≤24` → `Окр(Ст24 × ДлС/24)` (24 ч → полная Ст24);
  - `ДлС>24` → `Ст24` (полная, без пропорции — переработка считается отдельно).
- **Ожидаемый результат:** Ст12=2400, ДлС=12 → 2400; Ст24=4000, ДлС=18 → `Окр(4000×18/24)=3000`; ДлС=26 → 4000. 🟢
- **Доплата за проживающих той же смены** также зависит от порога 12: `ДлС≤12 → Сумма_12`, иначе `Сумма_24` (`ManagerModule.bsl:54`). 🟢
- **Ловушка:** граница «ровно 12» относится к первой ветви (Сумма_12 / Ст12), «ровно 24» — ко второй (Ст24 × 24/24 = Ст24). 🟢

## EC-05. Имя отеля вне «Реноме»/«Чехов»

- **Условие:** база развёрнута под отелем, не входящим в хардкод.
- **Поведение легаси:** ни одна `Загрузить*_HTTP` не вызывается; матрица строится без внешних заселений/завтраков (остаются ручные/расчётные данные).
- **Источник:** `Module.bsl:347-376`.
- **Ожидаемый результат:** расчёт не падает; суммы заселений/завтраков = ручной ввод или 0. 🟢
- **Риск:** добавление нового отеля требует правки кода (хардкод, ADR-0008). 🟡

## EC-06. Документ не проводится по регистрам — отчётность из ТЧ

- **Условие:** требуется отчёт/сверка по начисленной ЗП.
- **Поведение легаси:** движений регистров нет; данные читаются прямым запросом к ТЧ `Зарплата`/`ЗарплатаСмены` документа.
- **Источник:** `.mdo` (нет регистровых движений), `Module.bsl:2123-2353`.
- **Следствие:** нет «единого источника правды» для бух-движений; при удалении/перезаписи документа аналитика меняется немедленно. 🟡
