# Персонал и зарплата (администраторы)

> ⚠️ **Повторное извлечение №2 (2026-08-21-ПСН-РЕНОМЕ, собственная ветка ПСН «Реноме»):** дельта спецификаций этого unit — в [../re-extraction/2026-08-21-ПСН-РЕНОМЕ/specs-delta.md](../re-extraction/2026-08-21-ПСН-РЕНОМЕ/specs-delta.md) §7. **Приоритет:** эта дельта старше дельты №1 (2026-06-18) и канона.

> Файл `requirements.md` — ЧТО делает модуль, а не как. Уверенность каждого утверждения: 🟢 ПОДТВЕРЖДЕНО кодом, 🟡 ВЫВЕДЕНО, 🔴 ПРОБЕЛ.
> Зарплата **горничных** — отдельный модуль «Горничные»; здесь только администраторы стойки (ресепшн). Связь с ним описана, логика — нет.

## Обзор

Модуль ведёт кадровый учёт администраторов ресепшн (карточка сотрудника, должность, ставки/оклады по истории дат) и рассчитывает их заработную плату за календарный период [ДН;ДК]. Расчёт посуточный: для каждого дня периода фиксируется смена (длина, тип, переработка), из которой выводятся оклад за смену, доплаты за проживающих/заселения/завтраки; сверху начисляются надбавки (стаж, стандарты, иностранные языки), отпуск, больничный, премия; вычитаются авансы и выплаты — получается «к выплате». Документ-носитель расчёта **не проводится по регистрам** — все данные остаются в его табличных частях. 🟢

## Ответственности

- Хранить карточки администраторов и историю их ставок/окладов/надбавок по `ДатаУстановки` (ТЧ `Начисления`). 🟢
- Хранить справочники `Должности` (иерархия 2 уровня, тип должности, порядок) и `ТипыДолжностей`. 🟢
- Хранить конфигурируемые шкалы: надбавка за стаж по диапазонам отработанных дней (РС `АдминистраторыНадбавкаЗаСтаж`) и доплата за проживающих по числу занятых номеров × длине смены (РС `АдминистраторыСуммаЗаПроживающих`). 🟢
- Рассчитывать ЗП администратора за период: посуточно по сменам (сдельный) либо по окладу (постоянный), с надбавками, доплатами, выплатами и итогом «к выплате». 🟢
- Поддерживать ручную корректировку любого расчётного показателя (паттерн «тройка» И/_Р/_Есть). 🟢
- Денормализовать посуточную матрицу показателей в динамических реквизитах формы `<Показатель>_ddMMyy` и при записи разворачивать её в строки ТЧ `Зарплата`/`ЗарплатаСмены`. 🟢
- Подтягивать число занятых номеров по дням периода (источник для доплаты за проживающих) и заселения/завтраки из внешних баз сети по имени отеля. 🟢

## Бизнес-правила

- BR-01. Администратор исключается из расчёта, если у карточки `ПометкаУдаления=Истина` ИЛИ `НеРаботает=Истина`. 🟢 (`Forms/ФормаДокумента/Module.bsl:280-337`)
- BR-02. Актуальные ставки берутся из последней строки ТЧ `Начисления` с `ДатаУстановки ≤ ДК` (сортировка по убыванию). 🟢 (`:280-337`)
- BR-03. Шкалы стажа и проживающих загружаются на последнюю `ДатаНазначения ≤ ДК`. 🟢 (`:382-445`)
- BR-04. Оклад за смену (сдельный): `ДлС=0 → 0`; `ДлС≤12 → Окр(Ст12 × ДлС/12)`; `12<ДлС≤24 → Окр(Ст24 × ДлС/24)`; `ДлС>24 → Ст24` (полная без пропорции). 🟢 (`ОкладЗаСмену:2866`)
- BR-05. Оклад постоянного: `Окр(СуммаОклад × РасчётныеДни / ДнейМесяца)`, где `ДнейМесяца = День(КонецМесяца(ДН))`. 🟢 (`РасчитатьПостоянный:2491`)
- BR-06. Расчётные дни постоянного: `(ДК−ДН+1) − ДниОтпуска`, где день отпуска — день со сменой `НомерСмены=3`. 🟢 (`КоличествоРасчетныхДней:2506`)
- BR-07. Надбавка за проживающих постоянного: `Окр(НадбавкаЗаПроживающих × РасчётныеДни / ДнейМесяца)`. 🟢 (`:2491`)
- BR-08. Надбавка за стаж: `0`, если `ДатаПриема` пуста ИЛИ `НеНачислятьЗаСтаж=Истина`; иначе бэнд из РС по `РазницаВДнях = ДК − ДатаПриема` (`РазницаВДняхС ≤ РазницаВДнях < РазницаВДняхПо`) → `Сумма × РасчётныеДни / ДнейМесяца`, округлённо. 🟢 (`:2560`)
- BR-09. Надбавки за стандарты и инязыки: `Справочник.Надбавка × (ДК−ДН+1) / ДнейМесяца`, округлённо. 🟢 (`:2533`, `:2547`)
- BR-10. Доплата за проживающих за смену: бэнд из РС по `КоличествоНомеров` (`КоличествоНомеровС ≤ Кол < КоличествоНомеровПо`) → `Сумма_12` при `ДлС≤12`, иначе `Сумма_24`; пустая шкала → 0. 🟢 (`ManagerModule.bsl:54`)
- BR-11. Эффективное значение показателя (тройка): `_Э = _Р`, если `_Есть=Истина`, иначе `_Э = И` (ручное **заменяет** расчётное). 🟢 (`ОбновитьСтрокаЗарплатаСменыОсновные_Э:2011`)
- BR-12. Исключение для количеств заселений/завтраков: `_Э = И + _Р` (ручное — **дельта**, а не замена). 🟢 (`:2055-2071`)
- BR-13. Валидация `НомерСмены`: для постоянного допустимы `{0,3,4}`, для сдельного `{0,1,2,3}`; иначе предупреждение и откат к прежнему значению. 🟢 (`НомерСмены_ПриИзменении:2600`)
- BR-14. При `НомерСмены=4` и `ДлинаСмены=0` длина смены принудительно ставится 8. 🟢 (`:2600`)
- BR-15. Старт смены: дневная (НомерСмены=1) — 09:00, ночная (2) — 21:00. 🟢 знач. времени (`ManagerModule.ДатаВремяСмена`); 🟡 привязка 1=день/2=ночь выведена.
- BR-16. Итого смены = `Оклад_Э + Переработка_Э + Проживающие_Э + Заселения_Э(3 сети) + Завтраки_Э(3 сети)`. 🟢 (`ОбновитьЗарплатаСменыИтоги:2076`)
- BR-17. Итого ЗП = `ИтогоСмены + Стаж_Э + Стандарты_Э + ИнЯзыки_Э + Отпуск_Э + Больничный + Премия + ДопУслуги + СуммаПрочее`. 🟢 (`:2087`)
- BR-18. К выплате = `ИтогоЗП − (АвансНал + АвансКарта + ОтпускныеКарта + ЗПКарта + ИныеВыплатыНал + ИныеВыплатыКарта)`. 🟢 (`:2098-2100`)
- BR-19. Источник заселений ветвится по имени отеля: «Реноме» → Лайв; «Чехов» → ДомСоветов + СтритАрт; иначе пропуск. 🟢 хардкод (`:347-376`)
- BR-20. Запись запрещена, если `ДН` или `ДК` пусты; иначе режим записи — «Проведение», и `*_ddMMyy` разворачиваются в ТЧ; движений регистров нет. 🟢 (`ПередЗаписью:2123`, `ЗаполнитьПередЗаписью:2136-2353`)
- BR-21. Деление суммы за проживающих между администраторами смены закомментировано — сейчас вся сумма идёт одной строке. 🔴 (`:2966-2973`)
- BR-22. Точное место и формула начисления отпускных (`Отпуск`/`Отпуск_Р`, `СтавкаЗаОтпуск`) однозначно не локализованы. 🔴
- BR-23. РС `АдминистраторыТабель` (Администратор×Дата→Часы) не участвует в расчёте — смены вводятся вручную в форме. 🟡 (объявлен, в коде расчёта не вызывается)

## Критерии приёмки

```gherkin
Scenario: Оклад сдельного администратора за смену 24 часа
  Дано администратор НЕ постоянный со СтавкаЗаСмену24 = 4000 на актуальную ДатаУстановки
  Когда рассчитывается оклад за смену длиной 24 часа
  Тогда оклад за смену равен 4000 (полная ставка, без пропорции)

Scenario: Оклад сдельного администратора за неполную смену
  Дано администратор со СтавкаЗаСмену12 = 2400
  Когда рассчитывается оклад за смену длиной 6 часов
  Тогда оклад равен Окр(2400 × 6/12) = 1200

Scenario: Оклад постоянного за период с отпуском
  Дано постоянный администратор с СуммаОклад = 60000, период 01.06–30.06 (ДнейМесяца=30)
    И один день периода имеет НомерСмены=3 (отпуск)
  Когда рассчитывается оклад постоянного
  Тогда РасчётныеДни = 30 − 1 = 29 и Оклад = Окр(60000 × 29/30) = 58000

Scenario: Ручная корректировка через флаг _Есть
  Дано рассчитанная Премия (И) = 0 и оператор ввёл Премия_Р = 5000 с Премия_Есть = Истина
  Когда вычисляется эффективное значение
  Тогда Премия_Э = 5000 (ручное заменяет расчётное)

Scenario: Надбавка за стаж при пустой дате приёма
  Дано у администратора ДатаПриема пуста
  Когда рассчитывается надбавка за стаж
  Тогда надбавка за стаж = 0

Scenario (failure): Запись документа с пустым периодом
  Дано документ зарплаты с пустым ДН или ДК
  Когда пользователь пытается записать документ
  Тогда запись отклоняется (отказ в ПередЗаписью)

Scenario (failure): Недопустимый номер смены для постоянного
  Дано постоянный администратор
  Когда оператор вводит НомерСмены = 1 в ячейку дня
  Тогда выводится предупреждение «д.б. 0 или 3 или 4» и значение откатывается
```

## Приоритизация (MoSCoW)

| Требование | MoSCoW | Обоснование |
|-----------|--------|-------------|
| Расчёт ЗП по сменам/окладу + итоги (RF-05/06/13) | Must | Критический путь, ядро модуля |
| Тройка И/_Р/_Есть и дельта заселений (RF-08) | Must | Бизнес-правило без fallback, влияет на все суммы |
| Надбавки и доплаты по шкалам (RF-03/04/07) | Must | Прямо входят в итог ЗП |
| Подтягивание проживающих (RF-09) | Must | Знаменатель доплаты за проживающих |
| Внешние базы заселений/завтраков (RF-10) | Should | Ветвление по отелю; при недоступности расчёт идёт без них |
| Справочник должностей/типов (RF-02) | Should | Справочный, не блокирует расчёт |
| Деление суммы за проживающих между сменами (BR-21) | Won't | Закомментировано в легаси |
| РС `АдминистраторыТабель` в расчёте (BR-23) | Won't | Объявлен, но не используется (мёртвая/будущая интеграция) |
| Дубли-версии `*_Версия`, `АдминистраторыТабель_НеИспользуется` | Won't | Техдолг, не переносить |

> Приоритет выведен по частоте вызова, позиции в цепочке расчёта и наличию/отсутствию fallback.
