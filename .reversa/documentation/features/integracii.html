Интеграции и обмен

Как устроена фича · модуль «Интеграции и обмен» 25 520 строк сложность: высокая

Модуль реализует транспортный и протокольный слой внешних интеграций и синхронизации данных: планы обмена между базами сети (XML плюс FTP), обмен с сайтом бронирования (HTTPS JSON), HTTP-сервисы заселений и ежедневного отчёта, выгрузку в Бухгалтерию/НДС, мессенджеры WhatsApp/Telegram через Green API, эквайринг PayKeeper и COM-обмен картинками с планшетом.

Назначение

Обеспечивает узловой обмен между базами сети (XML плюс FTP-транспорт) и обмен с сайтом бронирования по HTTPS JSON.

Диспетчеризует мессенджер-рассылки через Green API и интеграцию эквайринга PayKeeper с привязкой платежей к долгам.

Связывает отдельные базы 1С (горничные, картинки, бонусы) синхронным COM-обменом с кэшем соединения и ретраями.

Бизнес-правила

  • IN-01Узловой обмен 1С: коды ошибок 1 и 30 трактуются как «нет нового сообщения» (не фатальны).
  • IN-02Транспорт планов обмена — временный XML плюс доставка через FTP (порт 21, пассивный режим).
  • IN-03Нормализация телефона: отбрасывает не-цифры; 8… в 7…; 10 цифр в 7 плюс номер; иначе 0 (невалидно). chatId = <номер>@c.us.
  • IN-04Мессенджер-рассылка идемпотентна через РС (ключ Клиент плюс ДатаРассылки плюс ТипРассылки); рассылка «Сайт» — выехавшим вчера гостям.
  • IN-05PayKeeper: токен кэшируется с TTL 1200 сек, ленивое обновление; аутентификация Basic плюс token в теле.
  • IN-06PayKeeper: статус success — автоматическая привязка платежа к документу долга/оплаты.
  • IN-07Обмен с горничными/картинками/бонусами — отдельные базы 1С через COM, кэш соединения в параметре сеанса, до 3 попыток.

Крайние случаи

  • Боевые секреты в исходниках: FTP-креды, Telegram ApiToken, COM-пароль картинок. Не воспроизводить, выносить в защищённое хранилище 🔴.
  • XDTO-схемы обмена и фискального контура не разобраны — без них сериализация невоспроизводима.
  • План ВГ_ВыпискаГостиницы имеет пустой состав — обмен идёт вручную, минуя выборку изменений.
  • Повторная привязка PayKeeper для уже привязанного success-платежа — идемпотентность под вопросом (риск двойной привязки к долгу).

Открытые вопросы

  • 🔴 S-01Боевые FTP-креды в комментарии исходника — вынести, ротировать, вычистить из истории VCS.
  • 🔴 S-02Green API Telegram ApiToken и idInstance в комментарии — перенести в константы, перевыпустить токен.
  • 🔴 S-03Хардкод COM-пароля Pwd="123" для базы картинок планшета.
  • 🔴 G-01XDTO-схемы обмена (Cashbox, ExchangeMessage) не разобраны — без них обмен не воспроизвести.
  • 🔴 G-02Пустой состав плана ВГ_ВыпискаГостиницы — проектное решение или утрата состава.
  • 🟡 Q-06Повторная привязка PayKeeper для success-платежа — идемпотентна ли, риск двойной привязки.
