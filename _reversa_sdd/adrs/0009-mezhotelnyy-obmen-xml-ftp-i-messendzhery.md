# ADR 0009 — Межотельный обмен (план обмена XML+FTP) и рассылки через Green API

- **Статус:** Принято (исторически) · 🟢 ПОДТВЕРЖДЕНО кодом
- **Дата:** неизвестна
- **Модуль:** Интеграции и обмен

## Контекст

Между базами сети нужно реплицировать данные (выписки, регистры); гостям нужны автоматические сообщения (подтверждения, рассылки выехавшим) в WhatsApp/Telegram. Транспорт должен работать через интернет между разнесёнными базами.

Свидетельства:
- Планы обмена `ОбменГостиницы`, `ВГ_ВыпискаГостиницы`, `ОбменТест` используют стандартный механизм платформы (`СоздатьЗаписьСообщения/ВыбратьИзменения`), доставка — временный XML + FTP (`ФТПСервер`, порт 21, пассивный, IN-02). 🟢
- Коды ошибок 1/30 трактуются как «нет нового сообщения» (IN-01). 🟢
- Рассылки: `МесенджерСервер` → адаптеры `WhatsAppСервер`/`TelegramСервер` → Green API (REST `api.green-api.com`); нормализация телефона (IN-03), идемпотентность через РС `РассылкаWhatsApp` (IN-04). 🟢
- Токены Green API вынесены в КОНСТАНТЫ (хорошая практика) — `GREENApiToken_*` (🟢), НО есть утечка реального токена и FTP-кредов в КОММЕНТАРИЯХ (🔴).

## Решение

Использовать штатные планы обмена 1С с файловым XML-носителем поверх FTP для межбазовой репликации; для мессенджеров — единый диспетчер `МесенджерСервер` поверх адаптеров каналов и облачного Green API, с идемпотентностью рассылок через регистр сведений.

## Рассмотренные альтернативы

- **Прямое COM-соединение между отельными базами.** Применено для горничных/картинок (ADR 0005), но для межотельной репликации выбран асинхронный план обмена (базы разнесены, нужен файловый транспорт).
- **Прямая интеграция с WhatsApp Business API.** Отклонено: Green API проще подключить, инкапсулирует протокол; адаптеры позволяют добавлять каналы (Telegram, MAX).
- **Собственный SMTP/SMS-шлюз.** Частично: ошибки рассылки уходят на e-mail; основной канал — мессенджеры.

## Последствия

- ➕ Штатный, отлаженный механизм обмена 1С; единая точка рассылки с поддержкой нескольких каналов; идемпотентность защищает от повторов.
- ➕ Токены в константах (конфигурируемы без правки кода).
- ➖ FTP (порт 21, пассивный) — устаревший небезопасный транспорт.
- ➖ 🔴 Утечка боевых секретов в комментариях: FTP-креды (`212.176.32.173`, `INVINA/streg`, пароль) и реальный Telegram ApiToken Green API — серьёзная проблема безопасности.
- ➖ 🟡 Хардкод e-mail получателя ошибок рассылки; `ВГ_ВыпискаГостиницы` с пустым составом плана (обмен вручную сериализацией).
- ⚠ При миграции: вынести секреты в защищённое хранилище, заменить FTP на безопасный транспорт.
