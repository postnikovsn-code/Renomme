## C-01 — Green API (WhatsApp) 🟢

- **Направление:** исходящее (отправка сообщений гостям); входит статус доставки в ответе.
- **Хосты:** `api.green-api.com` (текст/ссылки), `media.green-api.com` (файлы).
- **Формат URL метода:** `waInstance<Инстанс>/<Метод>/<Токен>`.
- **Транспорт:** `HTTPСоединение(..., ЗащищенноеСоединениеOpenSSL)`, POST.
- **Аутентификация:** `idInstance` и `apiToken` из констант `GREENIdInstance_WhatsApp` / `GREENApiToken_WhatsApp` (подставляются в URL). 🟢
- **Методы и тела:**

| Метод | Тип | Тело | Заголовки |
|-------|-----|------|-----------|
| `sendMessage` | POST | JSON `{chatId, message}` | `Content-Type: application/json` |
| `sendLink` | POST | JSON `{chatId, urlLink, ...}` | `application/json` |
| `sendFileByUpload` | POST | multipart/form-data (ручная сборка границ, MIME по расширению) | `multipart/form-data; boundary=...` |
| `checkWhatsapp` | POST | JSON `{phoneNumber}` | `application/json` |

- **Нормализация получателя:** `chatId = "<номер>@c.us"`, где номер из `ТелефонGREEN()` (BR-05): только цифры; `8…`→`7…`; 10 цифр→`7`+номер; иначе `0` (невалидно).
- **Коды:** HTTP 200 → `ЧтениеJSON`; иначе `ВызватьИсключение` (статус+тело). КодОшибки `100` = «нет WhatsApp на номере».
- **Файлы multipart:** `ПараметрFormData`/`ФайлFormData` собираются вручную; MIME выводится по расширению.
- **Точка в коде:** `CommonModules/GREEN_WhatsApp/Module.bsl` (1405 строк); обёртка-адаптер `WhatsAppСервер/Module.bsl`.

## C-03 — PayKeeper / СБП 🟢

- **Направление:** исходящий запрос → входящие данные о платежах.
- **Хост:** PayKeeper, HTTPS:443, `ЗащищенноеСоединениеOpenSSL`.
- **Аутентификация:** двойная — Basic (логин/пароль в `HTTPСоединение`) + `token` в теле запроса. Token-сессия с TTL 1200 c, ленивое обновление (BR-08).
- **Структура соединения:** `{Параметры{Адрес,ИмяПользователя,ПарольПользователя}, Токен{Идентификатор,ВремяИстечения}, Ошибка, Описание}`.
- **Content-Type:** `application/x-www-form-urlencoded`; тело = `"token="+Токен+ТелоЗапроса`.
- **Эндпоинты:**

| Операция | Метод/Путь | Примечание |
|----------|-----------|------------|
| Получить токен | `GET /info/settings/token/` | поле `token`, TTL 1200 c |
| QR-код / счёт СБП | `ПолучитьQRКод()` (`/change/...preview`) | возвращает Base64 JPEG + URL картинки |
| Статус платежа | `GET /info/payments/byid/?id=<ИД>` | поле `status` |
| Список платежей | `GET /info/payments/bydate/?...&status[]=...&serverid[]=...` | по умолч. системы `93,52`; статусы `success,canceled,failed,refunding,partially_refunded,refunded` |
| Возврат денег | `POST /change/payment/reverse/` | для статусов success/partially_refunded/refunded |
| Платёжные системы | `GET /info/systems/list/` | — |

- **Поля платежа (ответ → РС `PayKeeperПлатежи`):** `id→ИД_Платежа`, `clientid→Плательщик`, `orderid→НомерСчета`, `pay_amount→Сумма`, `status→Статус`, `success_datetime→ДатаОплаты`. Upsert по `ИД_Платежа`, сохранение `ГУИД/ДатаСоздания`; success → привязка к долгу.
- **Обработка ошибок хостинга:** детект HTML («Система заблокирована. Требуется продление хостинга», `<!DOCTYPE html>`) → извлечение текста вместо JSON (BR-11).
- **Точка в коде:** `CommonModules/PayKeeper/Module.bsl` (793), `PayKeeperСервер/Module.bsl` (1097), `PayKeeperКлиентСервер`.

## C-04 — Обмен с сайтом 🟢

- **Направление:** входящее (получение бронирований).
- **Транспорт:** HTTPS GET, `Структура(АдресСервера, Порт=443, SSL=Истина)`.
- **Путь:** `/test/manager/index.php?r=reservation/export&startDate=<дд-ММ-гггг>&endDate=<дд-ММ-гггг>`.
- **Окно по умолчанию:** последние 90 дней (`КонечнаяДата=ТекущаяДата()`, `НачальнаяДата=КонечнаяДата−90`).
- **Формат ответа:** JSON → `ПрочитатьJSON`; парсинг дат `СтрВДату()` с локализацией месяцев (Янв/Фев…).
- **Контракт результата:** `{ДанныеJSON, Ошибка:Булево, Описание:Строка}`; при сбое `ДанныеJSON=Массив()`.
- **Точка в коде:** `CommonModules/ОбменСайт/Module.bsl:2-25` (573 строки модуль).
- **Downstream:** данные → `Document.ЗаявкаСайт` → `ЗаявкаНаБронирование` (конвертация в модуле «Бронирование»).

## C-05 — HTTP-сервисы заселений 🟢

- **Направление:** входящее (получение заселений и ежедневного отчёта от удалённых баз).
- **Транспорт:** `Новый HTTPСоединение(Сервер,,,,,120)` (таймаут 120 c), GET; код состояния ≥ 300 → ошибка.
- **Базовый путь по серверу (из константы):**

| Константа сервера | Префикс пути |
|-------------------|--------------|
| `СерверЛайвHTTP` | `/LIVE_HTTP/` |
| `СерверЧеховHTTP` | `/CHEHOV_HTTP/` |
| `СерверДомСоветовHTTP` | `/DomSovetov_HTTP/` |
| `СерверСтритАртHTTP` | `/StreetArt_HTTP/` |

- **Эндпоинты:**

| Операция | Путь | Формат |
|----------|------|--------|
| Заселения | `hs/products/get_product/date_from/<dd.MM.yyyy>/date_to/<dd.MM.yyyy>` | JSON |
| Ежедневный отчёт факт | `hs/products/get_Report_1` | JSON (даты ISO) |

- **Сохранение ответа:** в файл `<КаталогБД>HTTPЗаселения<ИмяСервера>.txt`, затем `ЧтениеJSON`.
- **Серверная сторона (источник у удалённой базы):** `ОбменHTTP.ВыгрузитьЗаселения/ВыгрузитьЕжедневныйОтчетФакт`, `ОбменЗаселенияСервер.ВыгрузитьЗаселения_КУдалению` — отдают ТЗ.
- **Точка в коде:** `CommonModules/HTTP_Модуль/Module.bsl` (192), `ОбменHTTP/Module.bsl` (37), `ОбменЗаселенияСервер/Module.bsl` (27).
- 🟡 `127.0.0.1` закомментирован в `HTTP_Модуль:63,161`.

## C-06 — Узловой обмен 1С (XML + инфраструктура сообщений + FTP) 🟢

- **Направление:** двунаправленное (репликация между базами сети отелей и с Бухгалтерией).
- **Протокол данных:** штатная инфраструктура сообщений плана обмена 1С — `ПланыОбмена.СоздатьЗаписьСообщения()/СоздатьЧтениеСообщения()`, `ВыбратьИзменения(Получатель, НомерСообщения)`, сериализация порций `ЗаписатьДанныеXML/ПрочитатьДанныеXML`.
- **Носитель:** временный XML-файл (`ПолучитьИмяВременногоФайла('xml')`), регистрируются пространства имён xsd/xsi/v8.
- **Транспорт:** FTP через `ФТПСервер` — `Новый FTPСоединение(АдресФТП, 21, Имя, Пароль, , Истина(пассивный), 5(таймаут), Неопределено)`. Реквизиты узла из `ФТПСервер.ПолучитьДанныеУзлаОбмена(Код)` → `{АдресФТП, ИмяПользователя, Пароль, КаталогОбменаFTP}`.
- **Планы обмена:**

| План | thisNode | Состав | autoRecord |
|------|----------|--------|------------|
| `ОбменГостиницы` | `2a0723ee-ceab-4bf1-969f-551009473555` | `InformationRegister.БезналЗагрузка` | нет |
| `ВГ_ВыпискаГостиницы` | `bdb53db4-…` | пусто (вручную через `ОбменВыписка`, узел код `БУХ`) | — |
| `ОбменТест` | `202c2b76-…` | `InformationRegister.Тест` | Allow |

- **Семантика ошибок:** коды чтения `1`/`30` = «нет нового сообщения» (не фатально, BR-01).
- **Сериализация выписок/НДС:** `ОбменВыписка` (XML `DocumentObject.Выписка`), `ОбменБухгалтерияНДС.ЗаписатьФайлСообщение` (заявки/счета/НДС, FTP-имя через `ПолучитьИмяФайлаОбменаФТП`).
- **XDTO:** пакеты `Cashbox_1_21_1` (граница БПО) и `ExchangeMessage` (схема сообщения) — 🔴 схемы `.xdto` не разобраны.
- **Точка в коде:** `CommonModules/ОбменГостиницы/Module.bsl` (664), `ОбменВыписка/Module.bsl` (375), `ОбменБухгалтерияНДС/Module.bsl` (1011), `ФТПСервер/Module.bsl`.
- 🔴 **Секрет:** боевые FTP-креды в комментарии `ФТПСервер:199-202` (`212.176.32.173 / INVINA\streg / mnbvcxz*279`). См. `questions.md`.
