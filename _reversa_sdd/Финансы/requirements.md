## Visão Geral

Модуль учитывает денежные средства, долги гостей/контрагентов и взаиморасчёты: приём оплат (касса, банк, прочие), банковские выписки, групповые счета (один плательщик на несколько броней), гашение долгов, закрытие финансового периода/месяца и кассовой смены. 🟢

**Ключевая архитектурная особенность (ADR 0001).** Реальный долг и его гашение ведутся не в регистрах накопления, а в табличных частях документа `ЗаявкаНаБронирование` (`СчетаДетальноДолги`, `РаспределениеОплатДолги`). Регистры `Деньги/Долги/Взаиморасчеты` остались от старого «учётного» контура: фактически наполняется только `Взаиморасчеты`. 🟢

## Responsabilidades

- Приём и проведение оплат тремя видами документов: `КассовыйДокумент` (наличные/карта), `ВыпискаБанка` (безнал), `ПрочиеОплаты` (взаимозачёт/списание). 🟢
- Валидация документов оплаты перед проведением (заполненность, контроль раскладки суммы). 🟢
- Движение по регистру `Взаиморасчеты` (оборот по контрагенту), знак — по флагу `Приход`. 🟢
- FIFO-гашение долга по строкам ТЧ `СчетаДетальноДолги` с идемпотентным накоплением в ТЧ `РаспределениеОплатДолги`. 🟢
- Распределение оплаты по групповому счёту (один плательщик → несколько броней) с правилом `Мин(остаток, СуммаКЗакрытию)`. 🟢
- Расчёт комиссии турагента и НДС-позиций чека группового счёта. 🟢
- Ручная корректировка взаиморасчётов (`ВзаиморасчетыКоректировка`). 🟢
- Закрытие финансового периода: отчёты «Долги» / «Списания», разбивка списаний доп.услуг МИНИБАР/ПРАЧЕЧНАЯ. 🟢
- Пометка заявок `Закрыто` за месяц (`ЗакрытиеДокументов`) и закрытие фискальной смены (`ЗакрытьСмену`, делегирует в БПО). 🟢

## Regras de Negócio

- **БП-01.** Знак движения `Взаиморасчеты` определяется булевым реквизитом `Приход`: Истина → `ВидДвиженияНакопления.Приход`, Ложь → `Расход`. Период движения = `ДатаОплаты` (не `Дата` документа). 🟢
- **БП-02.** В `КассовыйДокумент` обязателен контроль раскладки: `Сумма = СуммаКарта + СуммаНаличные`; при нарушении документ не проводится. 🟢
- **БП-03.** Документ оплаты не проводится, если не заполнены `ДатаОплаты`, `ОтКого` или `Сумма = 0` (валидация `ТекстОшибки()`). 🟢
- **БП-04.** Реально документы оплаты создают ровно одно движение — `Взаиморасчеты`; гашение конкретных долгов выполняется отдельно, через ТЧ заявки. 🟢
- **БП-05.** Гашение долга — FIFO по строкам `СчетаДетальноДолги`: оплата идёт по строкам по порядку, гася `СуммаКЗакрытию` до нуля; при нехватке — частичное гашение. 🟢
- **БП-06.** Накопление оплаты в `РаспределениеОплатДолги` идемпотентно по паре (`ДокументОплаты`, `ДолгиГУИД`): повторная оплата добавляется в существующую строку, а не дублирует её. 🟢
- **БП-07.** Распределение по групповому счёту: на каждую бронь идёт `Мин(остаток оплаты, Σ СчетаДетальноДолги.СуммаКЗакрытию по СчетГУИД)`; нераспределённый остаток возвращается. 🟢
- **БП-08.** Комиссия турагента: `СуммаКомиссии = СуммаПроживание · Бронирует.ПроцентКомиссии / 100`; ветвление по `ТипОплатыСчета`. 🟢
- **БП-09.** В закрытие периода попадают только заявки со статусом `Выехал` или `Неустойка`, у которых `РезервПо` (дата выезда) внутри `[ДатаС; ДатаПо]`. 🟢
- **БП-10.** «Долг к закрытию» = `Σ СчетаДетальноДолги.СуммаКЗакрытию` (проживание + услуги) > 0. 🟢
- **БП-11.** «Списание» классифицируется по `ВидыОпераций` документа `ПрочиеОплаты`: ∈ {Списание, СписаниеЗачет, СписаниеДопУслуг}; списания доп.услуг агрегируются по `ПрограммныйКодУслуги` родительской папки (МИНИБАР / ПРАЧЕЧНАЯ). 🟢
- **БП-12.** `ЗакрытиеДокументов` помечает заявки `Закрыто=Истина` за месяц при условии «месяц закрытия < текущий месяц». 🟢
- **БП-13 (как есть, дефект).** Регистр `Деньги` фактически НЕ наполняется (движения строятся только в недостижимом после `Возврат` коде); регистр `Долги` пишется заявкой (Приход) и устаревшим `ГашениеДолгов_Старая` (Расход) → его баланс недостоверен. Единый источник правды для долга — ТЧ заявки. 🔴
- **БП-14 (как есть, дефект).** В `КассовыйДокумент/ВыпискаБанка/ПрочиеОплаты` после движения `Взаиморасчеты` стоит безусловный `Возврат`; ~90 строк построения `Деньги/Долги` и начисления бонусов недостижимы. 🟢
- **БП-15 (как есть, дефект).** Начисление бонусов идёт через COM-подключение к отдельной бонусной базе с захардкоженными кредами (`Pwd=""123""`), сейчас в мёртвом коде. 🔴

## Requisitos Funcionais

| RF-02 | Контроль раскладки кассы `Сумма = СуммаКарта + СуммаНаличные` | Must | Если равенство нарушено — документ не проводится с сообщением «Сумма <> Сумма Карта + Сумма Наличные» 🟢 |

| RF-05 | FIFO-гашение долга по строкам `СчетаДетальноДолги` | Must | Оплата гасит `СуммаКЗакрытию` по строкам по порядку; полное гашение → `СуммаКЗакрытию=0`, `СуммаОплачено=СуммаДолг` 🟢 |

| RF-12 | Закрытие периода — отчёт «Долги» | Must | Список заявок Выехал/Неустойка с `СуммаКЗакрытию>0`, итог `СуммаДолга`, счётчик закрытых 🟢 |
| RF-13 | Закрытие периода — отчёт «Списания» с разбивкой МИНИБАР/ПРАЧЕЧНАЯ | Must | Списания по `ВидыОпераций`, агрегация доп.услуг по `ПрограммныйКодУслуги` 🟢 |
| RF-14 | Пометка заявок `Закрыто` за месяц (`ЗакрытиеДокументов`) | Could | Заявки Выехал за месяц помечаются `Закрыто=Истина` если месяц закрытия < текущего 🟢 |

# RF-01 happy path
Dado КассовыйДокумент с заполненными ДатаОплаты, ОтКого, Сумма, и Сумма = СуммаКарта + СуммаНаличные
Quando документ проводится
Então создаётся ровно одно движение Взаиморасчеты с Период=ДатаОплаты, Контрагент=ОтКого, Сумма=Сумма
E знак движения = Приход при Приход=Истина, иначе Расход

# RF-02 failure path — контроль раскладки
Dado КассовыйДокумент с Сумма=1000, СуммаКарта=600, СуммаНаличные=300
Quando документ проводится
Então Отказ=Истина, выводится «Сумма <> Сумма Карта + Сумма Наличные. Документ НЕ сохранен», движений нет

# RF-03 failure path — пустые данные
Dado ВыпискаБанка с незаполненным ОтКого
Quando документ проводится
Então Отказ=Истина, выводится «От кого - пусто», движений нет

# RF-05 happy path — полное гашение строки долга
Dado строка СчетаДетальноДолги с СуммаКЗакрытию=1000 и оплата ОстатокКРаспределению=1500

Então СуммаКЗакрытию=0, СуммаОплачено=СуммаДолг, ОстатокКРаспределению=500, функция возвращает +1

# RF-05 alt path — частичное гашение
Dado строка СчетаДетальноДолги с СуммаКЗакрытию=1000 и оплата ОстатокКРаспределению=400
Quando РаспределитьОплатаСтрокаДолгСтрока
Então СуммаКЗакрытию=600, СуммаОплачено += 400, ОстатокКРаспределению=0, функция возвращает -1

# RF-06 идемпотентность
Dado оплата (ДокументОплаты, ДолгиГУИД) уже распределена в РаспределениеОплатДолги

Então строка не дублируется, СуммаОплаты увеличивается на сумму распределения

# RF-07 групповой счёт
Dado групповой счёт на 2 брони (СуммаКЗакрытию 1000 и 2000) и оплата 1500
Quando РаспределитьДокументОплатыГрупповойСчетОбъект

# RF-12 закрытие периода — отбор
Dado заявка со статусом Заехал и РезервПо внутри периода
