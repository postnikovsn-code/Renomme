## Основной поток — ночной аудит

(см. `flowcharts/Аудит-ЕжедневныйАудит.md`)

1. Создание документа: `Автор = ТекущийПользователь`, `Дата/ДатаОтбора = ТекущаяДата()`; форма достраивает параллельную таблицу `ПроданныеНомераОтклонения` (`ПриСозданииНаСервере:30-67, 84-138`). 🟢
2. `ЗаполнитьТаб()` очищает ТЧ `ПроданныеНомера/Незаезды/Аннуляции` (`:424-426`). 🟢
3. Запрос проживающих к РС `ЗанятостьНомеров` (статус `Проживает`/`Выехал`, период/время в `ДатаОтбора`) с левым соединением оплат по способам через `РаспределениеОплатДолги × СчетаДетальноОплаты` (`:448-578`). 🟢
4. Фильтр: пропуск выехавших до `ДатаОтбора + 14ч` (`:595-597`). 🟢
5. По каждой брони: найти строку `Проживание` за день, определить двухместность (`ДокументыСервер.ДвухМестный`), вызвать `ПроживаниеОтклонение(...)` (`:617-634`). 🟢
6. Заполнить строку `ПроданныеНомера`: суммы заявка/факт/отклонение/отклонение-часы, цена ценовой политики со скидкой клиента, допместо, ГУИД, оплаты по способам (`:628-716`). 🟢
7. Незаезды (статус `Бронь`) и аннуляции (`ДатаАннуляции` за день) (`:728-798`). 🟢
8. `ЗаполнитьПроданныеНомераОтклонения()` — оставить строки с расхождением (`:216-228`). 🟢
9. Проведение: при `Проверка=Истина` — движения РС `ПроданныеНомера` (`ObjectModule.bsl:6-22`). 🟢

### Расчёт отклонения (`ПроживаниеОтклонение`)

- `ЦенаНаДень = Окр(СтрокаПроживание.Сумма / Количество, 2)`; `ЦенаЗаЧас = Окр(ЦенаНаДень / 24, 2)` (`:890-893`). 🟢
- Ранний заезд (`Час(Заезд) < 6`): `Вр6`/кол-во=1.5 → откл `ЦенаНаДень*0.5`, часы `6−ЧасЗаезд`; `Вр14`/кол-во=1 → откл `ЦенаНаДень`, часы `14−ЧасЗаезд` (`:898-922`). 🟢
- Поздний выезд: диапазоны часа выезда 14–18 / 18–23 / =23 против планового `ВремяВыезда`/кол-ва суток → откл `ЦенаНаДень*0.5` или `ЦенаНаДень`, часы `ЧасВыезд−13`/`−17` (`:936-997`). 🟢
- Магические часы 6/13/14/17/18/23 и доли 0.5/1/1.5 — захардкоженная политика расчётного часа. 🟡

## Основной поток — ежедневный факт-отчёт

(см. `flowcharts/Аудит-ЕжедневныйОтчетФакт.md`)

1. `СформироватьОтчетНаСервере`: проверка дат; режим «Помесячно» округляет границы (`:18-37`). 🟢
2. `ТЗ = CM.ТЗ_ОтчетДанные(ДатаС, ДатаПо)` — сбор первички: проживание из `ЗаявкаНаБронирование.Проживание` (ВНУТР. соединение `СчетаДетальноДолги`), допуслуги, оплаты `РаспределениеОплатДолги`, эквайринг по проценту с датой установки, `КоличествоНомеров` из `НомернойФонд` (`CM:2-357`). 🟢
3. `CM.ЗаполнитьРегистрЕжедневныйОтчетФакт(ТЗ)` — запись витрины РС (`CM:376-407`). 🟢; формулы агентского/B2B/ADR_НА 🔴.
4. Запрос к РС `ЕжедневныйОтчетФакт` за период (чтение витрины обратно). 🟢
5. Расчёт метрик по строкам: ADR, занятые, загрузка %, средняя стоимость, структура (`Forms/Форма/Module.bsl:203-239`). 🟢
6. Вывод областей макета: Шапка / Строка(день) / Итоги / ИтогиМесяц → `ПолеОтчета`. 🟢

### Формулы метрик 🟢

```
ADRДвухместные      = ?(КолДвухм=0, 0, Окр(СуммаДвухм / КолДвухм))
ADRОдноместные      = ?(КолОдном=0, 0, Окр(СуммаОдном / КолОдном))
ИтогоЗанятыеНомера  = КолОдном + КолДвухм
ПроцентЗаселяемости = ?(КоличествоНомеров=0, 0, Окр(ИтогоЗанятые / КоличествоНомеров * 100))
ИтогоСредняяСтоимость = ?(ИтогоЗанятые=0, 0, Окр(ИтогоСумма / ИтогоЗанятые))
ЦенаЗаЧас           = Окр(ЦенаНаДень / 24, 2)
```

## Основной поток — сводный отчёт сети

1. `ЕжедневныйОтчетФактСводный.Форма` (36 строк) делегирует в `CM.СформироватьЕжедневныйОтчетСводный` (`CM:436-762`). 🟢
2. Локальные данные + массивы `МассивРеноме/МассивЛайв/МассивЧехов/МассивДомСоветов/МассивСтритАрт`; удалённые — через `ЗагрузитьHTTP_ЕжедневныйОтчетФакт(..., ИмяСервера)` → `HTTP_Модуль.ПолучитьЕжедневныйОтчетФакт` (`CM:817-851`). 🟢
3. Каждому отелю присваивается `СортировкаОтель` 1..N; строится общий табличный документ. 🟢
4. Контракт HTTP описан в `contracts.md`. 🟡 (имена отелей и адреса захардкожены, ADR-0008).

## Альтернативные потоки

- **Пустой день / нулевой знаменатель:** все деления метрик защищены `Если знаменатель=0 Тогда 0` → отчёт строит нули, не падает. 🟢
- **`Проверка=Ложь` при проведении:** документ проводится без движений РС. 🟢
- **Недоступный отель сети:** `ЗагрузитьHTTP_…` возвращает `Ошибка=Истина` + текст с именем сервера; свод не прерывается аварийно. 🟢 (`CM:821-834`)
- **`Результат.Данные = Неопределено`:** HTTP-сервис ответил, но не подготовил данные → ошибка подготовки с именем сервера. 🟢 (`CM:829-833`)

## Зависимости

- РС `ЗанятостьНомеров` — источник проживающих/незаездов (модуль «Бронирование»/«Размещение»). 🟢
- Док `ЗаявкаНаБронирование` (ТЧ `Проживание`/`ДопУслуги`/`СчетаДетально*`/`РаспределениеОплатДолги`) — основной источник денежных метрик. 🟢
- Док `КассовыйДокумент`, `ВыпискаБанка` — типизация оплат (карта/нал/безнал). 🟢
- `ДокументыСервер` — `ДвухМестный`, `ЗаполнитьЦенаСуммыСтрокаПроживание` (цены/скидки — модуль «Ценообразование»). 🟢
- Справ. `НомернойФонд` — знаменатель загрузки. 🟢
- `HTTP_Модуль.ПолучитьЕжедневныйОтчетФакт` — транспорт сводного отчёта. 🟢
- `ОбщийФункционалСервер` (`РеквизитыИзТабличнаяЧастьДокумента`, `ТаблицаЗначенийВМассивСтруктур`) — генерация форм/конвертация. 🟢

## Решения дизайна

| Решение | Доказательство | Доверие |
|---------|----------------|---------|
| Документ-«конструктор движений»: аналитика в форме, проведение лишь копирует ТЧ → РС | `ObjectModule.bsl:3-23` | 🟢 |
| Тумблер `Проверка` как ворота движений (подтверждённая витрина дня) | `ObjectModule.bsl:6`, ADR-0008/AU-01 | 🟢 |
| Materialized view: факт-отчёт пишет РС-витрину и читает её обратно (кэш дня) | `Forms/Форма/Module.bsl:64-72` | 🟢 |
| Мультиотельность через код+HTTP, а не сущность «Организация» | `CM:436-851`, ADR-0008 | 🟡 |
| Защита деления на ноль по всему расчёту метрик | flowchart «Защита» | 🟢 |

## Внутреннее состояние

- ТЧ `ПроданныеНомера` (≈38 колонок), `Незаезды`, `Аннуляции` документа `ЕжедневныйАудит`. 🟢
- РС `ПроданныеНомера` — подтверждённая витрина продаж дня (регистратор `ЕжедневныйАудит`). 🟢
- РС `ЕжедневныйОтчетФакт` — витрина показателей дня (изм. `Дата`/`Отель`/`Месяц`; рес. количества/суммы размещений, `СуммаАгентскогоВознаграждения`, `Процент_НА`, `ADR_НА`, `СуммаВ2В`, `СуммаКомиссии`, `Мероприятия`). 🟢
- РС `АктивностиКалендарь` (изм. `Дата`, рес. `АктивностьКалендарь`) — фактор спроса. 🟡

## Наблюдаемость

- HTTP-ошибки сводного отчёта возвращаются оператору текстом с именем сервера и подсказкой «ОБРАТИТЕСЬ К АДМИНИСТРАТОРУ» (`CM:823, 831`). 🟢
- 🔴 Структурированного журналирования (ЗаписьЖурналаРегистрации) в разобранных методах unit не обнаружено — ошибки идут пользователю предупреждениями/в свод.

## Риски и пробелы

- 🔴 Формулы `СуммаАгентскогоВознаграждения`/`СуммаВ2В`/`ADR_НА`/`Процент_НА` в `ЗаполнитьРегистрЕжедневныйОтчетФакт`/`ТЗ_ОтчетДанные` построчно не разобраны — граница с «Финансами»/«Ценообразованием».
- 🔴 14 DCS-отчётов: схема ресурсов/измерений из `Template.dcs` не извлекалась; 30+ отчётов классифицированы по имени/источнику.
- 🟡 Имена отелей сети (Реноме/Лайв/Чехов/ДомСоветов/СтритАрт) и параметры HTTP захардкожены.
- 🟡 Магические часы расчётного дня и доли захардкожены в `ПроживаниеОтклонение`.
- 🟡 Дубли/мёртвый код: `ЕжедневныйАудит_Исходный`, две версии `СуммаЗаПроживаниеОтклонение`, `_OLD`-формы, закомментированные исторические алгоритмы тарификации — затрудняют выделение активной логики.
