# ADR 0005 — Интеграция через отдельные базы 1С по COM (горничные, картинки, бонусы)

- **Статус:** Принято (исторически) · 🟢 ПОДТВЕРЖДЕНО кодом
- **Дата:** неизвестна
- **Модуль:** Горничные / Интеграции / Размещение / Финансы

## Контекст

Часть функций ведётся в самостоятельных базах 1С: регистрация уборок горничными — на планшетах в отдельной базе «Горничные»; картинки планшета — в базе «<Организация>_Картинка Планшет»; бонусная программа — в базе «BONUS». Эти базы нужно синхронизировать с основной «ОТЕЛЬ».

Свидетельства:
- `ОбменГорничныеСервер.Соединение()` — `V83.COMConnector` к файловой БД горничных, кэш в параметре сеанса, до 3 попыток (IN-07). 🟢
- В обеих базах одноимённый модуль `ОбменГорничныеСервер` как RPC-фасад; обратное направление пишется с `ОбменДанными.Загрузка=Истина` для разрыва цикла (HK-08). 🟢
- `ОбменКартинкаСервер.Соединение()` — COM к `C:\_Base1C\<Организация>_Картинка Планшет` (IN-07). 🟢
- `СлужебныеСервер.ConnectБаза_BONUS()` — COM к базе бонусов (в мёртвом коде проведения оплат, ADR 0001). 🟢
- Загрузчики номеров (`ЗагрузкаНомеровЛайв/Реноме/Чехов`) — тоже COM-импорт из внешних баз. 🟢

## Решение

Связывать основную базу с вспомогательными через синхронное COM-соединение (`V83.COMConnector`) с RPC-вызовами одноимённых модулей-фасадов; соединение кэшировать в параметре сеанса; обмен справочниками двусторонний с защитой от зацикливания (`ОбменДанными.Загрузка`).

## Рассмотренные альтернативы

- **Единая база со всеми подсистемами.** Отклонено исторически: планшеты горничных и картинки развивались как отдельные продукты/базы; объединение потребовало бы крупной миграции.
- **Асинхронный обмен через планы обмена 1С (XML+FTP).** Применено для МЕЖотельного обмена (ADR 0009), но для горничных/картинок выбран синхронный COM (нужна оперативность RPC, локальная файловая база).
- **REST/HTTP-сервисы между базами.** Применено для заселений/отчётов (HTTP_Модуль), но не для горничных — там исторически COM.

## Последствия

- ➕ Оперативный RPC-обмен, переиспользование одного кода-фасада в обеих базах.
- ➖ Жёсткая привязка к файловым путям и платформе Windows/COM (`V83.COMConnector`).
- ➖ 🔴 Хардкод учётных данных COM: `Pwd="123"`, `Usr="Соединение"/"Администратор"` в `ОбменГорничныеСервер`, `ОбменКартинкаСервер`, загрузчиках номеров — утечка секретов в исходниках.
- ➖ Хрупкость: разрыв соединения → ретраи через `Перейти ~метка` (антипаттерн `UsingGoto`), ошибки часто подавляются пустыми `Попытка`.
- ⚠ При миграции этот контур интеграции — кандидат на замену сервисным (HTTP/очередь) обменом с вынесением секретов в защищённое хранилище.
