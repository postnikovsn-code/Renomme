# Бронирование — Внешние контракты

> Внешний контракт модуля: входящая заявка из внешнего канала (сайт / Travelline / мессенджеры), материализуемая как документ `ЗаявкаСайт`, затем конвертируемая в `ЗаявкаНаБронирование`. Контракт описан по реквизитам `.mdo`; транспорт обмена — отдельный unit «Интеграции и обмен» (ADR-0005, ADR-0009). Уверенность: 🟢/🟡/🔴.

## Контракт: входящая заявка канала (`ЗаявкаСайт`)

**Направление:** входящий (внешняя система → отель).
**Материализация:** документ `Document.ЗаявкаСайт` (один документ на одну внешнюю заявку).
**Идемпотентность:** дубликаты предотвращаются на этапе конвертации в бронь (`ЕстьЗаявкаНаБронирование` ищет проведённую бронь с `ЗаявкаСайт = ТекущаяСсылка`). 🟢
**Источник полей:** `Documents/ЗаявкаСайт/ЗаявкаСайт.mdo`; `data-dictionary.md` § «ЗаявкаСайт».

### Поведение при потреблении контракта

1. Внешняя заявка сохраняется как `ЗаявкаСайт` (транспорт — unit «Интеграции и обмен»). 🟡
2. Оператор выполняет команду `СоздатьЗаявкуНаБронирование`:
   - проверка дубля (`ЕстьЗаявкаНаБронирование`) — BR-11; 🟢
   - открытие формы `ЗаявкаНаБронирование` с параметром `ЗаявкаСайт`; 🟢
   - сопоставление клиента по `Фамилия`/`Имя`/`Телефон` (`ТипСовпадения` 1=нет / 2=несколько / иначе один) — BR-12; 🟡
   - маппинг полей сайта в реквизиты брони (`ЗаполнитьЗаявкуИзЗаявкаСайт`); 🔴 точный маппинг не разобран (см. `questions.md` Q-04).
3. `ВремяЗаезда`/`ВремяВыезда` участвуют в расчёте почасового периода резерва (BR-05). 🟢

### Пробелы контракта

- 🔴 Транспорт/формат обмена (XML/FTP/мессенджеры) описан в ADR-0009, но точная схема входящего сообщения и правила заполнения `ЗаявкаСайт` — в unit «Интеграции и обмен», здесь не дублируется.
- 🔴 Точный маппинг `КатегорияНомераСайт` (строка) → `КатегорияНомера` (ссылка) и денежных полей в ТЧ `Проживание` брони — см. Q-04, Q-03.
- 🟡 Семантика `ТипОплаты`/`ФлагОплаты` (кодовые значения) не расшифрована.

> Исторический прямой запрос к внешней MS SQL (`ВыполнитьЗапросСайт`) НЕ является частью действующего контракта — функция отключена и содержит хардкод секрета (см. `questions.md` Q-02). Контракт = обмен через документ `ЗаявкаСайт`.
