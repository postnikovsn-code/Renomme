# ADR 0008 — Мультиотельность через код `НастройкиСервер.Это*()` вместо сущности «Организация»

- **Статус:** Принято (исторически) · 🟢 ПОДТВЕРЖДЕНО кодом
- **Дата:** неизвестна
- **Модуль:** сквозной (Персонал, Горничные, Допуслуги, Аудит, Интеграции)

## Контекст

Конфигурация обслуживает сеть отелей (Реноме, Лайв, Чехов, ДомСоветов, СтритАрт). Каждый отель — отдельная база, но с общей конфигурацией; поведение должно различаться по отелю (надбавки ЗП, макеты печати, источники заселений, доступность тарифа БонШанс).

Свидетельства:
- `НастройкиСервер.ЭтоЛайв()/ЭтоЧехов()/ЭтоДомСоветов()/ЭтоСтритАрт()/ЭтоРеноме()` — булевы фасады по `Константы.Организация.ОрганизацияИмя` (`НастройкиСервер:39-67`). 🟢
- `ФункциональностьДоступностьОрганизация()` — БонШанс выключен для «ДомСоветов» (`:20-36`). 🟢
- Макеты печати по организациям: `КоворкингСчета.Template.{...}{Лайв,СтритАрт,Реноме,Чехов}`; выбор области по `НастройкиСервер.Это*`. 🟢
- Источники заселений ветвятся по имени отеля в ЗП администраторов (HR-06). 🟢
- Сводный отчёт сети — имена отелей захардкожены в `ЕжедневныйОтчетФакт`. 🟢

## Решение

Различать поведение по отелю через имя организации (`Константы.Организация`), читаемое булевыми фасадами `НастройкиСервер.Это<Имя>()`; ветвить функциональность, макеты и источники по этим фасадам/строковым сравнениям имени.

## Рассмотренные альтернативы

- **Конфигурируемая сущность «Профиль отеля»** с реквизитами-флагами функциональности. Отклонено фактически: вместо данных используются код-фасады и сравнения по имени-строке.
- **Отдельная конфигурация на каждый отель.** Отклонено: дороже в сопровождении; выбрана общая конфигурация + базы.
- **Функциональные опции 1С** (`FunctionalOption`). Не применено для отельных различий (хотя платформа их поддерживает).

## Последствия

- ➕ Одна конфигурация на всю сеть; различия централизованы в `НастройкиСервер`.
- ➖ Имена отелей («Реноме»/«Лайв»/…) захардкожены строками в десятках мест → добавление отеля требует правки кода.
- ➖ Ветвления `Если ИмяОрганизации = "..."` рассыпаны (ЗП, печать, отчёты, БонШанс) — хрупко, легко пропустить место.
- ➖ Нет декларативного «профиля отеля» — функциональность не настраивается без программиста.
- ⚠ При миграции мультиотельность стоит вынести в конфигурируемый профиль/опции, а не строковые сравнения.
