### Общие модули (бизнес-логика)

| Символ | Сигнатура | Возврат | Наблюдение |
|--------|-----------|---------|------------|
| `ЗаявкаОбщееКлиентСервер.РаспределитьОплатаСтрокаДолгСтрока` | `(ОплатыСтрока, ОстатокКРаспределению, ДолгСтрока, РаспределениеОплатДолги)` Экспорт | `+1` / `-1` / `0` | Гасит одну строку долга; мутирует `ОстатокКРаспределению` и `ДолгСтрока` (вых. параметры) 🟢 |

| `ЗаявкаОбщееКлиентСервер.РаспределитьСтрокаОплатаНаСчета` | `(ОплатаСтрока, ОстатокКРаспределению, Счета, СчетаДетальноДолги, РаспределениеОплатДолги)` Экспорт | — | Отбирает счета по контрагенту → распределяет долги 🟢 |
| `ГрупповойСчетСервер.РаспределитьДокументОплатыГрупповойСчетОбъект` | `(ДокументОплаты, ГрупповойСчётОбъект, СуммаОплаты)` | остаток | `Мин(остаток, СуммаСчетаКЗакрытию)` по броням группы 🟢 |
| `ГрупповойСчетСервер.УменьшитьОплатыГрупповойСчетСуммаВозврата` | `(...)` | — | Транзакция: снятие оплат, пересчёт, повторное распределение 🟢 |
| `ГрупповойСчетСервер.ЗаполнитьПозицииЧекаККМОплатаГрупповойСчет` | `(...)` | позиции чека | НДС-позиции, `ДатаУчетаНДС=Макс(РезервПо)` 🟢 |

> Коды-флаги возврата FIFO: `+1` — строка/долг закрыт; `-1` — оплата исчерпана; `0` — продолжаем. 🟢

## Fluxo Principal

### Проведение документа оплаты (касса/банк/прочие)
1. `Ответ = ТекстОшибки()` — валидация. `Documents/КассовыйДокумент/ObjectModule.bsl:66` 🟢
2. Если `ЗначениеЗаполнено(Ответ)` → сообщение «… Документ НЕ сохранен», `Отказ=Истина`, `Возврат`. (стр. 67-77) 🟢
3. Иначе: `Движение = Движения.Взаиморасчеты.Добавить()`; `ВидДвижения = ?(Приход, Приход, Расход)`; `Период=ДатаОплаты`; `Контрагент=ОтКого`; `Сумма=Сумма`. (стр. 79-85) 🟢
4. **`Возврат;` (стр. 87)** — ранний выход. Весь код ниже (движения `Деньги`, `Долги`, бонусы) недостижим. 🟢

### FIFO-гашение долга
1. `РаспределитьОплатаНаСчетаДетальноДолги`: для каждой строки `СчетаДетальноДолги` вызвать `РаспределитьОплатаСтрокаДолгСтрока`. `Module.bsl:73-81` 🟢
2. В строке: ранние выходы — `СуммаКЗакрытию=0 → +1`; `ОстатокКРаспределению=0 → -1`. (стр. 25-26) 🟢
3. `ОплатыОстаток = ОстатокКРаспределению − ДолгСтрока.СуммаКЗакрытию`. (стр. 28) 🟢
4. Если `ОплатыОстаток > 0` (хватает на весь долг): `СуммаОплаты=СуммаКЗакрытию`; `ОстатокКРаспределению=ОплатыОстаток`; `СуммаОплачено=СуммаДолг`; `СуммаКЗакрытию=0`. (стр. 30-37) 🟢
5. Иначе (частично): `СуммаОплаты=ОстатокКРаспределению`; `СуммаКЗакрытию −= ОстатокКРаспределению`; `СуммаОплачено += СуммаОплаты`; `ОстатокКРаспределению=0`. (стр. 38-48) 🟢
6. Найти строку `РаспределениеОплатДолги` по (`ДокументОплаты`, `ДолгиГУИД`); если нет — создать; `СуммаОплаты += СуммаОплаты`. (стр. 50-62) 🟢
7. Вернуть `+1` / `-1` / `0` по итогу. (стр. 64-70) 🟢

### Распределение по групповому счёту
1. `ОстатокСуммаОплаты = СуммаОплаты`; обход ТЧ `ДокументыДолги`. `ГрупповойСчетСервер/Module.bsl:453-529` 🟢
2. Для каждой заявки: `СуммаСчетаКЗакрытию = Σ СчетаДетальноДолги.СуммаКЗакрытию по СчетГУИД`. Если 0 — пропуск. 🟢
3. `СуммаОплатыЗаявка = Мин(Остаток, СуммаСчетаКЗакрытию)`; распределение в заявку; `ЗаявкаОбъект.Записать(Проведение)`. 🟢
4. Если `ОстатокСуммаОплаты <= 0` — `Прервать`, иначе следующая заявка. 🟢

### Закрытие финансового периода
1. `ЗаполнитьОтчетДолгиНаСервере(ДатаС, ДатаПо)` + `ЗаполнитьОтчетСписаниеНаСервере`. `Forms/Форма/Module.bsl:18-36` 🟢
2. Запрос: `ЗаявкаНаБронирование`, `ПометкаУдаления=Ложь`, `Статус ∈ {Выехал, Неустойка}`, `РезервПо ∈ [ДатаС; ДатаПо]`. 🟢
3. Левые соединения по ТЧ: Проживание (Σ Сумма), ДопУслуги ВСчет=Истина (Σ Кол·Цена), `СчетаДетальноДолги` (СуммаДолг/СуммаКЗакрытию), `РаспределениеОплатДолги` (списания). 🟢
4. Отчёт «Долги»: `СуммаКЗакрытию > 0`; подсветка `СуммаПроживаниеСчета ≠ СуммаПроживание` красным; итог + счётчик закрытых. 🟢
5. Отчёт «Списания»: `ВидОперации ∈ {Списание, СписаниеЗачет, СписаниеДопУслуг}`; разбивка доп.услуг по `ПрограммныйКодУслуги` → МИНИБАР / ПРАЧЕЧНАЯ / прочее. (стр. 329-382) 🟢

## Fluxos Alternativos
- **Касса: раскладка не сходится** (`Сумма ≠ СуммаКарта + СуммаНаличные`): добавляется текст ошибки, документ не проводится. 🟢
- **Оплата больше суммарного долга:** остаток после FIFO остаётся нераспределённым (`ОстатокКРаспределению > 0` по выходу из цикла → `Возврат 0`). 🟢
- **Возврат оплаты (касса/банк):** реквизиты `Возврат`/`ВозвратДокумент`; знак `Взаиморасчеты` инвертируется через `Приход`; пересчёт группового счёта в `УменьшитьОплатыГрупповойСчетСуммаВозврата`. 🟢
- **Групповой счёт, бронь уже закрыта** (`СуммаСчетаКЗакрытию=0`): бронь пропускается, оплата уходит дальше. 🟢

## Dependências
- **Бронирование** — `ЗаявкаНаБронирование` пишет регистры `Долги` (Приход) и `Взаиморасчеты`; хранит ТЧ долгового контура (`СчетаДетальноДолги`, `РаспределениеОплатДолги`, `Счета`). 🟢
- **Доп. услуги и коворкинг** — списания доп.услуг (МИНИБАР/ПРАЧЕЧНАЯ) учитываются в закрытии периода через `ПрограммныйКодУслуги`. 🟢
- **Подключаемое оборудование (БПО)** — `ЗакрытьСмену` делегирует в `ФУ_Клиент.ЗакрытьСмену`; чеки ККМ. 🟡
- **Интеграции и обмен** — PayKeeper (эквайринг), обмен банк/бухгалтерия как протокол; здесь — только порождаемые ими движения денег/взаиморасчётов. 🟡
- **Бонусная база** (внешняя) — COM-подключение `СлужебныеСервер.ConnectБаза_BONUS()` (в мёртвом коде, см. ADR 0005). 🔴

## Estado Interno
- Долговое состояние живёт в ТЧ `ЗаявкаНаБронирование.СчетаДетальноДолги` (`СуммаДолг`, `СуммаКЗакрытию`, `СуммаОплачено`) и `РаспределениеОплатДолги` (`СуммаОплаты`), ключи — `СчетГУИД`/`ДолгиГУИД`. 🟢
- Регистр `Взаиморасчеты` (Обороты): `Контрагент → Сумма, СуммаКомисииРасчет`; `enableTotalsSplitting=true`. 🟢
- Регистры `Долги` (Обороты, измерения `ДокументДолг`/`Контрагент`, ресурс `Сумма`) и `Деньги` — присутствуют, но фактически недостоверны/пусты. 🔴

## Observabilidade
- Пользовательские сообщения через `Сообщить(...)` при отказе в проведении (текст ошибок из `ТекстОшибки()`). 🟢
- Отдельной структурированной телеметрии/логирования (`ЗаписьЖурналаРегистрации`) в проведении оплат не обнаружено. 🟡
- Блок начисления бонусов обёрнут в `Попытка…Исключение` с **пустым** `Исключение` (молчаливое проглатывание) — в мёртвом коде. 🔴

## Riscos e Lacunas
- 🔴 **Двойной контур учёта.** Регистры `Деньги`/`Долги` не являются источником правды; балансовый отчёт по долгам стандартными средствами регистра получить нельзя (только запросом по ТЧ заявки). См. ADR 0001.
- 🔴 **Мёртвый код проведения** (~90 строк × 3 документа) после безусловного `Возврат` — скрывает захардкоженное COM-подключение к бонусной базе (`Pwd=""123""`).
- 🔴 **`ГашениеДолгов_Старая`** — параллельный писатель регистра `Долги` (Расход), сосуществует с актуальным ТЧ-контуром.
- 🟡 **4 версии методов отчёта** в `ЗакрытиеФинансовогоПериода` (`_Перенесено`, `_ПокаСохранить`) — неясно, какая каноническая.
- 🟡 **`ЗакрытьСмену`** опирается на модуль БПО; фискальная логика смены вне модуля «Финансы».
