# Гости и регистрация, Крайние случаи

> Файл `edge-cases.md`. Граничные/конфликтные сценарии домена гостей, извлечённые из легаси-кода. Уверенность: 🟢/🟡/🔴.

## EC-01 — Конфликт источников при распознавании паспорта (page3 / OCR / MRZ)

**Контекст.** Сканер PassportBox отдаёт до трёх наборов значений одного поля: с 3-й страницы (`page3`), из OCR разворота и из машиночитаемой зоны (`MRZ`). Значения могут различаться (например, дата рождения распознана по-разному OCR и MRZ).
**Поведение легаси.** `ЗаполнитьПоляИзJSON` применяет источники строго по возрастанию приоритета `page3 < OCR < MRZ`; более приоритетное **непустое** значение перезаписывает менее приоритетное; пустое не перезаписывает никогда (`PassportBoxВызовСервера/Module.bsl:464-479`). 🟢
**Риск/проверка.** Если MRZ ошибочно распознана (но непустая), её значение «победит» более точный page3/OCR. Тихая перезапись без сигнала оператору.
**Ожидаемая обработка.** Сохранить порядок приоритетов; при расхождении источников логировать/подсвечивать поле для ручной сверки оператором. 🟡

## EC-02 — Дубль клиента по ИНН/ФИО (физлицо vs юрлицо)

**Контекст.** Антидубль при записи работает по наименованию, ИНН+КПП, ПроверитьКонтрагента; отдельный отчёт дублей `КлиентыДвойныеИНН` фильтрует только `ТипКлиента=ЮрЛицо`.
**Поведение легаси.** При записи дубль юрлица по ИНН+КПП отлавливается (`ПередЗаписью`, `Module.bsl:263-308`). Дубли **физлиц** по ИНН/ФИО/паспорту автоматически отчётом не выявляются (`КлиентыДвойныеИНН/.../Module.bsl:22-143`, фильтр ЮрЛицо). Вид клиента «Исключить из отчётов» отключает антидубль по наименованию. 🟢/🟡
**Риск/проверка.** Физлицо может задвоиться (разные написания ФИО, опечатка в ИНН), а отчёт его не покажет → расхождение истории/счетов.
**Ожидаемая обработка.** Расширить детекцию дублей на физлиц (по нормализованному ФИО + ДатаРождения + паспорт). Подтвердить, является ли ограничение «только юрлица» намеренным. 🔴

## EC-03 — Иностранный гражданин vs гражданин РФ в выгрузке ФМС

**Контекст.** Формат CSV `#v.2.0.0` ветвится по `ИностранныйГражданин` по десяткам полей.
**Поведение легаси.** РФ: гражданство `RUS`, тип документа `103008`, поля визы/пребывания/миграционной карты/целей пустые. ИГ: гражданство `ГражданствоФМС_NEW.CODE_ALPHA3`, тип документа `ТипДокументаФМС_NEW.ID`, заполнены виза/мигркарта/цели; `АдресРегистрацииОтсутствует` для ИГ трактуется как True (`ВыгрузкаДляФМС/.../Module.bsl:138-429`). 🟢/🟡
**Риск/проверка.** Гость с двойным гражданством или сменой статуса; пустой `ГражданствоФМС_NEW` у ИГ даст пустое поле гражданства; магическое `103008` рассинхронится с классификатором.
**Ожидаемая обработка.** Валидировать обязательность `ГражданствоФМС_NEW`/`ТипДокументаФМС_NEW` для ИГ перед выгрузкой; вынести `103008` в константу. 🔴

## EC-04 — Объединение клиентов без полноценной защиты транзакции

**Контекст.** `ОбъединитьКлиентовНаСервере` оборачивает цикл замен в `НачатьТранзакцию`/`ЗафиксироватьТранзакцию`, но внутри цикла `Записать(Проведение)` вызывается **без** `Попытка/Исключение` (`Module.bsl:206-221`). 🟢
**Поведение легаси.** При сбое записи одной из заявок исключение прерывает выполнение, `ОтменитьТранзакцию` не вызывается → транзакция остаётся открытой/откатывается платформой неявно; частично применённые замены ссылок. Нарушение паттерна `BeginTransactionBeforeTryCatch`.
**Риск/проверка.** Несогласованное состояние: часть документов уже ссылается на клиента-результат, часть — нет; исходный клиент в неопределённом состоянии пометки.
**Ожидаемая обработка.** Обернуть тело транзакции в `Попытка/Исключение` с `ОтменитьТранзакцию` и проброс/логирование ошибки (канонический паттерн транзакций BSL). 🔴

## EC-05 — PassportBox недоступен или выключен

**Контекст.** Интеграция управляется константой `PassportBoxАктивность` + доступностью HTTP по IP/Порт.
**Поведение легаси.** `ПолучитьСоединениеПоНастройкам` возвращает структуру-ошибку при выключенной активности/недоступном сервисе; все исключения распознавания перехватываются и конвертируются в результат-ошибку, реквизиты клиента не меняются (flowchart Гости-ПолучитьРазворот23, п.5). 🟢
**Риск/проверка.** Молчаливый отказ распознавания может быть воспринят как «пустой паспорт»; таймаут (дефолт 30 c) блокирует форму.
**Ожидаемая обработка.** Явное сообщение оператору о причине (выключено / недоступно / таймаут); ручной ввод как fallback. 🟡

## EC-06 — Коллизия имени файла скана

**Контекст.** Имя приёмного файла = `<ГУИД клиента>_<имя>`.
**Поведение легаси.** При существующем файле с тем же именем суффикс авто-инкрементируется (`ПереместитьФайлВПутьДоФото`, `Module.bsl:141-188`). Оригинал копируется в архив и приёмник, затем удаляется. 🟢
**Риск/проверка.** Если запись в приёмник/архив частично прошла, а удаление оригинала — нет, возможны дубли файлов; путь пишется в ТЧ только после успешного переноса.
**Ожидаемая обработка.** Атомарность переноса (запись пути в ТЧ только при подтверждённом копировании); очистка оригинала в отдельном шаге с проверкой. 🟡
