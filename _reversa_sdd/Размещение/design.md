# Размещение и номерной фонд — Технический дизайн

> Файл `design.md`. Фокус — КАК устроен модуль, на основе прочитанного легаси-кода.
> Шкала доверия: 🟢 ПОДТВЕРЖДЕНО · 🟡 ВЫВЕДЕНО · 🔴 ПРОБЕЛ. Язык BSL — Russian, формат 1C:EDT.

## Interface / Интерфейс

### Структуры данных (реквизиты)

`Catalog.НомернойФонд` (иерарх., 2 ур., foldersOnTop; `Description` дл.25 обяз. `ShowError`; `Code` числовой авто, дл.9): 🟢

| Реквизит | Тип | Назначение |
|----------|-----|-----------|
| `Этаж` | Number(2) | Этаж |
| `КатегорияНомера` | CatalogRef.КатегорииНомеров | Категория |
| `Курящий`, `РаздельныеКровати`, `Балкон`, `Хостел`, `Коворкинг` | Boolean | Признаки-тумблеры |
| `ЦветНомераR/G/B` | Number(17) | Цвет фона строки шахматки |
| `ОписаниеНомера` | String(500) | Описание |
| `ОбщийКондиционер` | CatalogRef.НомернойФонд | Группировка комнат на 1 кондиционер |
| `ОсновнойНомер` | Number(10) | Связь с «основным» номером 🔴 (назначение не подтверждено) |
| `КатегорияХостел` | EnumRef.КатегорииХостела | Пол размещения М/Ж/О |
| `НомерГорничные` | String(50) | Код номера в системе горничных |
| ТЧ `Соседи.СоседнийНомер` | CatalogRef.НомернойФонд | Граф смежности комнат |

`Catalog.КатегорииНомеров` (иерарх., 2 ур.; `Description` дл.100 обяз.; `Code` строка дл.9; макет `МакетОсновной`): `Базовый`, `ТолькоОдноместный`, `Стандартный`, `Номер_пп`(Number) + 10 реквизитов `БазовыйТариф*` (Number(10,2)) — граница с Ценообразованием. 🟢

`InformationRegister.ЗанятостьНомеров` (`writeMode=RecorderSubordinate`, периодический): измерения `Номер`, `Клиент`, `ПериодРезерва`(Date,час), `Номер_пп`(Number); ресурсы `Зарезервирован`(Bool), `БонШанс`(Bool). 🟢

`InformationRegister.ЗамечанияПоНомерам` (регистратор `ОсмотрНомера`): измерения `Комната`, `Замечание`, `ВремяПроверки`, `Комментарий`, `Супервайзер`(Bool). 🟢

## Fluxo Principal / Основной поток

### Поток 1 — Построение шахматки `ВывестиШахматку` (`Интерфейс/.../Module.bsl:1096-1432`) 🟢
1. Очистка ТЗ шахматки; нормализация `ДатаС` (`НачалоДня` для «День», иначе `НачалоЧаса`).
2. Первый запрос РС `ЗанятостьНомеров` за период (`Зарезервирован=Истина`, статус ≠ `ОтказОтБронирования`) → ТЗ клиентов с колонкой `Цвет`.
3. Раскраска клиента по статусу (см. Алгоритм A).
4. Шапка: горизонтальная ось — дни (шаг 86400) или 6-часовые интервалы (шаг 3600·6); косметика метки «12:00»→«14:00».
5. Второй запрос РС `ЗанятостьНомеров` → данные ячеек (дубль запроса, 🟡 оптимизируемо).
6. `СпрНомеров = Справочники.НомернойФонд.Выбрать()` — перебор комнат, пропуск помеченных на удаление; каждая комната — строка.
7. Заголовок строки: `Наименование` + «/ РК» / «/ Б »; фон = `ЦветНомераR/G/B`; расшифровка ячейки заголовка = ссылка на номер.
8. Внутренний цикл по периодам: `НайтиСтроки({ПериодРезерва, Номер})` → закраска ячейки цветом клиента. 🟡 (детали закраски стр.1295-1432 — граница с Бронированием).
9. Вывести `ПолеОтчета`.

### Поток 2 — Проведение `ОсмотрНомера` (`ObjectModule.bsl:2-28`) 🟢
1. Если ТЧ `Замечания` пуста → одна запись РС `ЗамечанияПоНомерам` с `Замечание = Справочники.Замечания.Нет`.
2. Иначе цикл по строкам ТЧ → запись на каждое замечание.
3. Каждая запись: `Комната←Комната`, `ВремяПроверки←Дата`, `Комментарий←Комментарий`, `Супервайзер←ПостПроверка`.
4. При отмене проведения движения удаляются автоматически (`registerRecordsDeletion=AutoDelete`).
> Код сгенерирован «Конструктором движений регистров» (`__КОНСТРУКТОР_ДВИЖЕНИЙ_РЕГИСТРОВ`); транзакция/обработка исключений — стандартное автопроведение платформы. 🟡

### Поток 3 — Зеркало номера в БД горничных (`ObjectModule.bsl:2-55`) 🟢
1. `ПередЗаписью`: сохранить старое `НомерГорничные` из `Ссылка.НомерГорничные`.
2. `ОбновитьГорничныеНомера(старое, ЭтотОбъект)`: выбрать объект `ГорничныеНомера` (по старому реквизиту → по новому → создать), перезаписать поля, `Записать()`. 🔴 без транзакции/обработки исключения.
3. Если `Константа.ОбменСГорничными = Ложь` ИЛИ нет `Папка_Горничные` → выход.
4. Иначе COM-соединение `ОбменГорничныеСервер.Соединение()` → `Соединение.ОбменГорничныеСервер.ОбновитьНомерГорничные(...)`. Ошибка подавляется `Попытка/Сообщить`.

### Поток 4 — COM-импорт номеров (`ЗагрузкаНомеров*/.../Module.bsl`) 🟢
1. Сформировать строку подключения (🔴 хардкод File/Usr/Pwd).
2. `Новый COMОбъект("V83.COMConnector")` → `Connect(строка)`; неуспех → `Сообщить` + выход.
3. `База.NewObject("Запрос")`, текст: `ВЫБРАТЬ … ИЗ Справочник.НомернойФонд ГДЕ ПометкаУдаления=ЛОЖЬ` → `Выполнить().Выгрузить()` → ТЗ.
4. Цикл по строкам ТЗ: `НайтиПоКоду(Код)` локально; найден → пропуск; нет → `СоздатьЭлемент`, заполнить реквизиты, категорию (`КатегорииНомеров.НайтиПоКоду(КатегорияНомера.Код)`), `КатегорияХостел` через `ИмяЗначенияПеречисление` (в `Попытка`), `Записать()`.
5. Отдельные команды: `ЗагрузитьКатегорииНомеров` (категории по коду), `ЗагрузитьДанныеНомеров` (`ОбщийКондиционер` + ТЧ `Соседи`).

### Поток 5 — Замена номера в заявках (`ЗаменаНомеровВЗаявках/.../Module.bsl:3-29`) 🟢
1. `Заменить` (клиент): проверить заполнение `СтарыйНомер`/`НовыйНомер`.
2. `ЗаменитьНаСервере`: `Документы.ЗаявкаНаБронирование.Выбрать()` — перебор ВСЕХ; для строк с `НомерВРезерв=СтарыйНомер` подмена → `Записать(РежимЗаписиДокумента.Проведение)` с подавлением ошибки. 🔴 полный перебор без отбора, перепроведение каждого.

## Fluxos Alternativos / Альтернативные потоки

- **Осмотр без замечаний:** ровно 1 запись РС с предопределённым `Замечания.Нет` (RM-02). 🟢
- **Обмен с горничными отключён:** при `ОбменСГорничными=Ложь`/нет папки — COM-обмен пропускается, локальная запись проходит. 🟢
- **Категория не найдена при импорте:** `НайтиПоКоду` вернёт пустую ссылку → номер создаётся без категории (категория не догружается основной командой). 🟡
- **Имя значения enum не совпало:** `Перечисления.КатегорииХостела[имя]` в `Попытка` → значение остаётся пустым (подавление). 🟢
- **COM-база недоступна:** `Connect` неуспешен → сообщение + выход без изменений. 🟢
- **Баг соседей (Лайв/Чехов):** соседи не записываются из-за опечатки (см. edge-cases.md, questions.md). 🔴

## Dependências / Зависимости

- **Бронирование** — записывает РС `ЗанятостьНомеров`/`ПроданныеНомера`; формирует почасовой период (`ДокументыСервер.ЗанятостьНомераПериодРезерва` / `ЗанятостьНомераПроверить`). Шахматка только ЧИТАЕТ эти регистры. 🟢
- **Горничные** — внешняя БД 1С по COM (`ОбменГорничныеСервер.*`), справочник `ГорничныеНомера`; зеркало карточки номера. 🟢
- **Ценообразование** — `БазовыйТариф*` в `КатегорииНомеров` потребляются расчётом проживания. 🟡
- **Интеграции** — `КатегорииНомеровСайт` питает маппинг при импорте брони с сайта. 🟡
- **Коворкинг** — только признак `Коворкинг`; собственная шахматка/занятость ВНЕ модуля. 🟢
- **ОбщийФункционалСервер** — `ПолучитьЦветТекстаПоЦветуФона` (подбор цвета текста на шахматке). 🟢
- **Внешняя интеграция (COM, описана здесь, не отдельным contracts.md):** загрузчики `V83.COMConnector` к внешним базам 1С (Лайв/Реноме/Чехов) — контракт = запрос `Справочник.НомернойФонд`/`КатегорииНомеров` из удалённой базы; реквизиты переносятся по совпадению имён/кодов. 🟢

## Decisões de Design Identificadas / Выявленные решения

| Решение | Доказательство | Доверие |
|---------|---------------------|-----------|
| Здания/блоки — иерархия `НомернойФонд`, этаж — реквизит (нет отдельных Корпус/Здание) | `НомернойФонд.mdo` (hierarchical) | 🟢 (ADR/RM-03) |
| Почасовая модель занятости (1 запись РС на час), читается шахматкой | `InformationRegisters/ЗанятостьНомеров.mdo`; ADR 0002 | 🟢 |
| Денормализованный цвет номера `ЦветНомераR/G/B` для шахматки | `НомернойФонд.mdo` | 🟢 |
| Импорт номеров через отдельные базы 1С по синхронному COM | загрузчики; ADR 0005 | 🟢 |
| Резолв enum между базами рефлексией метаданных по индексу | `ИмяЗначенияПеречисление` | 🟢 |
| Зеркалирование номера в БД горничных при записи | `НомернойФонд/ObjectModule.bsl`; ADR 0005 | 🟢 |
| RBAC в коде через флаг `Админ` (в шахматке частично закомментирован) | `Интерфейс/.../Module.bsl`; ADR 0010 | 🟡 |

## Estado Interno / Внутреннее состояние

- `ЗанятостьНомеров` — основной «слой» доступности комнаты (часовой срез); шахматка строит из него визуальную ТЗ. 🟢
- `ЗамечанияПоНомерам` — журнал замечаний (подчинён `ОсмотрНомера`); движения авто-удаляются при отмене проведения. 🟢
- `ПроданныеНомера` — факт продажи комнаты (подчинён `ЗаявкаНаБронирование`); содержит устаревшие ресурсы `Тариф_НеИспользуется`/`ТарифКоррекция` (🔴). 🟢
- Карточка номера хранит денормализованные визуальные (цвет) и интеграционные (`НомерГорничные`) поля. 🟢

## Observabilidade / Наблюдаемость

- Ошибки COM-импорта и зеркалирования выводятся через `Сообщить(...)`; структурного логирования (ЖР) в прочитанных фрагментах нет. 🟡
- Шахматка не логирует; результат — табличный документ `ПолеОтчета`. 🟢

## Riscos e Lacunas / Риски и пробелы

- 🔴 Хардкод COM-кредов/путей в загрузчиках (`Pwd="123"`, `D:\DB`, `C:\_Base1C`).
- 🔴 Баг соседей в Лайв/Чехов: цикл по `ТЗ.Соседи` вместо `Строка.Соседи`, присваивание без точки (`НоваяСтрокаСоседиСоседнийНомер`) — соседи не пишутся; в Реноме исправлено.
- 🔴 Отсутствуют сущности Корпус/Здание/Помещение — здания эмулируются иерархией.
- 🔴 Зеркало в БД горничных пишется без транзакции/обработки исключения внутри метода.
- 🔴 Дубли `_OLD`/`_Исходный`/`_Старая` и мёртвые `__`-методы в шахматке.
- 🟡 Внутренний цикл закраски ячеек (`:1295-1432`) не прочитан полностью — граница с Бронированием.
- 🟡 Назначение `ОсновнойНомер` не подтверждено.
- 🟡 Дубль-запрос РС в шахматке — потенциальная оптимизация.
