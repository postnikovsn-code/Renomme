## Обзор

Модуль ведёт центральную сущность гостя/контрагента (`Catalog.Клиенты`, ~130 реквизитов + 5 ТЧ) и весь жизненный цикл вокруг неё: классификацию (виды/категории клиентов), контактную информацию и адреса, анкетирование, распознавание паспортов через внешний HTTP-сканер PassportBox, выгрузку проживающих в миграционную службу (ФМС, CSV `#v.2.0.0`), дедупликацию и объединение клиентов, загрузку сканов документов и отбор именинников среди проживающих. 🟢

## Ответственности

- Ведение карточки клиента (физ/юрлицо) с антидублем при записи. 🟢
- Классификация клиента: тип (`Enum.ТипыКлиентов`), вид (`Catalog.ВидыКлиентов`), категория со скидкой (`Catalog.КатегорииКлиентов`). 🟢
- Хранение контактной информации, адресов (`Catalog.Адреса`, `Catalog.Города`, ТЧ `КонтактнаяИнформация`/`ПрочаяИнформация`). 🟢
- Анкетирование гостя (`Document.Анкета`, `Document.АнкетаНовая`, шаблоны `Catalog.АнкетаВопросы`/`Catalog.ВопросыАнкеты`). 🟢
- Распознавание паспорта/регистрации через PassportBox (мультиисточник page3 < OCR < MRZ). 🟢
- Формирование файла миграционного учёта для ФМС (CSV ~94 поля, ветвление иностранец/РФ). 🟢
- Дедупликация клиентов по ИНН (юрлица) и каскадное объединение клиентов. 🟢
- Загрузка сканов документов из файловой папки в карточку клиента. 🟢
- Отбор именинников среди проживающих гостей. 🟢
- Денормализация истории броней клиента (`InformationRegister.ИсторияКлиента`, запись ведёт модуль Бронирование; здесь — чтение и перенос при объединении). 🟡

## Бизнес-правила

- **GR-01** Антидубль клиента перед записью — 3 ступени: по наименованию (для физлиц авто-сборка из Фамилия+Имя+Отчество) → по ИНН+КПП (если ИНН ≠ пусто/«0») → `ДокументыСервер.ПроверитьКонтрагента`. При дубле запись отменяется, открывается карточка существующего (`ФормаЭлемента/Module.bsl:263-308`). 🟢
- **GR-02** Вид клиента «Исключить из отчётов» отключает антидубль по наименованию. 🟡
- **GR-03** `ГУИД_ИсточникОбмена` присваивается из `Ссылка.УникальныйИдентификатор()` при первой записи, если пуст (ключ интеграции/обмена) (`ObjectModule.bsl:3-7`). 🟢
- **GR-04** Распознавание паспорта: 3 источника по приоритету `page3 < OCR < MRZ`; непустое более приоритетное перезаписывает менее приоритетное, пустое не перезаписывает никогда; ФИО приводится `ТРег` (сканер отдаёт прописными); 9 обязательных полей паспорта / 6 регистрации; обязательно фото page3 (`PassportBoxВызовСервера/Module.bsl:50-92,418-496`). 🟢
- **GR-05** Выгрузка ФМС ветвится по `ИностранныйГражданин`: для россиян гражданство `RUS`, тип документа `103008`, поля визы/пребывания/миграционной карты пустые (`ВыгрузкаДляФМС/Forms/Форма/Module.bsl:138-429`). 🟢
- **GR-06** Дедупликация по ИНН охватывает ТОЛЬКО юрлиц (`ТипКлиента = ЮрЛицо`, `Количество > 1`); дубли физлиц автоматически не выявляются (`КлиентыДвойныеИНН/Forms/Форма/Module.bsl:22-143`). 🟢
- **GR-07** При объединении клиентов исходный помечается на удаление ТОЛЬКО при отсутствии ссылок (`НайтиПоСсылкам`); замена каскадная во всех заявках/счетах/выписках/регистрах (`КлиентыОбъединиение/.../Module.bsl:224-417`). 🟢
- **GR-08** Именинник среди проживающих — если день/месяц рождения попадает в интервал `[РезервС; РезервПо]` активной брони (`Статус = Проживает`); учитываются и `Клиент`, и `Клиент2` (`ДниРождения/Forms/Форма/Module.bsl:11-102`). 🟢
- **GR-09** Полиморфный резолвер пункта выдачи документа ФМС: Строка → как есть; `СправочникСсылка.ПунктыВыдачиФМС_NEW` → `Формат(.ID, "ЧГ=")`; иначе пусто (`ВыгрузкаДляФМС/.../Module.bsl:432-442`). 🟢
- **GR-10** Выбор пункта выдачи паспорта по коду органа: при нескольких записях сортировка по `КонечнаяДата` убыв., выбирается запись, актуальная на `ДатаВыдачи` (`КлиентыСервер.ПунктыВыдачиФМС:22-89`). 🟢
- **GR-11** Загрузка скана: имя приёмного файла = `<ГУИД клиента>_<имя>` с авто-инкрементом суффикса при коллизии; оригинал копируется в архив и приёмник, затем удаляется; путь пишется в ТЧ `СканыДокументов` (`ЗагрузкаСканов/.../Module.bsl:141-188`). 🟢
- **GR-12** Парсер даты PassportBox `СтрокаВДату`: формат "ДД.ММ.ГГГГ"/"ДД.ММ.ГГ", убирает точки/время, переставляет в "ГГ[ГГ]ММДД", дополняет век "20" при 6 знаках (`PassportBoxВызовСервера/Module.bsl:214-229`). 🟢
- **GR-13** Признак ФМС `АдресРегистрацииОтсутствует` для иностранного гражданина в выгрузке всегда трактуется как True. 🟡
- **GR-14** Источник строк выгрузки ФМС: брони с `ВремяЗаездаТочное` = дата заезда; для `Клиент` и (если задан) `Клиент2` формируются отдельные строки. 🟢
- 🔴 Точная семантика незавершённой миграции реквизитов `_NEW`/`_OLD` (`ГражданствоФМС_NEW`, `ТипДокументаФМС_NEW`, `ПроцентАгент_OLD`, `Тариф_НеИспользуется`) — какая модель актуальна, не подтверждено. 🔴
- 🔴 Происхождение и стабильность магического числа типа документа `103008` (паспорт РФ) не подтверждены классификатором. 🔴
- 🔴 Логика заполнения `Document.АнкетаНовая` (5 ТЧ ответов ПХУП/Текст/ДаНет/ТаблицаДаНет) детально не разбиралась. 🔴

## Критерии приёмки

```gherkin
# RF-01 / GR-01 — антидубль (happy + failure)
Дано новый клиент-физлицо с Фамилия/Имя/Отчество, совпадающими с существующим
Когда оператор сохраняет карточку
Тогда запись отменяется и открывается карточка существующего клиента

Дано новый уникальный клиент-физлицо
Когда оператор сохраняет карточку
Тогда карточка записывается и ей присваивается ГУИД_ИсточникОбмена

# RF-04 / GR-04 — распознавание паспорта
Дано включённый PassportBox и корректный разворот 2-3 паспорта РФ под сканером
Когда оператор запускает «Сканировать разворот паспорта»
Тогда заполнены 9 обязательных полей паспорта и получено фото 3-й страницы

Дано разворот, где сканер не вернул номер паспорта
Когда оператор запускает распознавание
Тогда возвращается ошибка «Страница не распознана» и реквизиты не записываются

Дано под сканером документ с doc_type ≠ rus.passport.national
Когда оператор запускает распознавание паспорта
Тогда возвращается ошибка «Неверный тип документа»

# RF-08/RF-09 / GR-05 — выгрузка ФМС
Дано проживающий гражданин РФ с заполненным паспортом
Когда формируется строка ФМС
Тогда гражданство = RUS, тип документа = 103008, поля визы/мигркарты пустые

Дано проживающий иностранный гражданин с визой и миграционной картой
Когда формируется строка ФМС
Тогда гражданство = CODE_ALPHA3 страны, тип документа = ID из ТипДокументаФМС_NEW, поля визы/мигркарты заполнены

Дано каталог ПАПКА_ВыгрузкаДляФМС недоступен/не задан
Когда оператор запускает выгрузку
Тогда файл не создаётся и выводится сообщение об ошибке записи

# RF-12 / GR-07 — объединение клиентов
Дано два клиента-дубля, один выбран как результат
Когда оператор подтверждает объединение
Тогда все ссылки переведены на результат, исходный помечен на удаление (если ссылок не осталось)

Дано на исходного клиента остались ссылки, не покрытые заменой
Когда выполняется объединение
Тогда исходный НЕ помечается на удаление и выводится сообщение про оставшиеся ссылки

# RF-13 / GR-08 — именинники
Дано активная бронь (Статус=Проживает) клиента, чей день/месяц рождения попадает в период проживания
Когда формируется список именинников
Тогда клиент присутствует в списке (для Клиент и Клиент2)
```

## Приоритизация (MoSCoW)

| Требование | MoSCoW | Обоснование |
|-----------|--------|-------------|
| Антидубль клиента при записи (RF-01/02) | Must | Критический путь любой записи карточки, нет fallback |
| `ГУИД_ИсточникОбмена` при записи (RF-03) | Must | Ключ интеграции/обмена, используется несколькими модулями |
| Распознавание паспорта (RF-04/06/07) | Must | Ключевая фича домена, вызывается с формы клиента |
| Выгрузка ФМС с ветвлением (RF-08/09) | Must | Регуляторное требование, нет альтернативы |
| Каскадное объединение клиентов (RF-12) | Must | Целостность ссылочных данных при дедупликации |
| Распознавание регистрации (RF-05), резолвер ФМС (RF-10), дедуп ИНН (RF-11), загрузка сканов (RF-14), валидации (RF-15/16), настройки (RF-17) | Should | Важно, но есть ручные альтернативы |
| Именинники (RF-13) | Could | Вспомогательный сервис, срабатывает редко |
| Реквизиты `_OLD`, `ВыгрузкаДляФМС_Исходная`, `ПечатьУведомления_Старое` | Won't | Мёртвые/дублирующие копии (см. questions.md) |

> Приоритет выведен по частоте вызова и позиции в цепочке зависимостей.
