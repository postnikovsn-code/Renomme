# Подключаемое оборудование (БПО) — Требования

> ⚠️ **Повторное извлечение №1 (2026-06-18, коммит «Изменения ПСН» c52a282):** дельта спецификаций этого модуля — в [../re-extraction/2026-06-18-ПСН/specs-delta.md](../re-extraction/2026-06-18-ПСН/specs-delta.md). При расхождении смотри дельту.

> Спецификация **точек интеграции** гостиничного домена «ОТЕЛЬ» с типовой
> «Библиотекой подключаемого оборудования» (БПО, ред. 3.2).
> Шкала уверенности: 🟢 подтверждено в коде · 🟡 выведено · 🔴 пробел/требует валидации.

## Граница ответственности (читать первым)

> **🟢 ТИПОВАЯ БИБЛИОТЕКА БПО ред. 3.2 — НЕ МОДИФИЦИРУЕТСЯ.**
> Подсистема `ПоддержкаОборудования` (255 объектов метаданных, ~98 общих модулей,
> 63 шаблона-драйвера) — встроенная сторонняя библиотека. Её контракт (фасады
> `МенеджерОборудования*`, `ОборудованиеЧекопечатающиеУстройства*`,
> `ОборудованиеПлатежныеСистемы*`, `РаспределеннаяФискализация*`,
> `РассылкаЭлектронныхЧеков*` и др.) считается **стабильным**. Внутренности драйверов,
> протоколов устройств, фискализации на уровне ФН, ФЛК/ИСМ/ЕГАИС — **чёрная коробка**
> (ADR-0006). 🟢
>
> Эта спецификация описывает **только то, что добавляет/использует домен «ОТЕЛЬ»**:
> доменные обёртки `ФУ_Клиент`/`ФУ_Сервер`/`ОплатыЧекКлиент`/`СерверККМ`,
> внешний HTTP «Сервер ККМ», регистрацию драйвера АТОЛ, и доменное расширение
> «телеметрия датчиков» (`Catalog.Датчики`, `Document.ПоказанияДатчиков`).

## Visão Geral

Модуль обеспечивает фискальную и платёжную периферию гостиницы: подключение ККТ/драйверов
к рабочим местам, пробитие фискальных чеков (4 способа), открытие/закрытие кассовой смены,
рассылку электронных чеков и снятие показаний датчиков номеров. Реализован поверх типовой
БПО: домен собирает позиции/оплаты чека и параметры операции, библиотека выполняет
собственно фискализацию. 🟢

## Responsabilidades (со стороны домена)

- Подключение/отключение устройства к текущему рабочему месту при открытии/закрытии формы кассы (`ФУ_Клиент.ПриОткрытии_Подключить` / `ПриЗакрытии_Отключить`). 🟢
- Сборка позиций и оплат фискального чека из доменных данных (проживание/допуслуги/коворкинг/аванс) — `ОплатыЧекКлиент`. 🟢
- Делегирование пробития чека библиотеке одним из 4 способов фискализации. 🟢
- Открытие/закрытие/инкассация кассовой смены (`ФУ_Клиент`, `СерверККМ`, `Document.КассоваяСмена`). 🟢
- Подготовка реквизитов фискализации (организация/кассир/СНО) — `ФУ_Сервер`. 🟢
- Постановка электронных чеков в очередь и регламентная рассылка. 🟢
- Регистрация драйвера АТОЛ (`DataProcessor.АТОЛ10106`). 🟢
- Проведение документа показаний датчиков в РС `ПоказанияДатчиков` (доменное расширение). 🟢

## Regras de Negócio

- Признак `ФУ_Сервер.ЭтоСерверККМ()` переключает фискализацию домена на внешний HTTP «Сервер ККМ» вместо локальной ККТ. 🟢
- Сосуществуют 4 способа фискализации: локальная ККТ / Сервер ККМ (HTTP) / облачная ККТ / распределённая очередь (`РС ОчередьЧековККТ`). 🟢 (см. ADR-0006, EQ-02)
- Привязка «устройство → рабочее место» определяется через `Catalog.РабочиеМеста` + `SessionParameter.РабочееМестоКлиента`. 🟢
- Режим отправки электронного чека (сразу/отложенно через очередь) управляется константой `ОтправкаЭлектронныхЧековПослеПробитияЧека`. 🟢
- Подключение/отключение оборудования и пробитие чека — **асинхронные** (callback-стиль `ОписаниеОповещения`); результат обрабатывается в процедуре-завершении (`ОперацияЗавершение`, `ПодключитьОтключитьОборудованиеЗавершение`). 🟢
- Историю операций (`ФискальныеОперации`, `ПлатежныеОперации`, `ОперацииПроверкиКМ`, `ОчередьЧековККТ`, `ОперацииСПодключаемымОборудованием`) чистит регламент по срокам хранения из одноимённых констант. 🟢
- HTTP-соединение с Сервером ККМ авторизуется токеном; токен обновляется при истечении `ВремяИстечения < ТекущаяДата()`; ответ успешен при `Result.Code = 0`. 🟢
- `СерверККМ.СоздатьСоединение` имеет дефолтные `ИмяПользователя="Admin"`, `ПарольПользователя="Admin"`. 🔴 (потенциальный хардкод — см. questions.md Q-01)
- Документ `ПоказанияДатчиков` при проведении пишет по одной записи РС на каждую строку ТЧ; источник наполнения ТЧ вне модуля проведения. 🟢 / 🔴 (источник — Q-02)
- Маркированная продукция: при наличии КМ чек проходит проверку через `МенеджерОборудованияМаркировка*`/ФЛК (внутри библиотеки). 🟡

## Critérios de Aceitação

```gherkin
# Пробитие чека — happy path (локальная ККТ)
Dado оператор на форме кассы с подключённым ККТ текущего рабочего места
Quando он подтверждает оплату по счёту гостя
Então ОплатыЧекКлиент собирает позиции и оплаты чека
  E ОборудованиеЧекопечатающиеУстройстваКлиент.НачатьПробитиеЧека вызывается с параметрами фискализации
  E ФУ_Клиент.ОперацияЗавершение получает успешный результат
  E операция фиксируется в РС ФискальныеОперации

# Пробитие чека — Сервер ККМ (happy path)
Dado ФУ_Сервер.ЭтоСерверККМ() = Истина и доступный HTTP «Сервер ККМ»
Quando оператор пробивает чек
Então СерверККМ.ВыполнитьЗапрос отправляет JSON на /PrintService/api/v2/
  E ответ имеет Result.Code = 0
  E чек считается пробитым

# Failure — устройство недоступно / не подключено
Dado оборудование текущего РМ не подключилось при открытии формы
Quando оператор пытается пробить чек
Então операция возвращает ошибку (Результат с признаком ошибки)
  E пользователю показывается сообщение
  E факт пишется в РС ОперацииСПодключаемымОборудованием

# Failure — Сервер ККМ недоступен / ошибка запроса
Dado ЭтоСерверККМ() = Истина, но HTTP-сервер недоступен или вернул Code <> 0
Quando оператор пробивает чек
Então функция СерверККМ.* возвращает структуру {Ошибка=Истина, Описание=<текст>}
  E чек не считается пробитым
  E ошибка фиксируется (ФУ_Сервер.ЗаписатьОшибкуКММ)

# Failure — оффлайн-фискализация (ККТ оффлайн)
Dado локальная ККТ недоступна, но настроена распределённая фискализация
Quando оператор пробивает чек
Então чек ставится в РС ОчередьЧековККТ
  E будет фискализирован при восстановлении связи (распределённая фискализация)

# Открытие кассовой смены — happy path
Dado смена закрыта (SessionState=1 для Сервера ККМ)
Quando оператор открывает смену
Então ФУ_Клиент.ОткрытьСмену / СерверККМ.ОткрытьСмену выполняется успешно
  E Document.КассоваяСмена отражает открытую смену

# Электронный чек — отложенная рассылка
Dado константа ОтправкаЭлектронныхЧековПослеПробитияЧека выключена
Quando чек пробит и указан контакт получателя
Então создаётся запись Catalog.ОчередьЭлектронныхЧековКОтправке
  E ScheduledJob.РассылкаЭлектронныхЧеков отправляет чек на следующем запуске

# Показания датчиков
Dado документ ПоказанияДатчиков с заполненной ТЧ Датчики
Quando документ проводится
Então на каждую строку ТЧ создаётся запись РС ПоказанияДатчиков (НомерКадра, Время, Датчик, Показатель)
```

## Prioridade (MoSCoW)

| Requisito | MoSCoW | Justificativa |
|-----------|--------|---------------|
| Пробитие фискального чека (RF-02..RF-04) | Must | Критический путь оплаты, 54-ФЗ |
| Подключение оборудования к РМ (RF-01) | Must | Без подключения нет фискализации |
| Открытие/закрытие смены (RF-06) | Must | Обязательное условие пробития чеков |
| Реквизиты фискализации (RF-08) | Must | Без организации/кассира чек невалиден |
| Облачная/распределённая фискализация (RF-05) | Should | Альтернатива при оффлайне локальной ККТ |
| Инкассация/отчёт без гашения (RF-07) | Should | Важно, но не на каждом чеке |
| Очередь и рассылка эл. чеков (RF-09) | Should | Есть режим «сразу» как альтернатива |
| Показания датчиков (RF-11) | Should | Доменное расширение, не блокирует кассу |
| Регистрация драйвера АТОЛ (RF-10) | Could | Разовая настройка |
| Служебная печать текста (RF-12) | Could | Вспомогательная операция |
| `DataProcessor.ПечатьУведомления_OLD` | Won't | Устаревшая версия (tech-debt) |

> Приоритет выведен по частоте вызова и позиции в цепочке зависимостей.
