# Размещение и номерной фонд

> Файл `requirements.md`. Фокус — ЧТО делает модуль, а не как.
> Шкала доверия: 🟢 ПОДТВЕРЖДЕНО кодом · 🟡 ВЫВЕДЕНО · 🔴 ПРОБЕЛ (нужна человеческая валидация).
> Уровень детализации: detalhado. Язык: Русский.

## Visão Geral / Обзор

Модуль управляет **номерным фондом** гостиницы «ОТЕЛЬ»: карточками комнат, их категориями/типами, иерархией зданий и этажей, графом смежности (соседи, общий кондиционер), а также визуализацией размещения — **шахматкой** (сетка «комната × время»). Сюда же входят документ `ОсмотрНомера` (регистрация замечаний), массовая замена комнаты в заявках брони, COM-загрузка номеров из внешних баз (Лайв/Реноме/Чехов) и зеркалирование карточки номера во внешнюю БД горничных.

Регистры `ЗанятостьНомеров` / `ПроданныеНомера` описаны здесь как **структуры данных** номерного фонда; логика их записи (формирование почасового резерва, проверка пересечений) принадлежит модулю **Бронирование** — здесь модуль их только читает (шахматка). 🟢

## Responsabilidades / Ответственности

- Хранить карточку комнаты (`Catalog.НомернойФонд`): этаж, категория, цвет, признаки (балкон, курящий, хостел, коворкинг, раздельные кровати), соседи, общий кондиционер. 🟢
- Моделировать здания/блоки иерархией справочника `НомернойФонд` (2 уровня, папки сверху), этаж — числовым реквизитом. 🟢
- Хранить категории/типы номеров (`Catalog.КатегорииНомеров`) и сопоставление категорий внешнего сайта (`Catalog.КатегорииНомеровСайт`). 🟢
- Строить **шахматку размещения**: сетка «номер × время» с раскраской ячеек по статусу брони/цвету клиента и раскраской строк по собственному цвету номера (`DataProcessor.Интерфейс`). 🟢
- Регистрировать осмотр комнаты с замечаниями (`Document.ОсмотрНомера` → РС `ЗамечанияПоНомерам`). 🟢
- Выполнять массовую замену комнаты во всех заявках брони (`DataProcessor.ЗаменаНомеровВЗаявках`). 🟢
- Импортировать номера/категории из внешних баз 1С по COM (`ЗагрузкаНомеровЛайв/Реноме/Чехов`). 🟢
- Поддерживать зеркало карточки номера во внешней БД горничных при записи (`НомернойФонд.ObjectModule.ПередЗаписью` + `ОбновитьГорничныеНомера`). 🟢 (граница с модулем Горничные)

## Regras de Negócio / Бизнес-правила

- **RM-01.** При записи номера его карточка зеркалируется во внешнюю БД горничных ТОЛЬКО если `Константа.ОбменСГорничными = Истина` И задана `Константа.Папка_Горничные`; иначе — выход без обмена. 🟢 (`НомернойФонд/ObjectModule.bsl:2-27`)
- **RM-02.** Проведение осмотра без замечаний (пустая ТЧ `Замечания`) формирует ОДНУ запись РС `ЗамечанияПоНомерам` с предопределённым `Замечание = Справочники.Замечания.Нет`; с замечаниями — по одной записи на каждую строку ТЧ. 🟢 (`ОсмотрНомера/ObjectModule.bsl:2-28`)
- **RM-03.** Здания/блоки моделируются ИЕРАРХИЕЙ `НомернойФонд` (отдельных сущностей Корпус/Здание/Помещение НЕТ); этаж — числовой реквизит `Этаж`. 🟢🔴 (`НомернойФонд.mdo`; отсутствие сущностей — см. questions.md)
- **RM-04.** Приоритет цвета ячейки шахматки: `Проживает` → белый (255,255,255); `Выехал` → серо-бежевый (231,227,217); `ОтказОтБронирования` → тёмный лосось (233,150,122); иначе цвет регистратора → цвет клиента → случайный неконфликтный цвет. 🟢 (`Интерфейс/Forms/Форма/Module.bsl:1124-1140`)
- **RM-05.** Шахматка перебирает все комнаты `Справочники.НомернойФонд.Выбрать()`, ПРОПУСКАЯ помеченные на удаление; каждая комната = строка. 🟢 (`Интерфейс/.../Module.bsl:1096-1432`)
- **RM-06.** Заголовок строки шахматки = `Наименование` + « / РК» (если `РаздельныеКровати`) + «/ Б » (если `Балкон`); фон строки = собственный цвет номера `ЦветНомераR/G/B` (если сумма ≠ 0), цвет текста подбирается по фону. 🟢 (`:1096-1432`)
- **RM-07.** Шаг горизонтальной оси шахматки: 86400 сек для детализации «День», иначе 3600·6 (6-часовые интервалы); косметическая замена метки «12:00» → «14:00». 🟢 (`ВывестиШахматку`, `ВывестиШахматкуЧасы`)
- **RM-08.** Импорт номеров идемпотентен по коду: создаются только ОТСУТСТВУЮЩИЕ номера/категории (`НайтиПоКоду`); существующие основной командой не обновляются. 🟢 (`ЗагрузкаНомеров*/Module.bsl:57`)
- **RM-09.** При импорте категория номера сопоставляется по коду (`КатегорииНомеров.НайтиПоКоду(Код)`); значение перечисления `КатегорииХостела` резолвится рефлексией метаданных внешней базы по индексу (`ИмяЗначенияПеречисление`), несовпадение имени подавляется в `Попытка`. 🟢
- **RM-10.** Замена номера в заявках: перебор ВСЕХ `Документы.ЗаявкаНаБронирование.Выбрать()`; для строк ТЧ с `НомерВРезерв = СтарыйНомер` — подмена на `НовыйНомер` и `Записать(РежимЗаписиДокумента.Проведение)` с подавлением ошибки. 🟢 (`ЗаменаНомеровВЗаявках/Module.bsl:11-29`)
- **RM-11.** ТЧ `Соседи` (`СоседнийНомер`) и `ОбщийКондиционер` образуют граф смежности комнат (соседство + группировка на один кондиционер). 🟢
- **RM-12.** Признак `Коворкинг` на номере — единственная связь с модулем Коворкинг; сам коворкинг (шахматка/занятость) ВНЕ этого модуля. 🟢
- **RM-13.** В коде шахматки исторические проверки доступа `Если ... Админ` ЗАКОММЕНТИРОВАНЫ — защита местами фактически снята. 🟡 (`permissions.md`; ADR 0010)
- 🔴 **RM-GAP-1.** Бизнес-смысл реквизита `ОсновнойНомер` (Number) — связь со «основным» номером (слияние/составные номера) — не подтверждён кодом. (`data-dictionary`, 🟡→🔴)

## Requisitos Funcionais / Функциональные требования

| ID | Требование | Приоритет | Критерий приёмки |
|----|-----------|-----------|-------------------|
| RF-01 | Хранить карточку комнаты со всеми реквизитами и ТЧ `Соседи` | Must | Создать/прочитать номер с этажом, категорией, признаками, соседями; обязателен `Description` (`ShowError`) |
| RF-02 | Моделировать здания/этажи иерархией `НомернойФонд` | Must | Папка-здание содержит комнаты; `Этаж` числовой; нет отдельного справочника зданий |
| RF-03 | Хранить категории номеров и базовые тарифы | Must | Категория с `Code` (строка, дл.9), `Description` (дл.100, обяз.), 10 базовых тарифов |
| RF-04 | Сопоставлять категорию сайта с внутренней | Should | Запись `КатегорииНомеровСайт` маппит строковый код сайта → `CatalogRef.КатегорииНомеров` |
| RF-05 | Строить шахматку «номер × время» (день/6 часов) | Must | Сетка рисуется по периоду и детализации; строки = комнаты, колонки = время |
| RF-06 | Раскрашивать ячейки шахматки по статусу/цвету клиента | Must | Цвет ячейки соответствует приоритету RM-04 |
| RF-07 | Раскрашивать строки шахматки по цвету номера + метки РК/Б | Should | Фон строки = `ЦветНомераR/G/B`; суффикс « / РК», «/ Б » по признакам |
| RF-08 | Проводить осмотр номера с регистрацией замечаний | Must | Проведение пишет РС `ЗамечанияПоНомерам` по RM-02 |
| RF-09 | Массово заменять комнату во всех заявках брони | Should | Указать `СтарыйНомер`/`НовыйНомер`; заявки перепроводятся с подменой |
| RF-10 | Импортировать номера/категории из внешней базы по COM | Could | Команда создаёт отсутствующие номера/категории по коду |
| RF-11 | Импортировать связи номера (общий кондиционер, соседи) | Could | `ЗагрузитьДанныеНомеров` заполняет `ОбщийКондиционер` и ТЧ `Соседи` |
| RF-12 | Зеркалировать карточку номера в БД горничных | Should | При `ОбменСГорничными=Истина` и заданной папке карточка пишется во внешнюю базу |

## Critérios de Aceitação / Критерии приёмки

```gherkin
# RF-08 — Осмотр номера (happy path: без замечаний)
Dado документ ОсмотрНомера с заполненной Комнатой и пустой ТЧ Замечания
Quando документ проводится
Então в РС ЗамечанияПоНомерам создаётся ровно ОДНА запись
  И поле Замечание = Справочники.Замечания.Нет
  И ВремяПроверки = Дата документа, Супервайзер = значение ПостПроверка

# RF-08 — Осмотр номера (с замечаниями)
Dado документ ОсмотрНомера с 3 строками в ТЧ Замечания
Quando документ проводится
Então в РС ЗамечанияПоНомерам создаётся 3 записи (по одной на строку)
  И при отмене проведения движения удаляются автоматически (registerRecordsDeletion=AutoDelete)

# RF-06 — Раскраска ячейки шахматки (happy path)
Dado бронь со статусом Проживает на пересечении (Номер, ПериодРезерва)
Quando строится шахматка за период, покрывающий этот час
Então ячейка (Номер × час) закрашивается белым (255,255,255)

# RF-06 — Раскраска при отказе от брони (граничный статус)
Dado бронь со статусом ОтказОтБронирования
Quando строится шахматка
Então запрос РС исключает такие записи (статус ≠ ОтказОтБронирования)
  И при наличии цвета ячейки приоритет: регистратор → клиент → случайный

# RF-12 — Зеркало в БД горничных (happy path)
Dado Константа.ОбменСГорничными = Истина И задана Папка_Горничные
Quando карточка номера записывается
Então карточка (НомерГорничные, ПометкаУдаления, Наименование) пишется во внешнюю БД горничных

# RF-12 — Обмен отключён (failure / no-op)
Dado Константа.ОбменСГорничными = Ложь ИЛИ Папка_Горничные не задана
Quando карточка номера записывается
Então внешний COM-обмен НЕ выполняется, локальная запись проходит штатно

# RF-10 — Импорт номеров (happy path, идемпотентность)
Dado внешняя база доступна по COM и содержит номер с кодом К
Quando выполняется ЗагрузитьНомера и локального номера с кодом К нет
Então создаётся новый номер с реквизитами и категорией по коду
  И повторный запуск НЕ создаёт дубликат (НайтиПоКоду находит существующий)

# RF-10 — Импорт номеров (failure: база недоступна)
Dado внешняя COM-база недоступна (Connect неуспешен)
Quando выполняется загрузка
Então выводится сообщение об ошибке И обработка завершается без создания номеров

# RF-09 — Замена номера в заявках (happy path)
Dado указаны СтарыйНомер и НовыйНомер
Quando выполняется Заменить
Então во всех заявках строки с НомерВРезерв=СтарыйНомер получают НовыйНомер
  И заявки перепроводятся

# RF-09 — Замена номера (failure: не заполнены поля)
Dado СтарыйНомер или НовыйНомер не заполнен
Quando выполняется Заменить
Então клиентская проверка прерывает операцию до серверного перебора
```

## Prioridade (MoSCoW)

| Требование | MoSCoW | Обоснование |
|-----------|--------|---------------|
| Карточка номера + иерархия (RF-01, RF-02) | Must | Базовая сущность, на неё ссылаются Бронирование, Горничные, Финансы |
| Категории номеров (RF-03) | Must | Без категории нет тарификации и подбора номера |
| Шахматка + раскраска (RF-05, RF-06) | Must | Главный рабочий экран размещения |
| Осмотр номера (RF-08) | Must | Бизнес-правило без fallback (RM-02) |
| Зеркало в БД горничных (RF-12) | Should | Есть условный обход (флаг `ОбменСГорничными`); граница с Горничными |
| Замена номера в заявках (RF-09) | Should | Служебная массовая операция, есть ручная альтернатива |
| Раскраска строк/метки (RF-07) | Should | Визуальная подсказка, не критична для логики |
| Категории сайта (RF-04) | Should | Нужна для интеграции с сайтом (граница) |
| COM-импорт номеров (RF-10, RF-11) | Could | Разовая миграционная операция; срабатывает редко |
| Реквизит `ОсновнойНомер`, дубли `_OLD/_Исходный` | Won't | Назначение не подтверждено / мёртвый код (см. questions.md) |

> Приоритет выведен по частоте вызова и позиции в цепочке зависимостей.
