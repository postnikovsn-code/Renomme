# ADR 0011 — Хранение зарплатных смен в динамических реквизитах формы `*_DDMMYY`

- **Статус:** Принято (исторически) · 🟢 ПОДТВЕРЖДЕНО кодом
- **Дата:** неизвестна
- **Модуль:** Персонал и зарплата (администраторы)

## Контекст

Расчёт ЗП администратора за месяц требует посуточной детализации (смена/часы/переработка/оклад/доплаты на каждый день периода). Число дней переменно (28–31), показателей на день — много.

Свидетельства:
- Форма `АдминистраторыЗарплата` создаёт ~30+ ДИНАМИЧЕСКИХ реквизитов формы вида `НомерСмены_DDMMYY`, `Оклад_DDMMYY`, `Часы_DDMMYY`, `СуммаЗавтракиЛайв_DDMMYY` — по каждому дню месяца (HR-схема). 🟢
- Код смены пишется строкой `Часы_DDMMYY = "ДлинаСмены-НомерСмены/Переработка"` (`:2769-2791`). 🟢
- `ЗаполнитьПередЗаписью` (`:2136-2353`) разворачивает реквизиты `*_DDMMYY` в строки ТЧ объекта `Зарплата`/`ЗарплатаСмены`. 🟢
- Документ НЕ проводится по регистрам; данные хранятся в ТЧ (HR-07). 🟢
- Аналог в `ГорничныеЗарплата` — динамические колонки помещений `Количество_<N>` (MB/HK-смежно). 🟢

## Решение

Хранить посуточные показатели ЗП в динамически создаваемых реквизитах формы, именованных по дате (`<Показатель>_DDMMYY`); при записи разворачивать их в строки табличных частей документа. Расчёт вести в форме, без движений регистров.

## Рассмотренные альтернативы

- **Табличная часть «по строке на день»** в самом документе как первичная структура редактирования. Отклонено для UI: широкая «матрица день×показатель» удобнее редактируется как набор именованных полей формы (хотя в ТЧ данные всё равно разворачиваются при записи).
- **Регистр расчёта / накопления для ЗП.** Отклонено: документ не проводится по регистрам; вся аналитика — прямым запросом к ТЧ.
- **Отдельный документ на каждую смену.** Отклонено: расчёт месяца удобнее в одном документе-матрице.

## Последствия

- ➕ Удобный для оператора «табельный» интерфейс месяца; гибкость по числу дней.
- ➖ 🔴 Имена реквизитов генерируются по дате — их нельзя перечислить в `.mdo`; усложняет анализ, рефакторинг и типизацию.
- ➖ Нет единого источника правды для бух-движений (нет регистров); отчётность строится запросом к ТЧ (HR-07).
- ➖ Дубли-версии формы (`АдминистраторыЗарплата_Версия`, 4012 строк) — высокий техдолг.
- ➖ Расхождения клиент/сервер в формулах (напр. `КоличествоЧасовНаКлиенте` использует `*8` вместо `ДлинаСмены` — аналогичный баг и в горничных).
- ⚠ При миграции «матрицу день×показатель» нужно нормализовать в таблицу строк.
