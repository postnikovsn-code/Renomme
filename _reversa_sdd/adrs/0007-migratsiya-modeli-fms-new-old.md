# ADR 0007 — Незавершённая миграция модели ФМС-данных через реквизиты _NEW/_OLD

- **Статус:** Принято, в процессе (не завершено) · 🟡 ВЫВЕДЕНО
- **Дата:** неизвестна
- **Модуль:** Гости и регистрация

## Контекст

Формат миграционного учёта (ФМС) и его справочники-классификаторы (страны, типы документов, пункты выдачи) изменились. Карточка клиента `Catalog.Клиенты` должна поддерживать новые ссылки на классификаторы, не теряя старые данные до полного перехода.

Свидетельства:
- В `Catalog.Клиенты` сосуществуют реквизиты `ГражданствоФМС_NEW`, `ТипДокументаФМС_NEW` (новые ссылки на `СтраныФМС_NEW`/`ТипДокументаФМС_NEW`) и старые `ПроцентАгент_OLD`, `Тариф_НеИспользуется` (GR-связано). 🟢
- Внешние классификаторы `СтраныФМС_NEW`/`ТипДокументаФМС_NEW`/`ПунктыВыдачиФМС_NEW` с реквизитами `ID`/`CODE_ALPHA3`/`CODE_0` — новая модель. 🟢
- Выгрузка ФМС (`ВыгрузкаДляФМС` vs `ВыгрузкаДляФМС_Исходная`) имеет десятки закомментированных `_OLD`-полей. 🟢
- Магическое число `ПаспортРФ_ID = 103008` зашито в двух местах (GR-05). 🟢

## Решение

Добавить параллельные реквизиты `_NEW` (и классификаторы `*ФМС_NEW`) рядом со старыми, постепенно переводя логику выгрузки на новую модель; старые реквизиты и код оставить до завершения перехода (суффиксы `_OLD`, `_Исходная`, закомментированные поля).

## Рассмотренные альтернативы

- **Переименование старых реквизитов на месте.** Отклонено: 1С не позволяет безопасно переопределить тип реквизита без потери данных; параллельные `_NEW` сохраняют старые значения.
- **Единовременная конвертация всех клиентов в новую модель.** Не выполнено: риск для миграционной отчётности; переход растянут.
- **Вынести классификаторы ФМС во внешний сервис.** Отклонено: классификаторы заведены как справочники с импортом.

## Последствия

- ➕ Старые данные ФМС сохранены; выгрузка постепенно мигрирует на новые классификаторы.
- ➖ 🔴 Незавершённая миграция: в карточке клиента живут две модели данных одновременно — источник ошибок (какое поле актуально).
- ➖ Дубли выгрузки (`ВыгрузкаДляФМС` vs `_Исходная`) и десятки закомментированных `_OLD`-полей — высокий техдолг.
- ➖ Магическое `103008` (тип документа «паспорт РФ») в двух местах — рассинхронизация при правке.
- ⚠ При миграции/доработке нужно определить «золотую» модель ФМС и доудалить `_OLD`/`_Исходная`.
