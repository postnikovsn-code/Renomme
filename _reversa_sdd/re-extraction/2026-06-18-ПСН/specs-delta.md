## 1. Модуль `Бронирование`

Затрагивает `requirements.md`, `design.md`, `contracts.md`, `edge-cases.md`, `tasks.md`.
Связанный flowchart (создан Археологом): `../../flowcharts/Бронирование-ЧекАгента.md`.

### 1.1 Требования (дельта к `requirements.md`)

**Новые бизнес-правила:**

- **Δ-BR-01.** На брони появляется агентская цена продажи `ЦенаПродажиАгентом` (`Число(10,2)`, денежный) — сумма, по которой турагентство продаёт номер гостю; отлична от внутренней цены проживания. База печати «Чека агента». 🟢 тип / 🟡 обязательность (нет `fillChecking`). (`Документ.ЗаявкаНаБронирование.ЦенаПродажиАгентом`)
- **Δ-BR-02.** Группа/действие «Чек агента» **доступна только если контрагент `Бронирует` — турагентство** (`ЗначениеРеквизитаНаСервере(Объект.Бронирует, "Турагентство") = Истина`). Первое в системе правило видимости формы по флагу контрагента `Турагентство`. 🟢 (`Forms/ФормаДокумента/Module.bsl:374-376, 3677-3680`)
- **Δ-BR-03.** «Чек агента» пробивает **ровно одну позицию** «Услуги гостиницы N сут.», где `N = Цел((РезервПо − РезервС)/86400)`, минимум `N = 1`. Цена = Сумма = `ЦенаПродажиАгентом`, `Количество = 1`, `Скидка = 0`. 🟢 (`Module.bsl:9650-9738`)
- **Δ-BR-04.** Чек агента — **полный расчёт без аванса** (`ЭтоАванс = Ложь`): `СуммаКОплате = СуммаПредыдущихОплат = ЦенаПродажиАгентом`, `СуммаОплаты = 0`; эквайринг принудительно выключен (`ОплатаКартойВключена = Ложь`). 🟢 (`Module.bsl:9650-9665, ~9730`)
- **Δ-BR-05.** Чек агента **не порождает движений регистров** — печать через внешнюю `ОбщаяФорма.Чек`; `ObjectModule`/`ManagerModule` брони не затрагиваются. Статус брони не меняется. 🟢
- **Δ-BR-06 (deprecation).** Документ-очередь `ЛистОжидания` выведен из эксплуатации (переименован в `ЛистОжидания_НеИспользуется`; UUID, состав реквизитов, регистрация в `Configuration.mdo` сохранены). Поток «(создание) → ЛистОжидания → Бронь» через отдельный документ отключён. **Won't** в терминах MoSCoW. 🟢
- **Δ-BR-07 (уточнение глоссария).** Термин «Лист ожидания» теперь двойственен: депрекированный документ `ЛистОжидания_НеИспользуется` (вне эксплуатации) **плюс** сохраняющийся булев флаг `ЗаявкаНаБронирование.ЛистОжидания` («парковка спроса», в строю). Канон-правило BR-01 (бронь с флагом `ЛистОжидания` не формирует движений) **остаётся в силе**. 🟢 флаг / 🟡 семантика «единственного механизма».

**MoSCoW дельты:**
- Must: «Чек агента» (новый критический под-поток турагентских продаж). 🟢
- Won't: документ-очередь `ЛистОжидания_НеИспользуется` (депрекирован). 🟢

**Критерии приёмки (Gherkin):**
- Happy: `Дано бронь, у которой Бронирует — турагентство и заполнена ЦенаПродажиАгентом, Когда оператор нажимает «Чек агента», Тогда открывается ОбщаяФорма.Чек с одной позицией «Услуги гостиницы N сут.» на сумму ЦенаПродажиАгентом, без аванса и без кнопки «Оплатить картой».` 🟢
- Failure/гейт: `Дано бронь, у которой Бронирует — НЕ турагентство, Когда открывается форма брони, Тогда группа «Чек агента» недоступна.` 🟢
- Edge: `Дано РезервПо = РезервС, Когда формируется чек агента, Тогда количество суток N = 1.` 🟢

### 1.2 Дизайн / контракты (дельта к `design.md`, `contracts.md`)

- Новый реквизит шапки `ЦенаПродажиАгентом` (`Число(10,2)`). Скалярный, без новых FK/ТЧ. 🟢
- Группа формы `ГруппаЧекАгенту` (`UsualGroup`, горизонтальная): поле `ЦенаПродажиАгентом` + кнопка `ЧекАгента`; команда формы `ЧекАгента` (id 71). 🟢
- `&НаКлиенте Процедура ЧекАгента(Команда)` — собирает параметры чека ККМ (одна позиция, расчёт суток N, цена/сумма из `ЦенаПродажиАгентом`, `ЭтоАванс = Ложь`); НДС через `ДокументыСервер.СтавкаНДСТекущая / СуммаНДС / УчитыватьНДС_Чек(РезервПо)` с учётом флагов организации `ВсеСНДС/СтавкаНДС`; при `НЕ ВсеСНДС` и ставке не «БезНДС»/пустой → `НДС0`, `СуммаНДС = 0`, `ДатаУчетаНДС = РезервПо`. Открывает `ОбщаяФорма.Чек` с блокировкой интерфейса и `ОплатаКартойВключена = Ложь`. 🟢
- `&НаКлиенте Процедура ЗакрытиеФормы_ЧекАгента(Результат, ДополнительныеПараметры) Экспорт` — обработчик закрытия: при `Неопределено` выход, иначе `ОчиститьСообщения()`. 🟢
- Гейт в `ПриСозданииНаСервере` (две вставки): `ГруппаЧекАгенту.Доступность = ОбщийФункционалСервер.ЗначениеРеквизитаНаСервере(Объект.Бронирует, "Турагентство")`. 🟢
- **Контракт «Чек агента» → `ОбщаяФорма.Чек`** (новый вызов; см. §4 параметр `ОплатаКартойВключена`): передаются позиция услуги, суммы, флаги НДС, `ЭтоАванс = Ложь`, `ОплатаКартойВключена = Ложь`. 🟢
- Deprecation: в `design.md`/`legacy-mapping.md` узел `Document.ЛистОжидания` → `Document.ЛистОжидания_НеИспользуется`; единственное содержательное отличие нового `Forms/ФормаДокумента/Module.bsl` — `ПарамФормы.Вставить("НомерВРезерв", НомерВРезерв)` (локальная переменная) вместо пустого `Объект.НомерВРезерв`. 🟢

- **EC-Δ-BR-3.** `Бронирует` не заполнен / не турагентство → группа «Чек агента» недоступна (гейт). 🟢

## 2. Модуль `Аудит`

Затрагивает `requirements.md`, `design.md`, `edge-cases.md`, `tasks.md`.
Связанный flowchart (создан Археологом): `../../flowcharts/Аудит-КассоваяСменаГрупповыеСчета.md`.

### 2.1 Требования (дельта к `requirements.md`)

- **Δ-AU-01.** Отчёт кассовой смены разбирает **групповые счета**: для строк типа `ДокументСсылка.ГрупповыеСчета` суммы по `ДокументыДолги` собираются в сводную ТЗ `(УслугаКорень, СуммаОплаты)` и выводятся **разбивкой по группам доп. услуг**; групповая сумма прибавляется к `ИтогоОтель`. Услуга без значения трактуется как «Проживание», иначе поднимается к корню иерархии услуг (`КореньУслуга`). 🟢
- **Δ-AU-02.** **Юридическая формулировка** услуги проживания в фискальных/печатных формах унифицирована: «Проживание…»/«Услуги гостиницы» → «**Услуги по предоставлению мест для временного проживания в гостинице**». 🟢 (`ПечатьСервер`, ~7 мест)
- **Δ-AU-03 (фикс комиссии).** База расчёта комиссии по услуге исправлена: `СуммаУслуга = Цена × Количество` (было `= Сумма`); отбор строк долга — корректным `Новый Структура("ГУИД", ДолгиГУИД)` (был ошибочный 3-параметр). Уточняет правило FN-05/«Комиссия агента». **Меняет суммы исторических расчётов комиссий.** 🟢 (`ДокументыСервер` блок `// + Аудит`, ~325-343)

### 2.2 Дизайн (дельта к `design.md`)

- `&НаСервере Функция ТабДокКасса()` — действующая версия: добавлена ветка `ТипЗнч(...) = Тип("ДокументСсылка.ГрупповыеСчета")`. 🟢
- **Новые** `&НаСервере Функция ТЗ_Заявка(ДокументДолг, ДокументОплаты)` (запрос `ЗаявкаНаБронирование.РаспределениеОплатДолги ⟕ …ДопУслуги` по `ДолгиГУИД = ГУИД`, колонка `УслугаКорень`) и `&НаСервере Процедура ПрисоединитьГруппа(ТабДок, Макет, ТЗ_ГруппыДопУслуги, ТЗЗаявка)` (вывод области `Строка|Группа`: «Проживание», затем по группам доп. услуг). 🟢
- `ДокументыСервер` фикс комиссии — см. Δ-AU-03; функция и сигнатуры расчёта не менялись, изменена только формула базы и отбор строк. 🟢
- 🟡 Техдолг (находка, не правка): мёртвый клон `ТабДокКасса_1()` (старое тело без `ГрупповыеСчета`, не вызывается). Кандидат на удаление при чистке.

### 2.3 Edge-cases (дельта к `edge-cases.md`)
- **EC-Δ-AU-1.** Строка отчёта типа `ГрупповыеСчета` без значения услуги → трактуется как «Проживание». 🟢

### 3.1 Требования (дельта к `requirements.md`)

Запуск пакетно под спец-пользователем `РассылкаДеньРождения` (`ManagedApplicationModule`, авто-`ЗавершитьРаботуСистемы(Ложь)`). 🟢
- **Δ-IN-06 (фикс НДС).** В выгрузке в бухгалтерию `ОбменБухгалтерияНДС.ЗаписатьЗаявки` исправлено двойное преобразование ставки: `СтавкаНДСЧисло(СтавкаНДСТекущий)` вместо `СтавкаНДСЧисло(СтавкаНДСЧислоТекущий)` (8 мест). Формат файла и набор `ТипыСчетов` не менялись. 🟢
