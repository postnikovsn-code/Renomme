# Горничные (Housekeeping), Контракт обмена

> Файл `contracts.md`. Внешний контракт модуля — синхронный COM-обмен с отдельной базой 1С «Горничные» (планшеты). Извлечён из легаси-кода базы «ОТЕЛЬ»; код на стороне БД горничных — за периметром (🟡 там, где это влияет на полноту). Уровень: detalhado. Метки 🟢/🟡/🔴. Пути относительны корня `C:\_dev\ANB\AI\Hotel\`.

## 1. Общая характеристика

| Свойство | Значение | Доверие |
|----------|----------|---------|
| Тип контракта | RPC поверх синхронного COM (`V83.COMConnector`) | 🟢 |
| Транспорт | COM-соединение к **файловой** базе 1С; строка соединения `File="<Папка_Горничные>";Usr="Соединение";Pwd="123"` | 🟢 |
| Фасад (обе базы) | Одноимённый `CommonModule.ОбменГорничныеСервер` в «ОТЕЛЬ» и в БД горничных; вызовы вида `Соединение.ОбменГорничныеСервер.<Метод>(…)` | 🟢 |
| Направление | **Двустороннее** (исходящее: «ОТЕЛЬ» → горничные; входящее: горничные → «ОТЕЛЬ») | 🟢 |
| Глобальный тумблер | `Константа.ОбменСГорничными` (Булево); при `Ложь` любая процедура обмена выходит немедленно | 🟢 |
| Путь к БД | `Константа.Папка_Горничные` (Строка) | 🟢 |
| Кэш соединения | `SessionParameter.СоединениеГорничнныеАдресВХранилище` → адрес структуры `{Соединение}` во временном хранилище; до 3 ретраев с «пингом» `ПроверкаСоединения()` | 🟢 |
| Платформа | Жёсткая привязка к Windows/COM; кроссплатформенность отсутствует | 🟢 |
| Аутентификация | Логин/пароль захардкожены (`Usr="Соединение"`, `Pwd="123"`) | 🔴 (см. `questions.md` Q-01) |

**Точка входа соединения.** `ОбменГорничныеСервер.Соединение()` — `ПСН_РЕНОМЕ__АУДИТ/src/CommonModules/ОбменГорничныеСервер/Module.bsl:1-46`. Возвращает COM-объект или `Неопределено`. Все методы обмена начинают работу с проверки тумблера и получения соединения.

## 2. Сущности обмена

|-------------------|-----|-------------|--------------------|---------|

| `Catalog.ГорничныеПомещения` | Справочник | входящее (создать/обновить) | `ПомещениеГорничные` | 🟢 |

| `Catalog.ГорничныеНомера` ↔ `Catalog.НомернойФонд` | Справочники | исходящее (выгрузка таблицы соответствия) | `НомерГорничные` | 🟡 |
| `Document.ГорничныеОбслуживаниеНомера` (уборки номеров) | Документ | входящее (загрузка фактов) | ДатаОбслуживания + НомерОбслуживания_пп + НомерГорничные | 🟢 |
| `Document.ГорничныеОбслуживаниеПомещения` (уборки помещений) | Документ | входящее (загрузка фактов) | Дата + пп + Горничная | 🟡 |
| `Document.ГорничныеСмены` (смены) | Документ | входящее (загрузка фактов) | ДатаСмены + Горничная (ключ обмена `ГУИД`) | 🟢 |
| Состояние номеров (бельё/доп.места/оборудование) → `ГорничныеНомера` | Реквизиты | входящее | `НомерГорничные` | 🟢 |
| Задание на уборку (из брони) | Структура | исходящее (создание) | GUID заявки | 🟢 |

## 3. Операции контракта

### 3.1 Исходящие (вызывает «ОТЕЛЬ», метод исполняется в БД горничных)

| Операция | Метод-инициатор в «ОТЕЛЬ» | Удалённый вызов | Полезная нагрузка | Доверие |
|----------|---------------------------|-----------------|-------------------|---------|
| Создать задание уборки | `СоздатьЗаявку(Заявка, Событие)` (48-117) | `Соединение.ОбменГорничныеСервер.СоздатьЗаявку(ДанныеЗаявки, Событие)` | `Структура`: ГУИД, статус/времена (`XMLСтрока`), доп.места, времена заезда/выезда | 🟢 |
| Выгрузить горничную | `ОбновитьГорничнаяГорничные(Горничная)` (656-685) | `Соединение.ОбменГорничныеСервер.ОбновитьГорничныеОтель(Структура)` (зеркальный метод на той стороне) | `Структура`: Наименование, Сортировка, НеРаботает, ПометкаУдаления, `ГорничнаяГУИДСтрока` | 🟢 |
| Выгрузить таблицу соответствия номеров | `DataProcessor.ОбновитьГорничныеНомера` (Forms/Форма) | передача ТЗ соответствия в БД горничных | ТЗ: `НомерГорничные` ↔ номер фонда | 🟡 |
| Выгрузить номенклатуру минибара | модуль «Минибар» (`НоменклатураМиниБара.ObjectModule`) | `...ОбновитьНоменклатураМиниБараГорничные` | `Структура` по `Код` | 🟢 |

> `ОбновитьГорничнаяГорничные` возвращает `Булево` (Истина = ошибка); при ошибке «ОТЕЛЬ» выдаёт «НЕ выгружена». 🟢

## 4. Ключ синхронизации `ГорничнаяГУИДСтрока`

- Главный ключ справочника `Горничные` между базами. При первой записи карточки заполняется `Строка(Ссылка.УникальныйИдентификатор())` 🟢 (`Catalog.Горничные.ObjectModule.bsl:10-13`).
- Стабилен на весь жизненный цикл объекта; обе базы сопоставляют горничных по этому значению.
- ⚠ При загрузке **фактов** уборки сопоставление горничной идёт по **наименованию** (`НайтиПоНаименованию`, авто-создание при отсутствии), а не по `ГорничнаяГУИДСтрока` — потенциальный источник дублей (`questions.md` Q-07). 🟡

## 5. Разрыв эха (`ОбменДанными.Загрузка`)

- Все входящие процедуры пишут объект с `ОбменДанными.Загрузка = Истина` (722, 749, 776, 802). 🟢
- `Catalog.Горничные.ObjectModule.ПередЗаписью`: при `ОбменДанными.Загрузка = Истина` (или новый объект) → `ПроверкаОбмена = Ложь`, обратная выгрузка отменяется (6, 33). 🟢
- Итог: входящая запись фиксируется без обратной выгрузки → цикл «эха» разорван за один проход (см. `edge-cases.md` EC-04). 🟢

## 6. Защита ручных правок (`РучноеИзменение`)

- Документ уборки с `РучноеИзменение = Истина` при повторной загрузке **пропускается** (`Продолжить`), не перезаписывается. 🟢 (`ОбменГорничныеСервер.ЗагрузитьОбслуживаниеНомеров:214`; то же для помещений).
- Контракт идемпотентен по бизнес-ключу: повторная загрузка обновляет существующие документы, кроме помеченных ручной правкой.

## 8. Предусловия и инварианты контракта

- **Тумблер.** Без `Константа.ОбменСГорничными = Истина` контракт неактивен (все методы выходят). 🟢
- **Соединение.** Без валидного `Соединение()` (≤ 3 попыток) операция завершается без изменения данных + сообщение оператору. 🟢
- **Эхо.** Входящая запись не порождает исходящую (флаг `Загрузка`). 🟢
- **Ручные правки.** Документы с `РучноеИзменение` неприкосновенны при загрузке. 🟢
- **Выгрузка горничной** — только при `УчетУборок = Истина` и изменении одного из {Наименование, Сортировка, НеРаботает, ПометкаУдаления, УчетУборок}. 🟢
- **Идемпотентность** загрузки фактов по бизнес-ключам (раздел 3.3). 🟢

## 9. Пробелы контракта

- 🔴 Учётные данные COM захардкожены (`Pwd="123"`, `Usr="Соединение"`) — `Соединение():22` (`questions.md` Q-01).
- 🔴 Точные структуры ТЗ, выгружаемых из БД горничных (имена колонок), известны лишь по присваиваниям в коде «ОТЕЛЬ»; код на стороне БД горничных вне периметра.
- 🟡 Параметры `ЗагрузитьОбслуживаниеПомещений`/`ЗагрузитьСмены` выведены по аналогии, не прочитаны построчно.
- 🟡 Подавление ошибок выгрузки ТЗ пустым `Попытка` маскирует частичный сбой обмена (`questions.md` Q-09).
- 🟡 Сопоставление горничной при загрузке фактов по наименованию вместо `ГорничнаяГУИДСтрока` — риск дублей (`questions.md` Q-07).
