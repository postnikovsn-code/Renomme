## Контур и периметр

Модуль состоит из двух **независимых** товарных контуров. Точка истины — контур **Минибар**; контур **«Бар»/Товары** документируется как связанный.

| Контур | Номенклатура | Регистры | Документы | Обработка |
|--------|--------------|----------|-----------|-----------|
| **Минибар** (основной) | `Catalog.НоменклатураМиниБара` | `МинибарОстатки`, `МинибарПартии` (РН), `МинибарСебестоимость` (РС, Месяц) | `МинибарПриход`, `МинибарРасход` | `DataProcessor.Минибар` |
| **«Бар»/Товары** (связанный) | `Catalog.Товары` (группа «Бар») | `ОстаткиПродукции` (РН), `СебестоимостьТоваров` (РС) | `ИнвентарицацияБара` | `DataProcessor.ИнвентарицацияБара` |

🔴 Связь/синхронизация остатков между контурами в коде НЕ обнаружена (ADR 0012; `questions.md` Q-02).

## Структуры данных

См. `data-dictionary.md` → раздел «Минибар». Ключевое:

- `МинибарОстатки`: изм. `НоменклатураМинибара`; рес. `Количество`/`СуммаПриход`/`СуммаРасход`; рекв. `ЦенаПриход`/`ЦенаРасход`.
- `МинибарПартии` (FIFO): изм. `ДокументПрихода`/`НоменклатураМинибара`/`ЦенаПриход`; рес. `Количество`; рекв. `ЦенаРасход`.
- `МинибарСебестоимость` (periodicity=Month): изм. `НоменклатураМинибара` (mainFilter); рес. `Количество`/`Сумма`.
- `Document.МинибарРасход`: флаги `Программно`, `Списание`; ТЧ `Расход` (`ДатаРасхода`, `Номенклатура`, `Количество`, `Цена`, `ДокументИсточник`, `НомерОтель`, `ТипСписания`).

## Поток основной

### Проведение прихода (`МинибарПриход/ObjectModule.bsl:2-28`) 🟢
1. Цикл по ТЧ `Приход` → движение `МинибарОстатки` (Приход): `Количество`, `ЦенаПриход`, `СуммаПриход = Цена*Количество`, Период = `ДатаДокументаПрихода`.
2. Второй цикл по ТЧ `Приход` → движение `МинибарПартии` (Приход): партия с `ДокументПрихода = Ссылка`, `НоменклатураМинибара`, `Количество`, `ЦенаПриход`. **Каждый документ прихода = одна партия.**

### Проведение расхода — FIFO (`МинибарРасход/ObjectModule.bsl:2-98`) 🟢
1. Цикл по ТЧ `Расход` → движение `МинибарОстатки` (Расход): `Количество`, `ЦенаРасход`, `СуммаРасход = Цена*Количество`, Период = `ДатаРасхода`.
2. Цикл по ТЧ `Расход` для `МинибарПартии`:
   1. `ПартииОстатки(ДатаРасхода, Номенклатура)` → партии, упорядоченные по дате прихода.
   2. **Коррекция**: вычесть из `КоличествоОстаток` каждой партии количество уже добавленных в этом проведении движений по той же партии (защита от двойного списания).
   3. `РасходОстаток = Количество строки`. Идти по партиям от старейшей: списать `Мин(РасходОстаток, КоличествоОстаток)`, движение Расход с `ЦенаПриход` партии и `ЦенаРасход` строки; уменьшать `РасходОстаток`; при полном покрытии — `Прервать`.
   4. 🔴 Если `РасходОстаток > 0` (партий не хватило) — движение Расход БЕЗ `ДокументПрихода` на остаток (торговля в минус, себестоимость = 0).

### Автосбор расхода из уборок (`DataProcessors/Минибар/Forms/Форма/Module.bsl:17-94`) 🟢
1. `ОбменГорничныеСервер.ЗагрузитьОбслуживаниеНомеров(ДатаС, ДатаПо, "")` — дозагрузка фактов за месяц.
2. Запрос к `Документ.ГорничныеОбслуживаниеНомера.Минибар` за месяц (`КОНЕЦПЕРИОДА(...МЕСЯЦ)=ДатаСебестоимость`), упорядочен по дате/номеру/номенклатуре.
3. Если строк нет → сообщить и выйти.
4. Идемпотентность: найти `МинибарРасход` с `Программно=Истина` и `ДатаДокументаРасхода=КонецМесяца`. Есть → очистить ТЧ `Расход` (комментарий «Обновлён программно»); нет → создать (`Программно=Истина`, «Создан программно»).
5. Каждая строка уборки → строка расхода: `ДатаРасхода=ДатаОбслуживания`, `Номенклатура`, `Количество`, `Цена`, `ДокументИсточник=ссылка уборки`, `НомерОтель=НомерВРезерв`.
6. Записать с проведением.

### Средневзвешенная себестоимость и перенос (`...Module.bsl:968-1081`) 🟢
1. Начало месяца = срез последних `МинибарСебестоимость` (`КоличествоНачало`/`СуммаНачало`).
2. `СуммаПриход`/`КоличествоПриход` = СУММА прихода за месяц из `МинибарПриход.Приход`; `КоличествоРасход` = СУММА из `МинибарРасход.Расход`.
3. На номенклатуру (если есть движение):
   - `ЦенаСписания = (СуммаНачало + СуммаПриход) / (КоличествоНачало + КоличествоПриход)`; fallback при знаменателе 0.
   - `СуммаКонец = СуммаНачало + СуммаПриход − КоличествоРасход*ЦенаСписания`; `КоличествоКонец = КоличествоНачало + КоличествоПриход − КоличествоРасход`.
   - Запись `МинибарСебестоимость` на `Период = КонецМесяца + 1`.
4. Диапазон месяцев: `ДатыОбновления()` находит первый разрыв в цепочке и пересчитывает от него до даты расчёта + `БудущиеДаты()`.

## Потоки альтернативные

- **Нехватка партий (FIFO):** движение расхода без партии, остаток партий уходит в минус, себестоимость = 0 🔴 (`МинибарРасход/ObjectModule.bsl:54-61`).
- **Повторный автосбор за месяц:** перезапись существующего программного документа, без дублей 🟢.
- **Нет фактов потребления за месяц:** автосбор сообщает и выходит, документ не создаётся 🟢.
- **Деление на ноль в себестоимости:** fallback на `СуммаНачало/КоличествоНачало` или 0 🟢.
- **Расчёт задним числом:** пересчёт цепочки месяцев от первого разрыва (`ДатыОбновления`) 🟢.
- **`НеИспользуется`-номенклатура:** исключается из срезов/отчётов себестоимости 🟢.
- **(Связанный контур) Инвентаризация бара:** заполнение ТЧ по группе «Бар» (магическая строка), проведение Факт − Учёт по `ОстаткиПродукции` 🟢🔴.

## Зависимости

- **Горничные** — источник фактов расхода (ТЧ `Минибар` документа `ГорничныеОбслуживаниеНомера`); дозагрузка через `ОбменГорничныеСервер.ЗагрузитьОбслуживаниеНомеров`; двусторонняя синхронизация справочника `НоменклатураМиниБара` 🟢.
- **Доп. услуги и коворкинг** — зеркало номенклатуры в `Справочник.ДопУслуги` (группа `Enum.ПрограммныйКодУслуги.Минибар`); продажа гостю / в счёт 🟢.
- **Размещение и номерной фонд** — `Catalog.НомернойФонд`: `НомерОтель` в строках расхода; число номеров в отчёте движения (`ВНомерах`) 🟢🔴.
- **Интеграции** — `Константа.ОбменСГорничными` (тумблер выгрузки в БД горничных по COM, `V83.COMConnector`) 🟢 (ADR 0005).
- **(Связанный контур) Бар/Товары** — `Catalog.Товары`, `ОстаткиПродукции`, `СебестоимостьТоваров`; отдельный учёт, синхронизация с минибаром не найдена 🔴.

## Состояние внутреннее

- `МинибарОстатки` — текущие остатки и накопленные суммы прихода/расхода (изменяются проведением прихода/расхода).
- `МинибарПартии` — остаток по каждой партии (может уходить в минус по «безпартионной» позиции при торговле в минус).
- `МинибарСебестоимость` — переходящий помесячный остаток (Количество/Сумма) по средневзвешенной цене; запись на начало каждого месяца; цепочка должна быть непрерывной (контролируется `ДатыОбновления`).
- `Document.МинибарРасход` (`Программно=Истина`) — служит «материализованным» снимком потребления за месяц; перезаписывается при повторном сборе.

## Наблюдаемость

- Автосбор расхода и пересчёт себестоимости сообщают результат пользователю (`Сообщить`/`Предупреждение`): отсутствие расхода, факт создания/обновления документа, завершение пересчёта остатков 🟢.
- Комментарий программного документа расхода («Создан/Обношлён программно …») фиксирует происхождение 🟢.
- Отчёт «Движение» подсвечивает отрицательные остатки красным — визуальный сигнал учётных аномалий (в т.ч. торговли в минус) 🟢.
- Структурированного журналирования (ЗаписьЖурналаРегистрации) для контура минибара в прочитанном коде не обнаружено 🟡.

## Риски и пробелы

- 🔴 «Торговля в минус» (`МинибарРасход/ObjectModule.bsl:54-61`): себестоимость недостающего количества = 0 → занижает себестоимость и завышает прибыль; учётная корректность не гарантирована (ADR 0012).
- 🔴 Разрыв контуров минибар vs «Бар»: `ИнвентарицацияБара` инвентаризирует `Товары`/`ОстаткиПродукции`, а не `НоменклатураМиниБара`/`МинибарОстатки`; синхронизация не найдена.
- 🔴 Опечатка FQN `ИнвентарицацияБара` («Инвентарицация») закреплена в именах метаданных.
- 🔴 Магическая строка `Справочники.Товары.НайтиПоНаименованию("Бар")` (`ИнвентарицацияБара/Forms/ФормаДокумента/Module.bsl:154`) — ломается при переименовании группы.
- 🔴 Допущение отчёта `ВНомерах = число всех номеров отеля` не параметризовано (`...Module.bsl:416-421`).
- 🔴 Дубль `ПрибыльНаСервере`/`ПрибыльНаСервере_1`; мёртвые процедуры (`ТоварыПриВыводеСтроки__`, `КоманднаяПанель1Заполнить__`, `ТЕСТ`); устаревшая `ИнвентарицацияБара/Forms/ФормаДокумента_OLD`.
- 🟡 Точная роль `AccumulationRegister.ПродажиТоваров`/`СебестоимостьТоваров` для минибара не разобрана (описаны как связь общего торгового контура).
- 🟡 Формы документов расхода (`ФормаДокумента`/`ФормаСписка`) детально не разбирались.
