# Ценообразование — Крайние случаи

> Крайние случаи модуля «Ценообразование», выведенные из кода. Каждый описывает условие, поведение легаси и ожидаемое поведение реконструкции. Уверенность: 🟢/🟡/🔴.

## EC-01. Частичные сутки по времени заезда/выезда

- **Условие:** многодневная бронь с временем заезда `Вр0`/`Вр6` (ранний) или временем выезда `Вр18`/`Вр0` (поздний).
- **Поведение легаси:** `Количество` строки дня заезда: `Вр0→2`, `Вр6→1.5`, иначе `1`; день выезда: `Вр18→1.5`, `Вр0→2`, иначе `1`; промежуточные дни = `1`. Сумма дня = Цена × Количество. Период считается по `[РезервС; РезервПо−86400]` (последняя ночь — день перед выездом). 🟢
- **Ожидаемо:** ранний заезд и поздний выезд добавляют 0.5–1.0 ночи к стоимости; коэффициенты 2/1.5/1 нельзя менять без согласования (зашитая тарифная политика). 🟢
- Источник: `ДокументыСервер.ЗаполнитьТаблицуПроживания_Таблица:428-513`; `flowcharts/Ценообразование-РасчетПроживания.md`.

## EC-02. Однодневная бронь (РезервС = РезервПо)

- **Условие:** заезд и выезд в один день.
- **Поведение легаси:** отдельная ветка; `Количество = 1`; коэффициенты заезда/выезда НЕ применяются (закомментированы) — поведение отличается от многодневной брони. Если бронь БонШанс — цена из `ЦеныБонШанс` без скидки. 🟢
- **Ожидаемо:** однодневная бронь тарифицируется как 1 ночь независимо от времён; расхождение с многодневной логикой — осознанное (подтвердить бизнес-смысл). 🟡
- Источник: `ЗаполнитьТаблицуПроживания_Таблица`; `flowcharts/Ценообразование-РасчетПроживания.md` (п. «Однодневная бронь»).

## EC-03. Отсутствие текущей/долгосрочной цены → fallback на базу

- **Условие:** на запрашиваемую дату нет текущих и/или долгосрочных записей в `КалендарьЦенБазовый`/`КалендарьЦенКатегории`.
- **Поведение легаси:** текущая цена при отсутствии текущих записей = долгосрочная; долгосрочная при отсутствии долгосрочных = базовая. Если и базовой цены нет (`БазовыеЦены` пуст) — все цены = 0 (контракт не падает). 🟢
- **Ожидаемо:** каскад всегда возвращает структуру цены; нулевая цена — валидный, а не аварийный результат. 🟢
- Источник: `КалендарьЦен.ПолучитьТекущаяЦенаДня:161-224`, `ПолучитьБазоваяЦенаДня:57-99`; `flowcharts/Ценообразование-ЦенаДняКалендарь.md`.

## EC-04. Тариф без завтрака с незаполненной ценой → обычная цена

- **Условие:** выбран тарифный план, запрошена цена «без завтрака», но соответствующее поле матрицы (`Цена…БезЗавтрака`) = 0.
- **Поведение легаси:** fallback на цену «с завтраком» того же сочетания будни/вых × 1/2 (например, `ЦенаБудниДвухБезЗавтрака=0` → `ЦенаБудниДвух`). Незаполненная «без завтрака» цена трактуется как «такая же, как обычная». 🟢
- **Ожидаемо:** 0 в поле «без завтрака» = «использовать обычную цену», а не «бесплатно»; реконструкция обязана повторить fallback. 🟢
- Источник: `ЦенаНаДеньТарифныйПлан:553-628`; `flowcharts/Ценообразование-ЦенаТарифныйПлан.md`.

## EC-05. Граница magic-date '20240401'

- **Условие:** бронь с `РезервПо` (или рассчитываемый день) ДО `'20240401'`.
- **Поведение легаси:** расчёт делегируется `ДокументыСервер_Старый`/`КалендарьЦен_Старый` (старая модель цен, параллельная кодовая база). Брони после границы считаются новым календарём цен. 🟢
- **Ожидаемо:** исторические брони сохраняют корректные (старые) суммы; пересчёт их новой моделью ЗАПРЕЩЁН (исказит закрытые финансовые периоды). При миграции обе ветви и граница должны быть учтены. 🟢
- Источник: `ДокументыСервер.ДатаПереходаНаНовыйКалендарьЦен:369-371`; ADR-0003; `questions.md` Q-04.

## EC-06. БонШанс-цены (горящий тариф)

- **Условие:** однодневная бронь с признаком БонШанс.
- **Поведение легаси:** цена = `ПолучитьБонШансЦена` — последняя запись `ЦеныБонШанс` с `ДатаЦены ≤ даты` (с fallback на `Константы.БонШансЦена`); `Количество = 1`; скидка клиента НЕ применяется (`Сумма = Цена × 1`). 🟢
- **Ожидаемо:** горящая цена — отдельный источник, не проходит через каскад календаря и не подлежит скидке. При отсутствии записи и константы — поведение цены 0 (подтвердить). 🟡
- Источник: `ПолучитьБонШансЦена:405-425`; `ЗаполнитьТаблицуПроживания_Таблица`.

## EC-07. Несимметрия скидок: тариф vs ценовая политика

- **Условие:** одна и та же бронь с заполненным тарифным планом (цена > 0) против брони без тарифа.
- **Поведение легаси:** при цене тарифа `Сумма = СуммаБезСкидки` (скидка клиента игнорируется); при ценовой политике `Сумма = Окр(СуммаБезСкидки × (1 − Скидка/100), 2)` (скидка применяется). 🟢
- **Ожидаемо:** идентичная по дням бронь может дать разную итоговую сумму в зависимости от наличия тарифа — источник недопонимания. Реконструкция повторяет несимметрию as-is, но это кандидат на бизнес-уточнение. 🟡
- Источник: `ЗаполнитьЦенаСуммыСтрокаПроживание:515-539`; ADR-0004 (последствия).

## EC-08. Запись изменения цен прервана на середине цикла

- **Условие:** при записи цен по набору выбранных дат происходит сбой (исключение) на одной из дат.
- **Поведение легаси:** цикл идёт БЕЗ транзакции → часть дат/регистров (`КалендарьЦенБазовый`, `КалендарьЦенКатегории`, `*История`) останется записанной, часть — нет; данные несогласованны. 🔴
- **Ожидаемо:** реконструкция оборачивает цикл в транзакцию (см. `tasks.md` T-21): либо все выбранные даты записаны, либо ни одной. 🟡
- Источник: `ИзменитьВыбранныеНаСервере:1565-1661`; `flowcharts/Ценообразование-ИзменениеЦен.md`; `questions.md` Q-02.

## EC-09. Запись цены, равной исходной (без изменения)

- **Условие:** на форме `КалендарьЦен` цена/доплата формально перезаписана тем же значением.
- **Поведение легаси:** в наборе записей создаётся строка только для ИЗМЕНЁННЫХ типов; запись в `*История` пропускается, если значение не изменилось (точечное хранение только отклонений). 🟢
- **Ожидаемо:** неизменённое значение не создаёт мусорных записей в регистрах/истории; идемпотентность повторной записи. 🟢
- Источник: `ИзменитьВыбранныеНаСервере`; `flowcharts/Ценообразование-ИзменениеЦен.md`.

## EC-10. Тариф с `Двухместный = Неопределено`

- **Условие:** вызов `ЦенаНаДеньТарифныйПлан` с неопределённым флагом двухместности.
- **Поведение легаси:** guard возвращает 0 → тариф молча не применяется, вызывающий код откатывается на ценовую политику. 🟡
- **Ожидаемо:** неопределённость двухместности трактуется как «тариф неприменим»; реконструкция должна явно инициализировать флаг до вызова. 🟡
- Источник: `ЦенаНаДеньТарифныйПлан:553-628`; `flowcharts/Ценообразование-ЦенаТарифныйПлан.md`.
