# Гости и регистрация, Внешние контракты

> Файл `contracts.md`. Два внешних контракта домена: (1) HTTP API распознавания паспортов PassportBox (входящий вызов отеля → сканер); (2) выходной файл миграционного учёта для ФМС (CSV `#v.2.0.0`). Уверенность: 🟢/🟡/🔴.

---

## Контракт 1: PassportBox — HTTP-сканер распознавания документов

**Направление:** исходящий (отель → внешний сервис PassportBox).
**Транспорт:** HTTP, адрес/порт из констант `PassportBoxIP`, `PassportBoxПорт` (дефолт 80), таймаут `PassportBoxТаймаут` (дефолт 30 c), включение `PassportBoxАктивность`.
**Клиент:** `CommonModule.PassportBoxВызовСервера` (`ПСН_РЕНОМЕ__АУДИТ/src/CommonModules/PassportBoxВызовСервера/Module.bsl`). 🟢
**Эндпоинт:** `POST /CaptureDocument` → JSON-ответ (`РаспознатьДокумент:149`). 🟢
**Идемпотентность:** каждый вызов — независимое распознавание текущего документа под сканером (без ключа дедупликации). 🟢

### Вход (запрос)
| Параметр | Источник | Назначение | Уверенность |
|----------|----------|------------|-------------|
| Адрес/порт | константы `PassportBoxIP`/`PassportBoxПорт` | адрес сканера | 🟢 |
| Таймаут | константа `PassportBoxТаймаут` | предел ожидания HTTP | 🟢 |
| Тип операции | вызов `ПолучитьРазворот23` / `ПолучитьРегистрацию` / `ПолучитьКартинку` | какой документ распознать | 🟢 |

> Тело запроса формируется драйвером сканера; детальная схема запроса в коде домена не разобрана. 🟡

### Выход (JSON-ответ)
Ответ содержит до трёх наборов значений одного поля по источникам с приоритетом `page3 < OCR < MRZ`; драйвер сворачивает их в плоскую структуру реквизитов (`ЗаполнитьПоляИзJSON:464-479`). 🟢

| Поле результата | Источник в JSON | Назначение | Уверенность |
|-----------------|-----------------|------------|-------------|
| `doc_type` | корень ответа | тип документа: `rus.passport.national` (паспорт) / `rus.passport.registration` (регистрация) | 🟢 |
| `error` | корень ответа | признак/описание ошибки распознавания | 🟢 |
| Серия | page3/OCR/MRZ | серия паспорта | 🟢 |
| Номер | page3/OCR/MRZ | номер паспорта | 🟢 |
| ДатаВыдачи | OCR/MRZ | дата выдачи (парсится `СтрокаВДату`) | 🟢 |
| КодПодразделения | OCR | код органа выдачи | 🟢 |
| Фамилия / Имя / Отчество | OCR/MRZ | ФИО (приводится `ТРег`, дефис сохраняется) | 🟢 |
| Пол | OCR/MRZ | строка пола → `Пол_СтрокуВПеречисление` → `EnumRef.Пол` | 🟢 |
| ДатаРождения | OCR/MRZ | дата рождения | 🟢 |
| (регистрация) поля адреса | OCR | адрес регистрации (6 обязательных полей) | 🟡 |
| Фотографии (page3) | поток картинок | фото 3-й страницы (обязательно) | 🟢 |

### Правила контракта
1. **9 обязательных полей паспорта**: Серия, Номер, ДатаВыдачи, КодПодразделения, Фамилия, Имя, Отчество, Пол, ДатаРождения. При пустом любом — ошибка «Страница не распознана» (`ОбязательныеПоляПаспорта`, `Module.bsl:418-430`). 🟢
2. **6 обязательных полей регистрации** — для `ПолучитьРегистрацию`. 🟡
3. **Приоритет источников** строго возрастающий `page3 < OCR < MRZ`; непустое более приоритетное перезаписывает менее приоритетное; пустое не перезаписывает (`Module.bsl:464-479`). 🟢
4. **Проверка `doc_type`**: при несовпадении — «Неверный тип документа». 🟢
5. **Фото page3 обязательно** (фото 2-й страницы отключено/закомментировано) (`Module.bsl:518-534`). 🟢
6. **Обработка ошибок**: все исключения перехватываются и конвертируются в результат-ошибку `{Ошибка, Описание}`; нет проброса наверх. 🟢
7. **Парсинг дат**: `СтрокаВДату` — "ДД.ММ.ГГ[ГГ]" → Дата, век "20" при 6 знаках (`Module.bsl:214-229`). 🟢

### Структура результата (возврат драйвера)
```
{
  Ошибка:      Булево,
  Описание:    Строка,            // при Ошибка=Истина
  Реквизиты:   Структура,         // 11 полей паспорта (свёрнутые источники)
  Фотографии:  <данные page3>     // при успехе
}
```
🟢 (по flowchart Гости-ПолучитьРазворот23)

## Контракт 2: Выгрузка для ФМС — файл миграционного учёта (CSV `#v.2.0.0`)

**Направление:** исходящий (отель → миграционная служба ФМС/МВД, через файл).
**Формат:** текстовый CSV, кодировка/разделитель `;`, версия формата `#v.2.0.0`.
**Производитель:** `DataProcessor.ВыгрузкаДляФМС` (`ПСН_РЕНОМЕ__АУДИТ/src/DataProcessors/ВыгрузкаДляФМС/Forms/Форма/Module.bsl`). 🟢
**Имя файла:** `<первые 10 символов текущей даты>.csv` (`Module.bsl:105-111`). 🟢
**Каталог:** константа `ПАПКА_ВыгрузкаДляФМС`. 🟢
**Гранулярность:** одна строка на пару «клиент + бронь»; для `Клиент` и (если задан) `Клиент2` создаются отдельные строки; источник — брони с `ВремяЗаездаТочное` = дата заезда (`Module.bsl:13-43`). 🟢

### Структура файла
| Часть | Содержимое | Уверенность |
|-------|------------|-------------|
| Строка 1 (шапка) | `#v.2.0.0;;;…;` — фиксированное число `;` (`Module.bsl:91`) | 🟢 |
| Строки данных | результат `СформироватьСтрокуДляФМС(Клиент, Бронь)`, ~94 поля, разделитель `;` (`Module.bsl:138-429`) | 🟢 |

### Поля строки данных (по группам, в порядке формирования)
| № группы | Поля | Зависит от ИГ? | Уверенность |
|----------|------|:--------------:|-------------|
| 1 | `ИностранныйГражданин` → 1/0 | — | 🟢 |
| 2 | ФИО кириллица + ФИО латиница + Пол + ДатаРождения | нет | 🟢 |
| 3 | Место рождения: Страна(`CODE_ALPHA3`), Регион, Район, Город, НасПункт | нет | 🟢 |
| 4 | Гражданство: ИГ → `ГражданствоФМС_NEW.CODE_ALPHA3`; РФ → `RUS` | да | 🟢 |
| 5 | Тип документа: ИГ → `ТипДокументаФМС_NEW.ID`; РФ → `103008` | да | 🟢 (103008 — 🔴 magic) |
| 6 | Документ: Серия, Номер, ДатаВыдачи, Срок до, ПунктВыдачи (через `ПунктВыдачиДокументаФМС`) | частично | 🟢 |
| 7 | Адрес регистрации (`Проживание*`) | нет | 🟢 |
| 8 | Адрес прежнего проживания (`ПрежнееПроживание*`) | нет | 🟢 |
| 9 | Документы на пребывание в РФ | только ИГ | 🟢 |
| 10 | Виза: Тип/Кратность/Идентификатор | только ИГ | 🟢 |
| 11 | Даты прописки С/По + `АдресРегистрацииОтсутствует` (ИГ всегда True) | да | 🟢/🟡 |
| 12 | Миграционная карта: Серия/Номер, КПП въезда, Дата въезда | только ИГ | 🟢 |
| 13 | Законный представитель: ФИО, документ, место рождения | нет | 🟢 |
| 14 | Бронь: № комнаты, РезервС (заезд), РезервПо (выезд) | нет | 🟢 |
| 15 | Цель въезда/поездки, `СтепеньРодства.ID` | только ИГ | 🟢 |

### Правила форматирования
1. **Признак ИГ** — главный переключатель: для РФ поля визы/пребывания/мигркарты/целей пустые, гражданство `RUS`, тип документа `103008`. 🟢
2. **Даты**: `Формат(Дата, "ДФ=dd.MM.yyyy")`. 🟢
3. **Целочисленные ID**: `Формат(Значение, "ЧГ=")` (без разделителей групп). 🟢
4. **`ПунктВыдачиДокументаФМС`** (полиморфный резолвер, `Module.bsl:432-442`): Строка → как есть; `СправочникСсылка.ПунктыВыдачиФМС_NEW` → `Формат(.ID, "ЧГ=")`; иначе пусто. 🟢
5. Источник кодов — внешние классификаторы `*ФМС_NEW` (`ID`, `CODE_ALPHA3`, `CODE_0`, `END_DATE`). 🔴 структура не разбиралась (см. questions Q-04).

### 🔴 Пробелы контракта ФМС
- Магическое `103008` зашито в коде (Q-01).
- Десятки закомментированных `_OLD`-полей мешают восстановить точную версию формата (Q-02).
- Точный перечень и порядок всех ~94 полей восстановим только из `Module.bsl:138-429` построчно; здесь дана групповая структура. 🟡
- Структура внешних классификаторов ФМС не подтверждена (Q-04).
