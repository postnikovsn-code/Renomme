## Часть 1. Доменный глоссарий

Термины гостиничного домена в том виде, в каком они материализованы в метаданных и коде конфигурации. Для каждого термина — объект-носитель и доверие.

### 1.1 Бронирование и спрос

| Термин | Определение в системе | Носитель (метаданные) | Доверие |
|--------|------------------------|------------------------|---------|
| **Бронь / Заявка на бронирование** | Центральный документ всего жизненного цикла размещения: от резерва до выезда и расчёта. ≈80 реквизитов, 8 табличных частей, проводится по 5 регистрам. | `Document.ЗаявкаНаБронирование` | 🟢 |
| **Статус брони** | Состояние брони в жизненном цикле: Бронь · Проживает · Выехал · ОтменаБронирования · ОтказОтБронирования · Неустойка. | `Enum.СтатусБрони` | 🟢 |
| **Лист ожидания** | «Парковка» спроса: заявка без свободного номера. Реализована и как флаг `ЛистОжидания` на брони (движений не формирует), и как отдельный документ. | `Document.ЛистОжидания`, реквизит `ЗаявкаНаБронирование.ЛистОжидания` | 🟢 |
| **Заявка с сайта** | Сырая заявка с внешнего канала (сайт/Travelline), затем конвертируемая в полноценную бронь с сопоставлением клиента по ФИО/телефону. | `Document.ЗаявкаСайт` | 🟢 |
| **Канал бронирования** | Источник брони. Предопределённые: WhatsApp, МобильноеПриложение, НашСайт, ОтСтойки, Телефон, Трэвеллайн, ЭлектроннаяПочта. | `Catalog.КаналыБронирования` | 🟢 |
| **Тип бронирования** | Категория брони: Агент, КорпоративныйКлиент, Ремонт, ЧастныйГость (предопределённые). | `Catalog.ТипБронирования` | 🟢 |
| **Подтверждение бронирования** | Письмо-подтверждение или аннуляция гостю; ТЧ `Номера` ссылается на брони. | `Document.ПодтверждениеБронирования` | 🟢 |
| **Глубина бронирования** | Аналитика спроса: распределение броней по «корзинам» количества дней между датой брони и датой заезда (0-1, 2-3, 4-7, 8-14, 15-30, 31-60, >60). | `DataProcessor.ГлубинаБронирования` | 🟢 |
| **Мероприятие** | Городское событие, влияющее на спрос; фактор в прогнозе глубины бронирования и в активностях календаря. | `Catalog.Мероприятия`, `InformationRegister.АктивностиКалендарь` | 🟢 |
| **БонШанс** | «Горящий» тариф со специальной ценовой программой и особым правилом непересечения в занятости (брони БонШанс не конфликтуют между собой). | флаг-реквизит `БонШанс`, `InformationRegister.ЦеныБонШанс`, `Constant.БонШансЦена` | 🟢 |

### 1.2 Размещение и номерной фонд

| Термин | Определение в системе | Носитель | Доверие |
|--------|------------------------|----------|---------|
| **Номерной фонд / Номер (комната)** | Карточка комнаты: этаж, категория, цвет, признаки (балкон, курящий, хостел, коворкинг), соседи, общий кондиционер. Иерархия (2 уровня) моделирует здания/блоки. | `Catalog.НомернойФонд` | 🟢 |
| **Категория номера** | Тип/класс номера; несёт встроенные базовые тарифы (будни/выходные/двухместный). | `Catalog.КатегорииНомеров` | 🟢 |
| **Расчётный час / Сетка времени** | Дискретная почасовая сетка заезда/выезда: заезд Вр0/Вр6/Вр14/Вр18, выезд Вр0/Вр6/Вр12/Вр18. Превращает дату-диапазон в точный почасовой интервал. | `Enum.ВремяЗаезда`, `Enum.ВремяВыезда` | 🟢 |
| **Занятость номера** | Почасовой срез доступности комнаты: по одной записи РС на каждый занятый час. Ядро проверки доступности и шахматки. | `InformationRegister.ЗанятостьНомеров` | 🟢 |
| **Шахматка** | Визуальная сетка «номер × время» (день или 6-часовой интервал); ячейки красятся по статусу брони/цвету клиента. | `DataProcessor.Интерфейс` (форма) | 🟢 |
| **Осмотр номера** | Документ проверки комнаты с регистрацией замечаний. | `Document.ОсмотрНомера`, `InformationRegister.ЗамечанияПоНомерам` | 🟢 |
| **Хостел / Категория хостела** | Койко-место с разделением по полу размещения: М / Ж / О (общий). | флаг `Хостел`, `Enum.КатегорииХостела` | 🟢 |
| **Коворкинг (рабочее место)** | Арендуемое рабочее место с почасовой/посуточной оплатой; собственный мини-контур заявок, счетов, занятости. | `Catalog.КоворкингНомера`, `Document.КоворкингЗаявка`, `Document.КоворкингСчета` | 🟢 |

| **История клиента** | Денормализованный срез всех броней клиента (даты, номер, статус) для CRM/отчётов; ключ — ГУИД заявки. | `InformationRegister.ИсторияКлиента` | 🟢 |

|--------|-------------|----------|---------|

| **Прайс уборок / Стоимость уборок** | Цены уборок на дату назначения: Г/Т/ТС/РК/МК/МДМ, сдельные цены, цены по помещениям. Срез последних на дату начала периода ЗП. | `Catalog.ГорничныеСтоимостьУборок` | 🟢 |
| **Прачечная** | Услуги прачечной: выручка делится НДС → доля отеля (по умолч. 10%) / доля горничной. | `Document.ГорничныеПрачечная` | 🟢 |
| **Смена горничной** | Рабочая смена (дата, время открытия/закрытия). | `Document.ГорничныеСмены` | 🟢 |
| **Расчёт зарплаты горничных** | Сдельная ЗП с моделью «И/Р/Э/Есть» (исходное/ручное/эффективное/флаг замены): оклад с учётом отпуска, надбавки за стаж/стандарты, отпускные, сводный квиток. | `Document.ГорничныеЗарплата` | 🟢 |
| **Надбавка за стаж** | Шкала надбавки по диапазонам дней стажа (0.5г→500, 1г→1000, 2г→2000, 3г→3000, 5л→3500). | `InformationRegister.ГорничныеНадбавкаЗаСтаж` | 🟢 |

### 1.7 Ценообразование

| Термин | Определение | Носитель | Доверие |
|--------|-------------|----------|---------|
| **Базовая цена** | Цена «с даты установки» (ПЕРВЫЕ 1 УБЫВ по дате): фундамент каскада цены дня. | `Catalog.БазовыеЦены`, `КалендарьЦенБазовый` | 🟢 |
| **Календарь цен** | Динамический справочник цен по датам/категориям; трёхуровневый каскад База → Долгосрочная → Текущая цена. | `DataProcessor.КалендарьЦен`, регистры `КалендарьЦен*` | 🟢 |
| **Вид/тип цены календаря** | Вид: Долгосрочная / Текущая. Тип: БазоваяЦена / ДоплатаЗаДвухместный / ДоплатаЗаЗавтрак. | `Enum.КалендарьЦенВидЦены`, `Enum.КалендарьЦенТипЦены` | 🟢 |
| **Тарифный план** | Матрица цен 2×2×2 (будни/выходные × одно/двухместный × с/без завтрака). Тариф игнорирует скидку клиента. | `Catalog.ТарифныеПланы`, ТЧ `ТарифныйПланСтроки` | 🟢 |
| **Расчётный час / коэффициент суток** | Коэффициент частичных суток по времени заезда/выезда: Вр0=2, Вр6=1.5, иначе 1; выезд Вр18=1.5, Вр0=2. | `ДокументыСервер.ЗаполнитьТаблицуПроживания_Таблица` | 🟢 |
| **Скидка** | Итоговая скидка строки = MAX(категорийная/клиентская скидка, накопительная скидка по истории ночей). | `ДокументыСервер.ИтогоСкидка/СкидкаКлиента` | 🟢 |
| **Комиссия агента** | % от суммы проживания без скидки + % от услуг ПРОЖИВАНИЕ_УСЛУГИ для турагентств. | `ДокументыСервер.СуммаКомиссии` | 🟢 |
| **B2B-наценка** | Наценка `Окр(Цена/((100−%)/100) − Цена)×Количество` для строк с флагом В2В. | `ДокументыСервер.СуммаВ2В` | 🟢 |
| **ADR (средняя цена номера)** | Average Daily Rate: выручка / число проданных номеро-ночей. Считается раздельно по одно-/двухместным. | `ЕжедневныйОтчетФакт` | 🟢 |
| **Загрузка (occupancy)** | Процент заселяемости: занятые номера / общее число непомеченных номеров × 100. | `ЕжедневныйОтчетФакт`, `ОбщееКоличествоНомеров()` | 🟢 |
| **Цены конкурентов / Задание цен по загрузке** | Аналитика средней цены конкурентов и динамическое задание цены по корзинам загрузки (30/45/60/75/90%). | `Document.ЦеныКонкурентовАналитика`, `КалендарьЦенЗаданиеНаЦены` | 🟢 |

## Часть 3. Сквозные неявные принципы (вывод Detective)

1. **Двойственность контуров учёта** 🟡 — система переживает незавершённую миграцию: долги (ТЧ заявки vs регистры `Деньги/Долги`), цены (`'20240401'`-граница), ФМС-данные (`_NEW`/`_OLD`). См. ADR 0001, 0003, 0007.
2. **Почасовая модель занятости** 🟢 — фундаментальный инвариант: и номера, и коворкинг хранят занятость по одной записи РС на час/день. Это объединяет бронирование, коворкинг и аудит. См. ADR 0002.
3. **Сеть отелей как код** 🟡 — мультиотельность (Реноме/Лайв/Чехов/ДомСоветов/СтритАрт) зашита в `НастройкиСервер.Это*()` и ветвления по имени, а не в конфигурируемой сущности «Организация». См. ADR 0008.
4. **RBAC в коде, а не в ролях** 🟢 — доменное разграничение ресепшна реализовано булевым реквизитом `Пользователи.Админ`, а не механизмом ролей платформы (`.rights` почти пусты по домену). См. `permissions.md` и ADR 0010.
5. **Интеграция через отдельные базы по COM** 🟢 — горничные, картинки, бонусы вынесены в самостоятельные базы 1С, связанные синхронным COM-обменом. См. ADR 0005.
6. **БПО как фундамент** 🟢 — вся фискальная/торговая периферия делегирована типовой Библиотеке подключаемого оборудования ред. 3.2 через тонкий слой обёрток. См. ADR 0006.

## 🔴 ПРОБЕЛЫ доменного анализа

- 🔴 Точная семантика регистров `Деньги`/`ПродажиТоваров` — заявлены как регистраторы, но фактически не наполняются; неясно, отчётность какого периода на них ещё опирается.
- 🔴 Связь двух товарных контуров (минибар `НоменклатураМиниБара` vs «Бар» `Товары`) — синхронизация остатков в коде не обнаружена.
- 🔴 Document.АнкетаНовая (самоописываемая структура с 5 ТЧ ответов) — доменная модель опроса гостей не разобрана.
- 🔴 Формула `СуммаАгентскогоВознаграждения`/`ADR_НА`/`Процент_НА` витрины `ЕжедневныйОтчетФакт` — точный расчёт не локализован.
- 🔴 Внешние классификаторы ФМС (`СтраныФМС_NEW`/`ТипДокументаФМС_NEW`/`ПунктыВыдачиФМС_NEW`) — структура справочников не разбиралась.
