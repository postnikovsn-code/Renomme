## Граница: что библиотека, что домен

```
┌─────────────────────────── Домен «ОТЕЛЬ» (наш код) ───────────────────────────┐
│  ФУ_Клиент / ФУ_Сервер   ОплатыЧекКлиент   СерверККМ (HTTP)   АТОЛ10106         │
│  Document.ПоказанияДатчиков · Catalog.Датчики (телеметрия — доменное расширение)│
└───────────────┬───────────────────────────────────────────────┬───────────────┘
                │ вызовы фасадов (стабильный контракт)            │ HTTP JSON
                ▼                                                 ▼
┌──────── Типовая БПО ред. 3.2 (НЕ МОДИФИЦИРУЕТСЯ) ────────┐  ┌────────────────┐
│ МенеджерОборудования* · ОборудованиеЧекопечатающие*      │  │ Внешний        │
│ ОборудованиеПлатежныеСистемы* · ОблачныеККТ*             │  │ «Сервер ККМ»   │
│ РаспределеннаяФискализация* · РассылкаЭлектронныхЧеков*  │  │ (АТОЛ, REST)   │
│ Маркировка* · ФорматноЛогическийКонтроль* · драйверы    │  └────────────────┘
└─────────────────────────────────────────────────────────┘
```

> **🟢 Контракт библиотеки стабилен.** Домен вызывает фасады; внутренности (ФН, протоколы
> драйверов, ФЛК/ИСМ/ЕГАИС) — чёрная коробка (ADR-0006).

## Дерево подсистемы `ПоддержкаОборудования` (кратко, 🟢)

- `ПоддержкаОборудования`
  - `HttpBridge` — мост HTTP-вызовов библиотеки.
  - `ЛогированиеОборудования` — журналирование операций.
  - `НастройкиПрограммы` — `DataProcessor.ПанельАдминистрированияБПО`.
  - `ПодключаемоеОборудование`
    - `Несертифицированное`, `ОблачныеККТ`, `ПлатежныеСистемы` (эквайринг), `УстройствоРаспознавания` (весы/сканеры)
    - `ЧекопечатающиеУстройства`
      - `АвтономнаяККТ`, `КассоваяСмена`, `Маркировка`, `РаспределеннаяФискализация`, `РассылкаЭлектронныхЧеков`, `ФорматноЛогическийКонтроль (ФЛК)`
  - `СообщенияВСлужбуТехническойПоддержки`
  - `ЭлектронныеСертификаты` (→ `СертификатыНУЦМинцифры`)

(Полная карта файлов — в `legacy-mapping.md`.)

## Fluxo Principal — пробитие чека (🟢)

1. Форма кассы → `ОплатыЧекКлиент.ЧекОплаты(ДопПараметры, Форма)` (`ОплатыЧекКлиент/Module.bsl:6`).
2. `ЧекОплатыДействие(ДопПараметры)` (`:30`) — оркестрация.
3. `ЗаполнитьПозицииЧекаККМОплата*` (`:367`, `:502`, `:506`, `:571`) — сборка позиций по типу долга (проживание/групповой счёт/коворкинг/аванс) с учётом предыдущих оплат (`СуммаПредыдущихОплат*`).
4. Параметры строк чека и оплат — через `ОборудованиеЧекопечатающиеУстройстваКлиентСервер.ПараметрыФискальнойСтрокиЧека()` / `ПараметрыСтрокиОплаты()` (фасад библиотеки).
5. Реквизиты: `ФУ_Сервер.ПолучитьДанныеОрганизацииДляФУ()`, `ФУ_Сервер.Кассир(ЭтоКоворкинг)`.
6. Ветвление по способу фискализации (см. `flowcharts/Оборудование-ПробитиеЧека.md`):
   - **Локальная ККТ** → `ОборудованиеЧекопечатающиеУстройстваКлиент.НачатьПробитиеЧека(...)`
   - **Сервер ККМ** (если `ЭтоСерверККМ()`) → `СерверККМ.ВыполнитьЗапрос(HTTP)`
   - **Облачная ККТ** → `ОборудованиеЧекопечатающиеОблачныеККТ*`
   - **Распределённая** → запись в РС `ОчередьЧековККТ`
7. Результат → `ФУ_Клиент.ОперацияЗавершение(Результат, Параметры)` (`ФУ_Клиент/Module.bsl:5`).
8. Фиксация в РС `ФискальныеОперации`; при необходимости — постановка в `Catalog.ОчередьЭлектронныхЧековКОтправке`.

## Fluxos Alternativos

- **Подключение устройства:** `ПриОткрытии_Подключить` → `МенеджерОборудованияКлиентПовтИсп.РабочееМестоКлиента()` → `МенеджерОборудованияКлиент.НачатьПодключениеОборудованиеПоТипу(...)` → загрузка внешней компоненты драйвера. Привязка через `Catalog.РабочиеМеста` + `SessionParameter.РабочееМестоКлиента`. (см. `flowcharts/Оборудование-ПодключениеУстройства.md`) 🟢
- **Открытие смены через Сервер ККМ:** `СерверККМ.СоздатьСоединение` → `ОткрытьСмену(Соединение)`; токен обновляется автоматически. 🟢
- **Показания датчиков:** `Document.ПоказанияДатчиков.ОбработкаПроведения` → запись РС `ПоказанияДатчиков` по строкам ТЧ. 🟢
- **Рассылка эл. чеков:** очередь + `ScheduledJob.РассылкаЭлектронныхЧеков`; режим по константе. Ошибка → повтор на следующем запуске. 🟢
- **Ошибка операции:** библиотека/обёртка возвращает структуру с `Ошибка=Истина`; домен показывает сообщение и пишет в РС-журнал. 🟢

## Dependências

- **Типовая БПО ред. 3.2** (фасады `МенеджерОборудования*`, `ОборудованиеЧекопечатающиеУстройства*`, `РаспределеннаяФискализация*`, `РассылкаЭлектронныхЧеков*`, `Маркировка*`, `ФЛК*`) — собственно фискализация/драйверы. 🟢
- **Внешний «Сервер ККМ»** (АТОЛ, REST `/PrintService/api/v2/`) — альтернативный способ фискализации. 🟢
- `Catalog.РабочиеМеста` + `SessionParameter.РабочееМестоКлиента` — привязка оборудования к РМ. 🟢
- `Catalog.ПодключаемоеОборудование`, `Catalog.ДрайверыОборудования` — реестр устройств/драйверов (наполняются библиотекой/АТОЛ10106). 🟢
- Домен «Финансы» — `Document.КассоваяСмена`, источники долгов/оплат для позиций чека. 🟢
- `CommonTemplate.Драйвер*` (63 шаблона) — бинарные внешние компоненты драйверов. 🟡

## Decisões de Design Identificadas

| Decisão | Evidência no código | Confiança |
|---------|---------------------|-----------|
| Доступ к библиотеке только через тонкий слой обёрток (`ФУ_*`/`ОплатыЧекКлиент`/`СерверККМ`) | ADR-0006; модули обёрток | 🟢 |
| 4 сосуществующих способа фискализации | `flowcharts/Оборудование-ПробитиеЧека.md`; фасады | 🟢 |
| Внешний Сервер ККМ — HTTP REST с токен-авторизацией | `СерверККМ/Module.bsl:137-163` | 🟢 |
| Все операции с оборудованием асинхронные (callback) | `ФУ_Клиент` (`Начать…`, `ОписаниеОповещения`) | 🟢 |
| Журналы операций + регламентная очистка по сроку хранения | РС `*Операции*` + ScheduledJob `Очистка…` | 🟢 |
| Телеметрия датчиков — доменное расширение, не часть БПО | `flowcharts/Оборудование-ПоказанияДатчиков.md` | 🟢 |

## Estado Interno

- **Соединение Сервера ККМ** — структура `{Параметры, Токен{Идентификатор, ВремяИстечения}, Ошибка, Описание}`; токен живёт до `ВремяИстечения`, обновляется лениво (`ОбновитьТокен`, `:153`). 🟢
- **Кассовая смена** — состояние в `Document.КассоваяСмена` (домен) и `SessionState` на стороне Сервера ККМ (1 закрыта / 2 открыта / 3 истекла). 🟢
- **Очередь эл. чеков** — `Catalog.ОчередьЭлектронныхЧековКОтправке` (контакт, тип рассылки, статус). 🟢
- **РС-журналы** — `ФискальныеОперации`, `ПлатежныеОперации`, `ОперацииПроверкиКМ`, `ОчередьЧековККТ`, `ОперацииСПодключаемымОборудованием`, `ПоказанияДатчиков`. 🟢
- **Идентификатор подключённого объекта оборудования** — хранится на форме после подключения. 🟢

## Observabilidade

- Подсистема `ЛогированиеОборудования` — централизованное журналирование операций библиотеки. 🟢
- `ФУ_Сервер.ЗаписатьОшибкуКММ(ТекстОшибки)` — фиксация ошибок ККМ. 🟢
- РС-журналы операций — аудит-след каждой фискальной/платёжной операции. 🟢
- Подсистема `СообщенияВСлужбуТехническойПоддержки` — эскалация инцидентов. 🟡

## Riscos e Lacunas

- 🔴 Внутренности библиотеки БПО (ФН, протоколы драйверов, ФЛК/ИСМ/ЕГАИС) построчно не разбирались — осознанная граница (ADR-0006).
- 🔴 `СерверККМ.СоздатьСоединение` — дефолтные `Admin/Admin`; неизвестно, переопределяются ли при реальном вызове (Q-01).
- 🔴 Наполнение ТЧ `Document.ПоказанияДатчиков` (опрос физического устройства/импорт кадра) вне `ObjectModule` — не локализовано (Q-02).
- 🟡 `DataProcessor.ПечатьУведомления_OLD` — устаревшая версия (tech-debt маркер).
- 🟡 Множество `…Переопределяемый`/`…Локализация` модулей — точки расширения БСП/локализации, специфика не разбиралась.
- 🟡 Транспорт доставки электронного чека (email/SMS/мессенджер) — внутри библиотеки/интеграций.
