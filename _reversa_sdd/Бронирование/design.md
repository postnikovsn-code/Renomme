## Основной поток — проведение брони

См. `flowcharts/Бронирование-ОбработкаПроведения.md`. Порядок (`ObjectModule.bsl:4-140`):

1. **Валидация:** `Отказ = Не ПроверкаЗаполнения()` — при незаполненных реквизитах отмена (`:5-6`). 🟢
2. **Ранний выход:** если `ЛистОжидания` истина → `Возврат`; если `Статус ∈ {ОтменаБронирования, ОтказОтБронирования}` → `Возврат` (движений нет) (`:8-11`). 🟢
3. **Проверка занятости:** `ДокументыСервер.ЗанятостьНомераПроверить(...)`; при конфликте — сообщение «Номер занят… ЗАПИСЬ ОТМЕНЯЕТСЯ», `Отказ = Истина` (`:13-18`). 🟢
4. **История клиента:** `ЗаявкаСервер.ОбновитьИсториюКлиента(ЭтотОбъект)` (`:20`). 🟢
5. **Расчёт периода резерва (ТемпС/ТемпПо):** для суточной брони (`РезервС=РезервПо`) — спец-обработка (+24ч либо окно 13:00–18:00); `ТемпПо = ТемпПо − 1` (исключение последнего часа) (`:23-40`). 🟡
6. **Запрос существующих записей** занятости часа (один раз до цикла). 🟢
7. **Почасовой цикл** `Пока ТемпС < ТемпПо` шагом 3600: запись `ЗанятостьНомеров` (Номер, Клиент, час, Зарезервирован, БонШанс, `Номер_пп+1` при наложении) (`:61-76`). 🟢
8. **Движения `Взаиморасчеты`:** по каждой строке ТЧ `Счета` — расход на сумму долга счёта (`:78-91`). 🟢
9. Закомментированный блок `ДобавитьДвиженияДолг` (`:96-138`) — мёртвый код. 🔴

## Альтернативные потоки

- **Лист ожидания / отмена / отказ (BR-01, BR-02):** ранний `Возврат` без движений (`:8-11`). 🟢
- **Конфликт занятости (BR-03):** сообщение + `Отказ = Истина`, движения не пишутся. 🟢
- **Суточная бронь (BR-06):** расширение окна или принудительное 13:00–18:00. 🟡
- **БонШанс (BR-07):** в запросе занятости добавляется `И БонШанс = ЛОЖЬ` — резервы БонШанс не конфликтуют между собой. 🟡
- **Мульти-резерв (BR-08):** `Номер_пп` инкрементируется при наложении в одном часе. 🟡
- **Конвертация сайта (BR-11, BR-12):** при дубле — предупреждение; при неоднозначном клиенте — ручной выбор/создание. 🟢/🟡
- **Юрлицо при split-bill:** версия `_1` учитывает `НЕ ЮрЛицо` (не делит счёт юрлицам); основная версия эту проверку закомментировала. 🟡 поведенческое расхождение.

## Проверка занятости (деталь)

См. `flowcharts/Бронирование-ЗанятостьНомераПроверить.md`. `ДокументыСервер.ЗанятостьНомераПроверить:264-311`:
- Вычисляет период резерва через `ЗанятостьНомераПериодРезерва` (маппинг времён в часы, BR-05).
- Запрос к `РС.ЗанятостьНомеров`: `Номер = НомерКуда`, `ПериодРезерва` в `[Начало; Конец−1]`, `Регистратор <> ТекущийРегистратор`, группировка по Номер/Регистратор.
- При `БонШанс` динамически добавляет `И БонШанс = ЛОЖЬ`.
- Найдены строки ⇒ `Результат = Истина` (занят), `Регистратор` = первый конфликтующий.

## Разделение счёта (деталь)

См. `flowcharts/Бронирование-РазделениеСчета.md`. `ЗаявкаСервер.УстановитьЦенаСуммаДляРазделитьСчет:432-446`:
- При `РазделитьСчет И ЕстьКлиент2`: первый гость `X/2 + 0.001`, второй `X − X/2 − 0.001`.
- ±0.001 — приём против потери копейки на нечётных суммах (сумма частей = целому).
- Для `СчетаДетальноДолги` дополнительно корректируется `СуммаКЗакрытию` (`:393-427`).

## Глубина бронирования (деталь)

См. `flowcharts/Бронирование-ГлубинаБронирования.md`. `ГлубинаБронирования.СформироватьНаСервере:22-195`:
- `РазностьДат` = дни между датой брони и датой заезда; раскладка по корзинам `0-1, 2-3, 4-7, 8-14, 15-30, 31-60, >60`.
- `ПрогнозЗагрузки = Окр((ИтогоНомеров / КоличествоНомеров) · 100)`.
- Добавляются `Мероприятия` города на дату.
- 🔴 4 почти идентичных версии (`_1`/`_2`/`_3`/без суффикса) — активная неочевидна.

## Структуры данных

- **`ЗаявкаНаБронирование`** — ТЧ: `Проживание` (посуточно), `ДопУслуги`, `ДопПожелания`, `ЗабытыеВещи`, `Счета`, `СчетаДетальноДолги`, `СчетаДетальноСтроки`, `РаспределениеОплатДолги`. Внутридокументная нормализация «много счетов на бронь» через UUID-поля `СчетГУИД`/`ДолгиГУИД`. 🟢
- **`ЗанятостьНомеров`** — одна запись на час; измерение `ПериодРезерва` хранит точный час (`Date`). 🟢
- **`ЗаявкаСайт`** — плоский набор полей канала (см. `contracts.md`). 🟢

Полный словарь реквизитов — `data-dictionary.md` § «Модуль: Бронирование».

## Зависимости

- **`ДокументыСервер`** — проверка занятости, расчёт периода резерва, округления, комиссии (вызывается из проведения). 🟢
- **`ЗаявкаСервер`** — пересборка счетов, история клиента, split-bill (вызывается из `ПередЗаписью`/`ОбработкаПроведения`). 🟢
- **Модуль «Размещение»** — `НомернойФонд`, `КатегорииНомеров` (объект резерва). 🟢
- **Модуль «Ценообразование»** — `ТарифныеПланы`, `КалендарьЦен`, `РасчетПроживания`/`ЗаполнитьТаблицуПроживания` (расчёт сумм проживания). 🔴 тело не разобрано.
- **Модуль «Финансы и касса»** — `КассовыйДокумент`, `ВыпискаБанка`, `ПрочиеОплаты`, `ГрупповыеСчета` (оплаты/долги). 🟢
- **Модуль «Интеграции и обмен»** — поступление `ЗаявкаСайт` (Travelline/сайт/мессенджеры). 🟡 (ADR-0009)
- **Подсистема прав** — `ПараметрыСеанса.ТекущийПользователь.Админ` для удаления (ADR-0010). 🟢

## Внутреннее состояние

Состояние брони хранится в реквизите `Статус` (`Enum.СтатусБрони`) и эволюционирует по машине состояний (см. `flowcharts/Бронирование.md`, `state-machines.md`):
`Бронь → Проживает → Выехал`; ветви `ОтменаБронирования`/`ОтказОтБронирования`/`Неустойка`. Движущими являются все статусы, кроме двух отмен и брони с `ЛистОжидания`. Резерв материализуется в `ЗанятостьНомеров`; финансовое состояние — в ТЧ `Счета`/`СчетаДетальноДолги` и регистре `Взаиморасчеты`. 🟢
