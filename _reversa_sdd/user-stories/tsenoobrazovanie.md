## US-PR-01 — Базовые тарифы по категориям

**Как** Менеджер/Руководитель, **я хочу** задать базовые тарифы по категориям номеров (будни/выходные/двухместный), **чтобы** иметь отправную точку ценообразования.

Источник: `Catalog.КатегорииНомеров` (БазовыйТарифБудни/Выходные/БудниДвух), `Catalog.БазовыеЦены`. 🟢

### Критерии приёмки
```gherkin
Дано категория номера с базовыми тарифами
Когда рассчитывается цена дня
Тогда базой служит тариф категории (с разделением будни/выходные)
```
🟢

## US-PR-02 — Календарь цен (матрица года)

**Как** Менеджер/Руководитель, **я хочу** редактировать цены по дням в матрице года, **чтобы** управлять ценой точечно и по диапазонам.

Источник: `DataProcessors/КалендарьЦен/Forms/Форма/Module.bsl` (2826 стр.), РС `КалендарьЦенБазовый`, `КалендарьЦенКатегории`. 🟢

### Критерии приёмки
```gherkin
Дано открыт календарь цен на год
Когда менеджер изменяет выбранные ячейки
Тогда правки пишутся в РС КалендарьЦенБазовый/КалендарьЦенКатегории
  И ведётся история изменений (КалендарьЦенБазовыйИстория/КатегорииИстория)
```
🟢 `КалендарьЦен:1565-1661,1664,1681`.

## US-PR-03 — Каскад цены дня

**Как** Администратор стойки, **я хочу** получить цену конкретного дня по приоритетной модели, **чтобы** видеть актуальную цену для брони.

Источник: `CommonModules/КалендарьЦен` (ПолучитьБазоваяЦенаДня / ДолгосрочнаяЦенаДня / ТекущаяЦенаДня). 🟢

### Критерии приёмки
```gherkin
Дано дата проживания
Когда запрашивается цена дня
Тогда применяется каскад: текущая цена → долгосрочная цена → базовая цена
  И учитывается граница перехода на новый календарь цен (01.04.2024, ADR-0003)
```
🟢 `КалендарьЦен/Module.bsl:57-224`; `ДокументыСервер.ДатаПереходаНаНовыйКалендарьЦен:369-371`.
🔴 legacy `ДокументыСервер_Старый`/`КалендарьЦен_Старый` для дат < 01.04.2024 построчно не разобраны.

## US-PR-04 — Тарифные планы и БонШанс

**Как** Менеджер/Руководитель, **я хочу** применять тарифные планы и горящие цены (БонШанс), **чтобы** гибко продавать номера.

Источник: `Catalog.ТарифныеПланы`, РС `ЦеныБонШанс`, `ДокументыСервер.ЦенаНаДеньТарифныйПлан/ПолучитьБонШансЦена`. 🟢

### Критерии приёмки
```gherkin
Дано бронь с тарифным планом
Когда рассчитывается цена
Тогда применяется ЦенаНаДеньТарифныйПлан
Дано бронь с флагом БонШанс
Когда рассчитывается цена
Тогда применяется горящая цена из РС ЦеныБонШанс
```
🟢 `ДокументыСервер:553-628,405-425`.

## US-PR-05 — Расчёт стоимости проживания и скидки

**Как** Администратор стойки, **я хочу** рассчитать итоговую стоимость проживания с учётом скидок гостя, **чтобы** выставить корректную сумму в заявке.

Источник: `DataProcessors/РасчетПроживания`, `ДокументыСервер.ЗаполнитьТаблицуПроживания_Таблица/СкидкаКлиента/РасчитатьДолг`. 🟢

### Критерии приёмки
```gherkin
Дано бронь с периодом и категорией номера
Когда выполняется расчёт проживания
Тогда по дням заполняется ТЧ Проживание (цена дня × применённые скидки)
  И применяется скидка категории клиента и накопительная скидка клиента
  И рассчитывается итоговый долг (РасчитатьДолг)
```
🟢 `ДокументыСервер:428-513,676-768,890-937`. 🔴 накопительная скидка по истории ночей — на уровне контракта.

## US-PR-06 — Цены конкурентов и аналитика

**Как** Менеджер/Руководитель, **я хочу** загрузить цены конкурентов и сравнить со своими, **чтобы** принимать решения о ценообразовании.

Источник: `Document.ЦеныКонкурентовАналитика`, `DataProcessors/ЦеныКонкурентов(_С_ТревелЛайн)`, `КалендарьЦен.СредняяЦенаКонкурентовАналитика`. 🟢/🟡

### Критерии приёмки
```gherkin
Дано загружены цены конкурентов по датам/отелям
Когда формируется аналитика
Тогда показывается средняя цена конкурентов и расшифровка против собственных цен
```
🟢 `КалендарьЦен:577-595`. 🟡 загрузчики цен конкурентов вглубь не разобраны.

## US-PR-07 — Задание цены по загрузке

**Как** Менеджер/Руководитель, **я хочу** задавать цену в зависимости от прогноза загрузки (корзины), **чтобы** реализовать динамическое ценообразование.

Источник: `DataProcessors/КалендарьЦенЗаданиеНаЦены`. 🟢

### Критерии приёмки
```gherkin
Дано прогноз загрузки разложен по корзинам (границам)
Когда создаётся задание на цены
Тогда цена назначается по границе значения загрузки (ГраницаЗначение)
  И задание записывается (ЗаписатьЗаданиеНаСервере)
```
🟢 `КалендарьЦенЗаданиеНаЦены:13,390,408,440`.
