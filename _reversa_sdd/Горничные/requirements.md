> Файл `requirements.md`. Фокус — ЧТО делает модуль, не как. Уровень: detalhado. Каждое утверждение помечено 🟢 (подтверждено кодом) / 🟡 (выведено) / 🔴 (пробел).

## Обзор

Модуль учитывает работу горничных отеля: уборку номеров и помещений, смены, услуги прачечной, расчёт стоимости уборок и зарплаты. Физическая регистрация уборок и смен ведётся в **отдельной базе 1С «Горничные»** (планшеты горничных); в базу «ОТЕЛЬ» данные **загружаются** через синхронное COM-соединение, после чего по ним считается сдельная зарплата 🟢. Зарплата горничных (включая оклад, надбавку за стаж, отпускные, прачечную) рассчитывается именно здесь; зарплата администраторов — в модуле «Персонал» 🟢.

## Ответственности

- Двусторонняя синхронизация справочников (горничные, помещения, номенклатура минибара, типы комплектаций) между «ОТЕЛЬ» и БД горничных по COM 🟢.
- Создание задания на уборку в БД горничных при проведении/изменении брони (`СоздатьЗаявку`) 🟢.
- Загрузка фактов уборки/помещений/смен из БД горничных в документы «ОТЕЛЬ» с защитой ручных правок 🟢.
- Проведение уборок номеров в регистр сведений `УборкиНомеров` (основа сдельного учёта) 🟢.
- Деление выручки прачечной: НДС → доля отеля → доля горничной 🟢.
- Расчёт зарплаты горничных за период по модели «И/Р/Э/Есть» (оклад, отпуск, надбавка за стаж, надбавка за стандарты, сдельные уборки, помещения, прачечная) 🟢.
- Поддержка прайса уборок на дату (`ГорничныеСтоимостьУборок`) и шкалы надбавки за стаж (`ГорничныеНадбавкаЗаСтаж`) 🟢.

## Бизнес-правила

- Любая процедура обмена с БД горничных начинается с проверки тумблера `Константа.ОбменСГорничными`; при `Ложь` — немедленный выход 🟢 (`ОбменГорничныеСервер` строки 49-50, 120-121, 657-658).
- Горничная выгружается в БД горничных только если `УчетУборок = Истина` и изменился один из ключевых реквизитов (Наименование/Сортировка/НеРаботает/ПометкаУдаления/УчетУборок) 🟢 (`Catalog.Горничные.ObjectModule.ПроверкаОбмена` 19-30).
- Ключ обмена горничной — `ГорничнаяГУИДСтрока`; при первой записи он заполняется строкой GUID ссылки 🟢 (ObjectModule 10-13).
- Записи, пришедшие из обмена (`ОбменДанными.Загрузка = Истина`), не выгружаются обратно — защита от «эха» 🟢 (ObjectModule 6, 33; входящие процедуры пишут с этим флагом — строки 722, 749, 776, 802).
- Документ уборки с `РучноеИзменение = Истина` при повторной загрузке пропускается (не перезаписывается) 🟢 (`ОбменГорничныеСервер` 214).
- Сдельная часть зарплаты учитывается только при `Горничная.УчетУборок = Истина`; иначе = 0 🟢 (code-analysis §2.1).
- Оклад начисляется пропорционально расчётным дням: `Оклад_расч = Окр(Оклад_месяц × РасчётныеДни / ДнейВМесяце)`, `РасчётныеДни = ДнейПериода − ДниОтпуска` 🟢 (§2.2).
- Надбавка за стаж определяется по шкале диапазонов (`РазницаВДняхС <= стаж < РазницаВДняхПо`, срез на ДК) и начисляется пропорционально периоду 🟢 (§2.3).
- Деление выручки прачечной: `СуммаНДС = Окр(СуммаОплаты × СтавкаНДС/(100+СтавкаНДС))`; `СуммаОтелю = Окр(СуммаБезНДС × ПроцентОтеля/100)` (по умолчанию `ПроцентОтеля = 10`); остаток — горничной 🟢 (§2.7, flowchart Прачечная).
- При создании задания уборки, если у номера не заполнен `НомерГорничные`, оператору выдаётся сообщение и задание не создаётся 🟢 (`СоздатьЗаявку` 54-62).
- При загрузке уборки, если номер не найден в `НомернойФонд` или `ГорничныеНомера` — строка пропускается с сообщением 🟢 (193-209).
- Горничная при загрузке ищется по наименованию; при отсутствии — авто-создаётся 🟢 (264-275).
- Минибар сопоставляется по коду (`НоменклатураМиниБара.НайтиПоКоду`); цена берётся из карточки номенклатуры, при ненайденной — 0 с сообщением 🟢 (288-299).
- Видимость реквизитов и набор надбавок на форме зарплаты зависят от профиля отеля (`НастройкиСервер.ЭтоЛайв()/ЭтоЧехов()/…`) 🟡 (§4).
- Конкретная структура печатных форм и отчётов (ОбщийКвиток, 4 отчёта) не разобрана 🔴.

## Критерии приёмки

```gherkin
# RF-01 — создание задания (happy)
Дано константа ОбменСГорничными = Истина
  И у номера брони заполнен реквизит НомерГорничные
  И COM-соединение с БД горничных установлено
Когда проводится/изменяется заявка на бронирование
Тогда в БД горничных создаётся заявка с тем же GUID, статусом и временами заезда/выезда

# RF-01 — отказ: не заполнен номер горничной
Дано константа ОбменСГорничными = Истина
  И у номера брони НЕ заполнен реквизит НомерГорничные
Когда вызывается СоздатьЗаявку
Тогда оператору выводится сообщение «Не заполнен реквизит Номер Горничные…»
  И задание в БД горничных не создаётся

# RF-02 — загрузка уборок (happy)
Дано константа ОбменСГорничными = Истина и соединение установлено
  И в БД горничных есть факты уборки за период с известными номерами и горничными
Когда вызывается ЗагрузитьОбслуживаниеНомеров(С, По, НомерГорничные)
Тогда по каждому факту создаётся/обновляется документ ГорничныеОбслуживаниеНомера
  И документ проводится, формируя запись в РС УборкиНомеров

# RF-02/RF-06 — отказ: защита ручных правок
Дано документ ГорничныеОбслуживаниеНомера с РучноеИзменение = Истина
Когда повторно вызывается ЗагрузитьОбслуживаниеНомеров на тот же период
Тогда документ пропускается и его реквизиты не изменяются

# COM недоступна (failure, общий)
Дано константа ОбменСГорничными = Истина
  И COM-соединение с БД горничных недоступно после 3 попыток
Когда вызывается любая процедура обмена
Тогда выводится сообщение «Нет связи с БД Горничные…»
  И операция завершается без изменения данных

# RF-08 — исходящая синхронизация горничной (happy)
Дано горничная с УчетУборок = Истина
  И изменилось её Наименование
Когда горничная записывается (не из обмена)
Тогда ОбновитьГорничнаяГорничные выгружает структуру (Наименование, Сортировка, НеРаботает, ПометкаУдаления, ГорничнаяГУИДСтрока) в БД горничных

# RF-08 — отказ эха: запись из обмена
Дано входящий COM-вызов ОбновитьГорничныеОтель пишет элемент с ОбменДанными.Загрузка = Истина
Когда элемент записывается
Тогда обратная выгрузка в БД горничных НЕ выполняется

# RF-11 — деление прачечной (happy)
Дано строка прачечной с СуммаОплаты и ПроцентОтеля = 10, СтавкаНДС задана
Когда вызывается ОбновитьСуммаПрачечная
Тогда СуммаНДС = Окр(СуммаОплаты × СтавкаНДС/(100+СтавкаНДС))
  И СуммаОтелю = Окр(СуммаБезНДС × 10/100)
  И СуммаПрачечная (к выдаче) = Окр(СуммаБезНДС × (1 − 10/100))

# RF-13 — оклад с отпуском (happy)
Дано горничная с месячным окладом и отпуском внутри периода ДН..ДК
Когда выполняется расчёт зарплаты
Тогда Оклад_И = Окр(Оклад × (ДниПериода − ДниОтпуска) / ДнейВМесяце)

# RF-16 — сдельная часть отключена (failure-путь правила)
Дано горничная с УчетУборок = Ложь
Когда выполняется расчёт зарплаты
Тогда суммы сдельных уборок (Г/Т/ТС/РК/МК/МДМ) = 0
```
