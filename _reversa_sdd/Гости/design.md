## Основной поток

### Запись карточки клиента (антидубль)
1. `ФормаЭлемента.ПередЗаписью` — для физлица собрать наименование из Фамилия+Имя+Отчество. 🟢
2. `КлиентПоНаименованию()` — поиск по наименованию (если вид клиента не «Исключить из отчётов»). 🟡
3. Если ИНН заполнен и ≠ "0" — `КлиентПоИННКППСсылка()`. 🟢
4. `ДокументыСервер.ПроверитьКонтрагента`. 🟢
5. При найденном дубле — `Отказ = Истина`, открыть карточку существующего. 🟢
6. Иначе `ObjectModule.ПередЗаписью` присваивает `ГУИД_ИсточникОбмена`. 🟢

### Распознавание паспорта (PassportBox)
1. `ПолучитьСоединениеПоНастройкам()` — проверка `PassportBoxАктивность` + IP из констант. 🟢
2. `РаспознатьДокумент(Соединение)` → HTTP `/CaptureDocument` → JSON. 🟢
3. `НоваяСтруктураРеквизитовПаспорта()` — пустой шаблон (11 полей). 🟢
4. `ЗаполнитьПоляИзJSON` для источников в порядке page3 → OCR → MRZ; непустое более приоритетное перезаписывает. 🟢
5. Проверка `doc_type` (`rus.passport.national`). 🟢
6. `ТРег` к ФИО (дефис обрабатывается). 🟢
7. Проверка 9 обязательных полей; при пустом — ошибка «Страница не распознана». 🟢
8. `ПолучитьФотографииПаспорта` — обязательна page3. 🟢
9. Возврат `НовыйРезультатДанных {Реквизиты, Фотографии}`. 🟢

### Выгрузка ФМС
1. Сбор пар «клиент + бронь»: брони с `ВремяЗаездаТочное` = дата заезда; `Клиент` и `Клиент2` → отдельные строки. 🟢
2. Запись шапки `#v.2.0.0;...;`. 🟢
3. Для каждой пары — `СформироватьСтрокуДляФМС(Клиент, Бронь)`:
   - поле 1: `ИностранныйГражданин` → 1/0; 🟢
   - ФИО (кириллица + латиница), Пол, ДатаРождения; 🟢
   - место рождения (страна CODE_ALPHA3, регион, район, город, насп.); 🟢
   - гражданство: ИГ → `ГражданствоФМС_NEW.CODE_ALPHA3`, РФ → `RUS`; 🟢
   - тип документа: ИГ → `ТипДокументаФМС_NEW.ID`, РФ → `103008`; 🟢 (магическое число — см. questions)
   - реквизиты документа + `ПунктВыдачиДокументаФМС`; 🟢
   - адреса регистрации/прежнего проживания; 🟢
   - пребывание/виза/мигркарта/цели/степень родства — только ИГ; 🟢
   - № комнаты, РезервС (заезд), РезервПо (выезд). 🟢
4. Запись файла `<10 симв. даты>.csv` в каталог `ПАПКА_ВыгрузкаДляФМС`. 🟢

### Объединение клиентов
1. `ПоказатьВопрос` — подтверждение (клиент-результат). 🟢
2. `НачатьТранзакцию`. 🟢
3. Для каждой отмеченной строки `ЗаменитьКлиента`:
   - `ЗаявкаНаБронирование`: Бронирует/Турагентство/Оплачивает/Клиент + ТЧ Счета (Контрагент/Клиент) → `Записать(Проведение)`; 🟢
   - РС `ИсторияКлиента` (Клиент), `ИсторияКлиентаДопПожелания` (Контрагент); 🟢
   - `ГрупповыеСчета.Контрагент`, `ВыпискаБанка.ОтКого`; 🟢
   - `НайтиПоСсылкам(исходный)`: есть ссылки → сообщить, нет → пометить на удаление. 🟢
4. `ЗафиксироватьТранзакцию`. 🟢

## Альтернативные потоки
- **PassportBox недоступен/выключен:** `ПолучитьСоединениеПоНастройкам` возвращает ошибку; распознавание отдаёт структуру-ошибку, реквизиты не меняются. 🟢
- **Неверный тип документа:** возврат «Неверный тип документа» до проверки полей. 🟢
- **Нет фото page3:** возврат «нет фото 3-й страницы» даже при заполненных полях. 🟢
- **ИНН < 10 знаков:** предупреждение пользователю при `ИННПриИзменении`. 🟢
- **Коллизия имени скана:** авто-инкремент суффикса имени файла. 🟢
- **Объединение: на исходного остались ссылки:** клиент не помечается на удаление, выводится сообщение. 🟢
- **Дубль-физлица по ИНН:** не выявляется отчётом `КлиентыДвойныеИНН` (фильтр только ЮрЛицо). 🟢

## Зависимости
- **Бронирование** — `ЗаявкаНаБронирование.Клиент/Клиент2/Оплачивает/Бронирует/Турагентство`; РС `ИсторияКлиента` пишется при проведении заявки. 🟢
- **Финансы и касса** — `ГрупповыеСчета.Контрагент`, `ВыпискаБанка.ОтКого` (замена при объединении). 🟢
- **Ценообразование** — `КатегорииКлиентов.Скидка`, `СкидкиКлиента`. 🟡
- **Интеграции и обмен** — `ГУИД_ИсточникОбмена`, `НеУчаствуетВОбмене`, перенос клиентов из Реноме/Чехов. 🟡
- **PassportBox** (внешний HTTP-сервис распознавания) — см. `contracts.md`. 🟢
- **ФМС** (выходной CSV-контракт) — см. `contracts.md`. 🟢
- Внешние классификаторы ФМС `*ФМС_NEW` (`ID`, `CODE_ALPHA3`, `CODE_0`, `END_DATE`) — структура не разбиралась. 🔴

## Решения дизайна

| Решение | Доказательство | Уверенность |
|---------|----------------|-------------|
| Мультиисточниковое распознавание с приоритетом page3 < OCR < MRZ | `PassportBoxВызовСервера/Module.bsl:464-479` | 🟢 |
| Признак ФМС `ИностранныйГражданин` как главный переключатель формата выгрузки | `ВыгрузкаДляФМС/.../Module.bsl:138-429` | 🟢 |
| Антидубль на уровне `ПередЗаписью` формы (а не на уровне объекта/БД) | `ФормаЭлемента/Module.bsl:263-308` | 🟢 |
| `ГУИД_ИсточникОбмена` как стабильный ключ интеграции | `ObjectModule.bsl:3-7`; ADR-0008/0009 | 🟢 |
| Магическое число `103008` для типа документа «паспорт РФ» | `ВыгрузкаДляФМС/.../Module.bsl:181`; `ФормаЭлемента:2019` | 🔴 |
| Незавершённая миграция модели ФМС `_NEW`/`_OLD` | `Catalog.Клиенты.mdo`; ADR-0007 | 🔴 |

## Внутреннее состояние
- Карточка клиента — основной носитель состояния: персональные/паспортные/миграционные данные, флаги-тумблеры (`ИностранныйГражданин`, `ЧС`, `НеУчаствуетВОбмене`, `НеПоказыватьИсторию`, `АдресРегистрацииОтсутствует`), цвет (`ЦветR/G/B`). 🟢
- ТЧ карточки: `КонтактнаяИнформация`, `ПрочаяИнформация`, `СканыДокументов`, `ПроцентыКомиссии`, `ПроцентыВ2В`. 🟢
- РС `ИсторияКлиента` — денормализованный срез броней (пишет модуль Бронирование). 🟢
- Константы PassportBox/папок — конфигурация интеграций. 🟢

## Наблюдаемость
- Явного логирования (ЗаписьЖурналаРегистрации) в разобранных функциях домена не обнаружено; ошибки PassportBox возвращаются как структура-ошибка и показываются пользователю. 🟡
- Дедуп-отчёт `КлиентыДвойныеИНН` выводит табличный документ как диагностику дублей. 🟢

## Риски и пробелы
- 🔴 Магическое число `103008` (паспорт РФ) зашито в коде в двух местах — рассинхрон при изменении классификатора.
- 🔴 Незавершённая миграция реквизитов `_NEW`/`_OLD` — неясно, какая модель ФМС актуальна.
- 🔴 `ОбъединитьКлиентовНаСервере`: `Записать(Проведение)` в цикле внутри транзакции без `Попытка/Исключение` — при сбое нет `ОтменитьТранзакцию` (нарушение `BeginTransactionBeforeTryCatch`).
- 🔴 Структура внешних классификаторов ФМС (`*ФМС_NEW`) вне домена, не разбиралась.
- 🔴 `Document.АнкетаНовая` (5 ТЧ ответов) — логика заполнения не разобрана.
- 🟡 Дубли физлиц по ИНН/ФИО/паспорту не выявляются автоматически (только юрлица).
- 🟡 Версионные дубли кода (`ВыгрузкаДляФМС_Исходная`, `ПечатьУведомления_Старое`, `_1`-копии) — мёртвый код.
