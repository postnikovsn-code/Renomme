# Бронирование — Задачи реконструкции

> Атомарные задачи для повторной реализации модуля «Бронирование» без доступа к исходному коду. Каждая задача цитирует легаси-источник, имеет критерий готовности и метку доверия 🟢/🟡/🔴. Дополняет `requirements.md` и `design.md`.

## Предпосылки

- [ ] Доступны зависимости из `design.md` (модули «Размещение», «Ценообразование», «Финансы»).
- [ ] Метаданные `НомернойФонд`, `КатегорииНомеров`, `Клиенты`, `ТарифныеПланы` существуют.
- [ ] Перечисления `СтатусБрони`, `ВремяЗаезда`, `ВремяВыезда` определены с указанными значениями (`data-dictionary.md`).
- [ ] Решён вопрос ценообразования (`РасчетПроживания`) — см. «Пробелы».

## Задачи

### Метаданные и структуры

- [ ] **T-01.** Создать документ `ЗаявкаНаБронирование`: реквизиты шапки (≈80) и 8 ТЧ (`Проживание`, `ДопУслуги`, `ДопПожелания`, `ЗабытыеВещи`, `Счета`, `СчетаДетальноДолги`, `СчетаДетальноСтроки`, `РаспределениеОплатДолги`); регистраторы по `.mdo:78-82`.
  - Источник: `Documents/ЗаявкаНаБронирование/ЗаявкаНаБронирование.mdo`; `data-dictionary.md` § «ЗаявкаНаБронирование»
  - Готово: документ создаётся, реквизиты и ТЧ совпадают со словарём данных
  - Доверие: 🟢

- [ ] **T-02.** Создать `РегистрСведений.ЗанятостьНомеров`: измерения Номер, Клиент, ПериодРезерва(Date), Номер_пп(Number); ресурсы Зарезервирован(Boolean), БонШанс(Boolean); `writeMode=RecorderSubordinate`, периодический.
  - Источник: `InformationRegisters/ЗанятостьНомеров/ЗанятостьНомеров.mdo`
  - Готово: регистр пишется подчинённо регистратору, хранит почасовую сетку
  - Доверие: 🟢

- [ ] **T-03.** Создать документы `ЗаявкаСайт`, `ЛистОжидания`, `ПодтверждениеБронирования` с реквизитами по словарю; справочники `КаналыБронирования`, `ТипБронирования` с предопределёнными элементами.
  - Источник: соответствующие `.mdo`; `data-dictionary.md`
  - Готово: объекты и предопределённые элементы соответствуют словарю
  - Доверие: 🟢

- [ ] **T-04.** Создать регистры `ИсторияКлиента`, `ИсторияКлиентаДопПожелания` (подчинены регистратору), `AccumulationRegister.Взаиморасчеты`.
  - Источник: `data-dictionary.md`; `legacy-mapping.md`
  - Готово: регистры существуют с указанными измерениями/ресурсами
  - Доверие: 🟢

### Логика занятости

- [ ] **T-05.** Реализовать `ДокументыСервер.ЗанятостьНомераПериодРезерва(РезервС, РезервПо, ВремяЗаезда, ВремяВыезда)`: маппинг заезд `Вр0/6/14/18→0/6/14/18`, выезд `Вр0/6/12/18→24/6/12/18`; `Начало = НачалоЧаса(НачалоДня(РезервС)+Заезд·3600)`, `Конец = НачалоЧаса(НачалоДня(РезервПо)+Выезд·3600)`.
  - Источник: `CommonModules/ДокументыСервер/Module.bsl:231-262`
  - Готово: для заданных дат/времён возвращается корректный почасовой интервал
  - Доверие: 🟢

- [ ] **T-06.** Реализовать `ДокументыСервер.ЗанятостьНомераПроверить(...)`: запрос к `ЗанятостьНомеров` на `[Начало; Конец−1]`, `Регистратор <> Текущий`; при `БонШанс` добавить `И БонШанс = ЛОЖЬ`; вернуть `Структура{Результат, НачалоПериодаРезерва, КонецПериодаРезерва, Регистратор}`, `Результат=Истина` ⇒ занят.
  - Источник: `CommonModules/ДокументыСервер/Module.bsl:264-311`; `flowcharts/Бронирование-ЗанятостьНомераПроверить.md`
  - Готово: конфликт с чужим регистратором даёт `Результат=Истина`; БонШанс не конфликтует с БонШанс
  - Доверие: 🟢

### Проведение брони

- [ ] **T-07.** Реализовать `ЗаявкаНаБронирование.ОбработкаПроведения`: валидация → ранний выход (лист ожидания/отмена/отказ) → проверка занятости → история клиента → почасовой цикл движений `ЗанятостьНомеров` (шаг 3600) → движения `Взаиморасчеты` по ТЧ `Счета`.
  - Источник: `Documents/ЗаявкаНаБронирование/ObjectModule.bsl:4-140`; `flowcharts/Бронирование-ОбработкаПроведения.md`
  - Готово: проведение проходит по основному потоку; критерии приёмки RF-04/RF-05 выполняются
  - Доверие: 🟢

- [ ] **T-08.** Реализовать спец-обработку суточной брони (`РезервС=РезервПо`): расширение окна до +24ч либо принудительное 13:00–18:00; `ТемпПо = ТемпПо − 1`.
  - Источник: `ObjectModule.bsl:23-40`
  - Готово: однодневная бронь резервирует корректный интервал, последний час исключён
  - Доверие: 🟡 (магические часы — подтвердить политику)

- [ ] **T-09.** Реализовать инкремент `Номер_пп` при наложении резервов в одном часе (поиск существующей записи часа/клиента/брони → `+1`).
  - Источник: `ObjectModule.bsl:70-73`
  - Готово: наложенные резервы сосуществуют через разные `Номер_пп`
  - Доверие: 🟡

- [ ] **T-10.** Реализовать `ПередЗаписью`: пересборка счетов через `ЗаявкаСервер.ОбновитьСчетаСтроки`, отложенное удаление пустых счетов, вычисление `Закрыт`, проставление `ДатаСоздания`/`ДатаИзменения`.
  - Источник: `ObjectModule.bsl:158-188`
  - Готово: пустые счета удаляются без ошибки `DeletingCollectionItem`; аудит-метки заполняются
  - Доверие: 🟢

- [ ] **T-11.** Реализовать `ПередУдалением`: проверка `ПараметрыСеанса.ТекущийПользователь.Админ`; не-админ → «Удаление документов запрещено», `Отказ=Истина`; снятие ссылок в `КассовыйДокумент`/`ВыпискаБанка`; `ЗаявкаСервер.УдалитьИсториюКлиента`.
  - Источник: `ObjectModule.bsl:203-260`; `permissions.md §3.2`
  - Готово: не-админ не может удалить бронь; админ удаляет с очисткой связей
  - Доверие: 🟢

- [ ] **T-12.** Реализовать `ПриКопировании`: сброс оперативных реквизитов (времена, номер, оплата), `Статус=Бронь`, очистка движений и ТЧ.
  - Источник: `ObjectModule.bsl:265-310`
  - Готово: копия брони не содержит «грязных» оперативных данных
  - Доверие: 🟢

## Рекомендуемый порядок

1. Метаданные (T-01…T-04) — фундамент.
2. Логика занятости (T-05, T-06) — ядро, блокирует проведение.
3. Проведение (T-07…T-12) — основной поток.
4. Счета/долги (T-13…T-15) и история (T-16).
5. Конвертация сайта (T-18, T-19) и аналитика (T-17).
6. Тесты (TT-*) — параллельно после соответствующей задачи.
