## 1. Обзор

🟢 **Платформа:** 1С:Предприятие 8 (конфигурация 1C:EDT, формат исходников `src/`).
🟢 **Имя конфигурации:** `ОТЕЛЬ` (синоним «ОТЕЛЬ»).
🟢 **Версия конфигурации:** `3.2.7.38`.
🟢 **Язык встроенного кода:** BSL (русский вариант, `scriptVariant=Russian`).
🟢 **Режим запуска по умолчанию:** `ManagedApplication` (управляемое приложение).
🟢 **Режим совместимости:** `8.3.24` (расширения — `8.3.27`).
🟢 **Управление блокировками данных:** `Managed` (управляемые).

🟡 **Природа проекта:** прикладная система управления гостиницей («ОТЕЛЬ»), построенная поверх типовой **«Библиотеки подключаемого оборудования» (БПО), редакция 3.2** (`briefInformation`: *«Библиотека подключаемого оборудования, редакция 3.2»*). То есть прикладной гостиничный домен сосуществует с большой инфраструктурной подсистемой работы с фискальным/торговым оборудованием.

## 2. Структура проекта (1C:EDT)

```
hotel/
├── .project                 # Eclipse / 1C:EDT project descriptor
├── .settings/               # настройки EDT
├── DT-INF/PROJECT.PMF       # метаданные проекта EDT
└── src/                     # исходники конфигурации (по видам метаданных)
    ├── Configuration/       # корень: Configuration.mdo + модули приложения
    ├── Catalogs/            # справочники
    ├── Documents/           # документы
    ├── InformationRegisters/      # регистры сведений
    ├── AccumulationRegisters/     # регистры накопления
    ├── ChartsOfCharacteristicTypes/
    ├── Enums/               # перечисления
    ├── Constants/           # константы
    ├── Reports/             # отчёты
    ├── DataProcessors/      # обработки
    ├── CommonModules/       # общие модули (бизнес-логика)
    ├── CommonForms/         # общие формы
    ├── CommonCommands/      # общие команды
    ├── CommonTemplates/     # общие макеты
    ├── CommonPictures/      # общие картинки
    ├── ExchangePlans/       # планы обмена
    ├── Roles/               # роли (RBAC)
    ├── ScheduledJobs/       # регламентные задания
    ├── Subsystems/          # подсистемы (доменная разметка)
    ├── DefinedTypes/        # определяемые типы
    ├── SessionParameters/   # параметры сеанса
    └── XDTOPackages/        # XDTO-пакеты (схемы обмена)
```

> ⚠️ В исходниках присутствуют объекты-дубликаты/устаревшие версии с суффиксами `_OLD`, `_Старая`, `_Старый`, `_Исходный`, `_Версия`, `_НеИспользуется` (например `ГашениеДолгов_Старая`, `ЗакрытиеДней_OLD`, `Администраторы_Версия`, `АдминистраторыТабель_НеИспользуется`). 🟡 Это технический долг / следы рефакторинга — кандидаты на отдельную пометку при раскопках.

## 7. Точки входа

🟢 Модули приложения (`Configuration/`):
- `ManagedApplicationModule.bsl` — модуль управляемого приложения (основной запуск).
- `OrdinaryApplicationModule.bsl` — модуль обычного приложения.
- `SessionModule.bsl` — модуль сеанса.

🟢 Регламентные задания (фоновые точки входа): `ОчисткаИстории*` (5 заданий по обслуживанию истории операций оборудования/платежей/фискализации) и `РассылкаЭлектронныхЧеков`.

## 8. Конфигурация и инфраструктура

🟢 `Configuration/Configuration.mdo` — корневой объект конфигурации.
🟢 `Configuration/Configuration.distr`, `ClientApplicationInterface.cai`, `ParentConfigurations/` — поставка и родительские конфигурации.
🟢 `DT-INF/PROJECT.PMF`, `.project`, `.settings/` — служебные файлы 1C:EDT.

🔴 **ПРОБЕЛ:** CI/CD (`.github/workflows`, Jenkinsfile, gitlab-ci), Docker, отдельные `.env`-файлы — **не обнаружены**. Для 1С это ожидаемо (развёртывание идёт через платформу/конфигуратор), но факт стоит подтвердить у владельца.

## 9. Тесты

🔴 **ПРОБЕЛ:** автоматизированные тесты (xUnitFor1C / Vanessa / `*.feature`) в исходниках **не обнаружены**. Присутствуют объекты с именами `*_ТЕСТ`/`*_Тест` (`PayKeeper_ТЕСТ`, `GREEN_Тест`, `Обмен_ТЕСТ`, `ОбменТест`), но это ручные/отладочные обработки и план обмена, а не тестовый фреймворк.

## 10. База данных

🟢 СУБД управляется платформой 1С (физическая схема генерируется из метаданных, не хранится как DDL). «Таблицы» = объекты метаданных (Catalogs, Documents, Registers). Детальный разбор структуры данных и связей выполнит **Data Master** и **Архитектор (ERD)**.
