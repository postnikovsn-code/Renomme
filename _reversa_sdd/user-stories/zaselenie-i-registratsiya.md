# User Stories — Заселение и регистрация гостя

> Сквозной поток: регистрация гостя, карточка, анкета, распознавание паспорта, миграционный учёт ФМС.
> Роли: Администратор стойки, Менеджер/Руководитель, Гость.
> Связанные unit: [`Гости/`](../Гости/), [`Бронирование/`](../Бронирование/), [`Интеграции/`](../Интеграции/).
> Доверие: 🟢 подтверждено · 🟡 выведено · 🔴 пробел.

## US-RG-01 — Ведение карточки гостя

**Как** Администратор стойки, **я хочу** завести карточку гостя (физ/юр лицо) с контактами и документами, **чтобы** единожды хранить данные гостя для всех его броней.

Источник: `Catalog.Клиенты` (~130 реквизитов + 5 ТЧ), `Catalogs/Клиенты/Forms/ФормаЭлемента/Module.bsl`. 🟢

### Критерии приёмки
```gherkin
Дано новая карточка физлица
Когда администратор записывает клиента
Тогда Наименование собирается из Фамилия+Имя+Отчество
  И при первой записи присваивается ГУИД_ИсточникОбмена (ключ обмена)

Дано в базе уже есть клиент с тем же наименованием или ИНН+КПП
Когда администратор пытается записать дубль
Тогда запись отменяется и открывается карточка существующего клиента (антидубль)
```
🟢 `ФормаЭлемента/Module.bsl:263-308`; `ObjectModule.bsl:3-7`.

## US-RG-02 — Распознавание паспорта через PassportBox

**Как** Администратор стойки, **я хочу** отсканировать паспорт и автозаполнить реквизиты, **чтобы** не вводить данные вручную и не делать опечаток.

Источник: `CommonModules/PassportBoxВызовСервера` (HTTP-сканер). 🟢

### Критерии приёмки
```gherkin
Дано подключён сканер PassportBox (IP/Порт/Таймаут в константах)
Когда администратор запрашивает разворот 2-3 страниц / регистрацию
Тогда реквизиты заполняются из 3 источников по приоритету page3 < OCR < MRZ
  И непустое более приоритетное значение перезаписывает менее приоритетное
  И ФИО приводится к ТРег
  И проверяются 9 обязательных полей паспорта / 6 полей регистрации

Дано сканер недоступен
Когда выполняется запрос
Тогда возвращается структура с признаком Ошибка и описанием
```
🟢 `PassportBoxВызовСервера/Module.bsl:50-92,418-496`.

## US-RG-03 — Анкета гостя

**Как** Гость, **я хочу** заполнить анкету (что понравилось/не понравилось, цели визита), **чтобы** отель улучшал сервис.

Источник: `Document.Анкета`, `Document.АнкетаНовая`, `Catalog.АнкетаВопросы`. 🟢 (АнкетаНовая вглубь 🔴)

### Критерии приёмки

```gherkin
Дано бронь со статусом Проживает
Когда гость заполняет анкету
Тогда создаётся документ Анкета/АнкетаНовая, связанный с Бронью и Клиентом
```

## US-RG-04 — Миграционный учёт (выгрузка для ФМС)

**Как** Администратор стойки, **я хочу** выгрузить данные проживающих в формате ФМС, **чтобы** выполнить требование миграционного учёта.

Источник: `DataProcessors/ВыгрузкаДляФМС/Forms/Форма/Module.bsl`. 🟢

### Критерии приёмки
```gherkin
Дано клиент и бронь с заполненными паспортными данными
Когда формируется выгрузка ФМС
Тогда генерируется CSV версии #v.2.0.0, разделитель ';', ~94 поля, даты ДФ=dd.MM.yyyy

Дано клиент — гражданин РФ (ИностранныйГражданин=Ложь)
Когда собирается строка ФМС
Тогда гражданство=RUS, тип документа=103008, поля визы/пребывания/мигркарты пустые

Дано клиент — иностранный гражданин
Когда собирается строка ФМС
Тогда заполняются поля визы/пребывания/миграционной карты
```
🟢 `ВыгрузкаДляФМС:138-429`. 🔴 Магическое число ПаспортРФ_ID=103008.

## US-RG-05 — Дедупликация и объединение клиентов

**Как** Менеджер/Руководитель, **я хочу** находить и объединять дубли клиентов, **чтобы** держать чистую клиентскую базу.

Источник: `DataProcessors/КлиентыДвойныеИНН`, `DataProcessors/КлиентыОбъединиение`. 🟢

### Критерии приёмки
```gherkin
Дано несколько юрлиц с одинаковым ИНН
Когда формируется список двойных ИНН (Количество>1, ТипКлиента=ЮрЛицо)
Тогда они показываются группами для объединения

Дано выбран основной и подчинённый клиент
Когда выполняется объединение
Тогда клиент заменяется во всех заявках/групповых счетах/выписках/регистрах истории
  И исходный помечается на удаление только при отсутствии ссылок
```
🟢 `КлиентыОбъединиение:224-417`. 🔴 Дедуп физлиц не реализован; нарушение транзакций в ОбъединитьКлиентовНаСервере.

## US-RG-06 — Загрузка сканов и дни рождения

**Как** Администратор стойки, **я хочу** загрузить сканы документов и видеть дни рождения проживающих, **чтобы** комплектовать карточки и поздравлять гостей.

Источник: `DataProcessors/ЗагрузкаСканов`, `DataProcessors/ДниРождения`. 🟢

### Критерии приёмки
```gherkin
Дано jpg-файлы в Папка_СКАНЫ
Когда выполняется загрузка сканов
Тогда файлы переименовываются в '<ГУИД клиента>_<имя>' с авто-инкрементом при коллизии
  И копируются в архив и приёмник, оригинал удаляется, путь пишется в ТЧ СканыДокументов

Дано брони со статусом Проживает, охватывающие текущую дату
Когда формируется список дней рождения
Тогда именинник определяется, если день/месяц рождения попадает в [РезервС; РезервПо]
  И учитываются Клиент и Клиент2
```
🟢 `ЗагрузкаСканов:141-188`, `ДниРождения:11-102`.
